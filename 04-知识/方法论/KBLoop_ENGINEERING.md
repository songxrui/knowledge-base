# KBLoop — 高质量媒体创作优化循环工程

> 版本: v1.0 | 创建: 2026-06-22 | 维护: 每次循环迭代后更新
> 工程定位: 知识库内容生产的核心执行引擎——不是"设计文档"，是"操作手册和纪律约束"
>
> **治理状态（2026-07-16）**：保留九阶段流程作为历史执行脚手架，不再维护事实数字和实验参数。主张身份统一看 `05-内容生产/内容体系/00-规则与索引/内容证据契约.md`；库存看 `05-内容生产/内容体系/03-处理状态/内容资产当前清单.md`；频率、复盘窗口、价格、用户、留存和停止条件看 `05-内容生产/内容体系/03-处理状态/内容生产事实与实验参数.md`；个人故事只允许引用 `05-内容生产/内容体系/03-处理状态/个人事实确认表.md` 中 `confirmed` 且允许公开的条目。
>
> 本文旧版中的盖章式完成声明、发布结果、个人素材、固定阈值和产品数字均为历史自述或候选配置，不是当前事实；与上述事实源冲突时自动失效。

## 一、工程哲学

### 1.1 核心矛盾诊断

知识库曾出现“手段-目的倒置”：维护大量内部单元、装配稿、主题地图和技能，但当前已发布归档中没有已确认的公开内容，数据表也没有有效后台数据行。库存与发布事实不在本文手写，以当前清单和发布台账为准。

根本原因: 基础设施建设的边际收益已经趋零。继续优化系统不会让第一篇内容产出。需要从"建设期"切换到"生产期"，同时保留质量门禁。

### 1.2 五条铁律

| # | 铁律 | 来源 |
|---|------|------|
| 1 | **先完成可核验版本再优化** — 发布是验证环节，不以“先发”为理由跳过事实和风险门禁 | 作者方法 |
| 2 | **内容即资产** — 每篇产出是可复用的原子资产，不能是一次性消耗品 | C3-1 |
| 3 | **来源标注即诚信** — 每条关键事实必须有 `claim_id`、精确定位和边界；证据不足则降级或阻断 | 内容证据契约 |
| 4 | **不过人化不发布** — faith-humanizer + AI-taste-check 双检零容忍 | faith-pipeline Phase 4 |
| 5 | **证据驱动反哺** — 发布后数据必须记录，方法论必须更新 | AGENTS.md 工作流 Step 5-7 |

### 1.3 禁产红线（什么不写）

- ❌ 用固定字数代替任务完成度；长度按平台、问题和证据需要确定
- ❌ 没有来源标注的论断
- ❌ 为满足“人格化”要求补写未确认个人经历或用户案例
- ❌ 选题不在DBS三选题范围内的内容
- ❌ 未经过faith-humanizer的内容

## 二、KBLoop 九阶段循环

> 各阶段分钟数是旧版时间盒 `experiment-parameter`，当前不生效；执行时记录实际耗时，再决定是否采用。

```
┌─────────────────────────────────────────────────────────┐
│                    KBLoop v1.0                           │
│                                                         │
│  [0] SELECT ──→ [1] RESEARCH ──→ [2] STRUCTURE          │
│       ↑                              ↓                  │
│       │                       [3] WRITE                 │
│       │                              ↓                  │
│  [8] LEARN ←── [7] PUBLISH ←── [4] HUMANIZE             │
│       ↑              ↓              ↓                  │
│       │         [6] VERIFY ←── [5] COMMERCIALIZE        │
│       │              ↓                                  │
│       └────────── 数据反哺                               │
└─────────────────────────────────────────────────────────┘
```

### Phase 0: SELECT（选题）— 5分钟

输入: DBS三选题（执行系统/内容与一人企业/认知框架重构）
操作:
1. 从 `05-内容生产/选题管理/历史选题/2026-06/压缩主题框架/` 读取三个压缩选题
2. 从 `05-内容生产/内容体系/00-缓冲区/` 和主题地图检索可用装配材料；当前无正式 `06-选题装配/` 目录时不得假设库存存在
3. 确定具体切入角度（压缩选题是宏观框架，每篇取一个具体切口）
4. 确认选题在DBS三选题范围内

产出: `05-内容生产/选题管理/` 中更新选题记录，标注 `[KBLoop-进行中]`

质量门禁: 选题必须通过"三个月后还值得看吗"测试

### Phase 1: RESEARCH（研究）— 15-20分钟

输入: 选定选题
操作:
1. **库内检索** (`05-内容生产/内容体系/02-内容单元库/`): 按主题关键词检索 QST/CON/OPI/CAS/SOL
2. **深度卡检索** (`04-知识/卡片/`): 读取匹配的C卡（含微信读书证据）和T卡
3. 外部检索: weread-skills 提取划线/笔记；exa-search 搜索学术论文/官方博客
4. 个人素材提取：只读取 `个人事实确认表.md` 中 `confirmed` 且允许公开的条目；当前确认数为 0 时跳过个人故事，不由 AI 补写

产出: `05-内容生产/进行中/[选题名]/RESEARCH_LOG.md`

质量门禁:
- 至少一个核心 `claim_id`，并有精确来源、边界和反证
- 引用数量由主张需要决定，不用固定数量制造“证据充足”外观
- 个人经历不是必填项；使用时必须有已确认记录
- 每条关键素材能回到原始来源

### Phase 2: STRUCTURE（结构化）— 10分钟

输入: RESEARCH_LOG
操作:
1. 用 QST/CON/OPI/CAS/SOL 五单元框架搭建文章骨架
2. 确定叙事弧（问题-解决 / 层进论证 / 叙事弧 / 比较分析）
3. 预设反共识立论点（≥2个）
4. 标记商业化钩子插入位置

产出: `05-内容生产/进行中/[选题名]/STRUCTURE.md`

结构约束:
- Hook（开头30秒必须抓住注意力）
- 反共识立论（让读者觉得"等等，这不对吧？"然后被说服）
- 证据链（每个论点≥1条来源标注）
- 个人故事（真实经历穿插，不是装饰，是论证的一部分）
- 可执行动作（读者看完能立刻做的1-3件事）
- 商业化桥接（自然过渡到健康之书/答案之书）
- 金句收尾（一句推文式短句）

### Phase 3: WRITE（写作）— 30-45分钟

输入: STRUCTURE + RESEARCH_LOG
操作:
1. 从结构骨架展开为完整长文；长度是编辑参数，不设通用最低字数
2. 遵循STYLE_GUIDE全部规则
3. 只有已确认个人事实才使用事实型“我”；观点可以直接陈述，不用伪个人化制造人格
4. 直接到刺痛，不铺垫不委婉
5. 短句为主，长短交替

产出: `05-内容生产/进行中/[选题名]/DRAFT_v1.md`

写作红线:
- ❌ 禁用词13个（赋能/抓手/闭环/底层逻辑/综上所述/众所周知/值得注意的是/在这个时代/本质上/不难发现/随着…的发展/首先其次最后/空壳排比）
- ❌ 不可查案例（"某朋友""某学员""某公司"）
- ❌ 三段式结构（首先→其次→最后）
- ❌ 升华结尾

### Phase 4: HUMANIZE（去AI味）— 15分钟

输入: DRAFT_v1
操作:
1. faith-humanizer: 41种AI写作模式扫描（A-I九大类），三轮替换（🔴→🟡→🟢）
2. AI-taste-check: 6大病征诊断（对称排比成瘾/空泛升华结尾/强行中立/信息密度低/具体性缺失/伪个人化）
3. STYLE_GUIDE自检: 13禁用词扫描 + 5种AI味模式 + 加粗密度 + 证据标注

产出: `DRAFT_v2.md`（人化后版本）

不过不发布：AI 味检查采用逐项问题清单，不把“少于 3 处”当客观事实或自动发布条件

### Phase 5: COMMERCIALIZE（商业化）— 10分钟

输入: DRAFT_v2
操作:
1. 在文章中自然嵌入健康之书/答案之书的引用
2. 构建"这篇文章只是冰山一角，答案之书里有完整系统"的钩子
3. 确保钩子是价值展示而非硬推销——读者读完钩子后觉得"这确实是我需要的"，而非"又来卖东西"

商业化钩子类型:
- 知识深潜钩: "这篇文章讲了一个点，答案之书第X章有完整的系统框架"
- 自测引导钩: "想测你的XX状态？答案之书里有完整的自测工具"
- 案例扩展钩: "文中提到的案例只是缩影，答案之书收录了XX个类似案例"
- 行动升级钩：说明产品内的具体下一步、适用条件和停止规则，不承诺固定天数结果

产出: `DRAFT_v3.md`（含商业化钩子）

### Phase 6: VERIFY（终审）— 10分钟

输入: DRAFT_v3
操作:
1. faith-gate-check: 3关布尔判定（语言质量/任务完成度/发布就绪）
2. faith-truth-check: 4步验证（拆解论断→验证来源→输出验证报告→修复建议）
3. STYLE_GUIDE发布前自检清单：逐项记录证据和未解决项，不使用盖章式质量判断

产出: `FINAL_[选题名].md` + `VERIFICATION_REPORT.md`

不通过处理: 回到对应阶段修正（人化不通过→Phase 4；来源不通过→Phase 1；结构不通过→Phase 2）

### Phase 7: PUBLISH（发布）— 5分钟

输入: FINAL版本
操作:
1. 发布到公众号
2. 适配发布到小红书/Threads（短内容版本）
3. 在 `05-内容生产/运营与发布/数据/数据统计表.csv` 记录发布信息
4. 将终稿移动到 `05-内容生产/运营与发布/已发布/`

产出: 已发布的文章 + CSV数据行

### Phase 8: LEARN（反哺）— 复盘窗口以参数台账为准

输入: 发布数据
操作:
1. 按 `EXP-REVIEW-001` 的当前状态记录初始和延迟数据；参数未启用时不伪造时间窗
2. 分开记录传播、理解、使用、反例、购买和交付成本
3. 方法论提炼: 从数据中提取可复用的洞察
4. 更新 `04-知识/方法论/KBLoop_ENGINEERING.md`（本次循环的经验）
5. 发布数据只能更新“该次发布的观察结果”，不能把内容主张自动升级为“已验证有效”

产出: 更新的方法论 + 更新的内容单元

## 三、质量门禁矩阵

| 阶段 | 门禁 | 通过标准 | 不通过处理 |
|------|------|---------|-----------|
| Phase 0 | 选题测试 | "三个月后还值得看"=YES | 换选题 |
| Phase 1 | 证据完整性 | 核心 claim 有定位、边界；个人经历已确认 | 补证据或降级 |
| Phase 2 | 结构完整性 | QST/CON/OPI/CAS/SOL五框架 | 重建结构 |
| Phase 3 | 任务完成度 | 文章完成一个受众任务，证据足够 | 补论证或收缩范围 |
| Phase 4 | AI味指纹 | 无伪经历、伪数据、空泛脚手架 | 逐项修复 |
| Phase 4 | 表达检查 | 黑话、脚手架和夸张逐项审查 | 按语境修复 |
| Phase 5 | 商业化自然度 | 钩子感觉像"价值延伸"而非"广告" | 重写钩子 |
| Phase 6 | Gate Check | 每项有证据或明确阻断 | 回对应阶段 |
| Phase 6 | Truth Check | 关键 claim 有定位、边界和状态 | 修正、降级或阻断 |
| Phase 7 | 发布执行 | 实际发布+CSV记录 | 不可跳过 |

## 四、商业化引擎设计

### 4.1 健康之书营销钩子映射

健康之书内容分布在答案之书CH2-3 + C1卡+T1-T4/T9-T10卡中。以下为可嵌入的钩子模板：

| 文章选题 | 健康之书钩子 | 切入方式 |
|---------|------------|---------|
| 执行系统/环境设计 | "为什么你的环境在消耗你的多巴胺基线——健康之书CH2的神经化学地图" | 科学证据钩 |
| 成瘾与戒断 | "戒游戏不是意志力问题——健康之书里关于多巴胺戒断的14天SOP" | 行动方案钩 |
| 昼夜节律与效率 | "你以为是懒，其实是光照不足——健康之书CH3的生物钟重置法" | 反常识钩 |
| 饮食与认知 | "你吃的每一口都在修改你的大脑——健康之书的代谢-认知映射表" | 因果链钩 |

### 4.2 答案之书营销钩子映射

| 文章选题 | 答案之书钩子 | 切入方式 |
|---------|------------|---------|
| 认知重构 | “删OS旧代码——这是答案之书第1章的框架钩子（来源摘录）” | 框架升级钩 |
| 一人企业 | "内容×产品×IP——答案之书CH4财富商业的完整模型" | 系统扩展钩 |
| 反脆弱 | "答案之书CH7的第一性模型——把你变成打不死的系统" | 深度概念钩 |
| 关系与边界 | "答案之书CH5——不是'如何社交'，是'为什么你不需要那么多人'" | 反共识钩 |

### 4.3 钩子设计原则

1. 价值先行: 钩子首先是给读者更多价值，其次才是引导产品
2. 自然过渡: 从文章内容到产品引用必须像"往下深挖"而非"突然转弯"
3. 具体定位：说明产品内的精确位置和可支持范围，不承诺未经验证的天数或结果
4. 一次一个: 每篇文章只挂一个钩子，不撒网

### 5.2 产出文章索引

| # | 标题 | 对应DBS选题 | 商业化钩子 | 字数 |
|---|------|-----------|-----------|------|
| 1 | 你以为你在做选择，其实你的多巴胺在替你选 | TOPIC1 执行系统 | 健康之书(多巴胺重置) | ~4000字 |

### 5.2 循环规则

1. 单线不并行: 一次只创作一篇。多线程是"完成感"的幻觉
2. 强制门禁: 每阶段门禁不通过不能进入下一阶段
3. 时间盒: 每阶段有建议时长，但以质量门禁为准（不因超时跳过门禁）
4. 中断恢复: 从上次完成的阶段继续，不从头开始
5. 停止条件：统一看 `EXP-STOP-001`、`EXP-STOP-002`；用户暂停时立即停止

Cycle 1-4 经验提炼:
- 历史记录认为压缩选题有助于选切口，但没有耗时对照，保留为待验证观察
- 写作时直接应用STYLE_GUIDE规则（而非事后修复）避免了大量返工
- 商业化钩子用"预告而非广告"的语气：价值先行、自然过渡、具体承诺
- 个人故事只有在本人确认且允许公开时才能使用；AI 不得把旧稿中的细节当事实
- 三篇文章形成了互锁的"认知三角"：身体(多巴胺/环境)→思维(反依赖/OS审计)→行动(内容资产/一人企业)
- 每篇文章2700-4000字，杜绝了"几百字短小文"的问题
- 引用数量不等于证据质量；关键主张需逐条回到原始来源
