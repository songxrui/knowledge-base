# 第一部分：十二个技能速查

## 1. dbs-orchestrator — 总路由

**一句话**：不知道用哪个技能时，把这个丢给它，它帮你判断。

**什么时候用**：你有一个模糊的问题或需求，但不确定该对应 12 个技能中的哪一个。输入"帮我看下我的问题该用谁"即可。

**怎么用**：
```
/dbs-orchestrator 我写了一条关于亏 5300 的脚本，总觉得哪里不对
```
→ AI 会自动判断这是"内容类"问题，路由到 dbs-content 或 dbs-hook。

**核心价值**：你不需要记住 12 个技能名。记不住就用这个入口。

---

## 2. dbs-content — 内容创作诊断

**一句话**：选题通过后，诊断这个内容该怎么做成好内容。它帮你判断方向对不对、形式对不对、表达对不对——但不帮你写。

**什么时候用**：
- 你有一个明确的选题，但不知道怎么下手
- 你已经写了初稿，但不确定好不好
- 你想知道一个选题最适合用什么形式（图文 vs 短视频 vs 长视频 vs 直播）

**怎么用**：
```
/dbs-content 我想写一篇"自媒体新人最容易犯的 5 个错误"，怎么切入？
```
→ AI 会先问你的选题和形式，然后做五维度诊断（价值密度、差异化、结构完整性、受众匹配、语言有效性）。

**五个核心原则**：
1. 文字洁癖是底线——AI 味必须洗掉
2. 自媒体的本质是精神控制——封面和标题是认知劫持
3. 内容好坏 = 投入精力 × 对内容的正确理解
4. 先有产品后有内容——内容为产品服务
5. 知识博主的核心工作只有两个：把事情搞清楚 + 说清楚

**注意**：这个技能不帮你写内容，它只诊断。写是你自己的事。

## 3. dbs-hook — 短视频开头优化

**一句话**：把脚本给它，它诊断开头有没有问题，并生成 10-15 个优化版开头供你选择。

**什么时候用**：
- 你写了一条短视频脚本，但觉得开头不够吸引人
- 你的视频 5 秒完播率低，怀疑开头有问题
- 你只有一个选题，不知道开头该怎么切入

**怎么用**：
```
/dbs-hook 这是我的脚本：
[粘贴完整脚本文案]
```
→ AI 会先检查内容质量（核心信念："写不出好开头，90% 是内容本身有问题"），然后做素材丰富度检查（有冲击力的数据？转折故事？金句？权威背书？痛点共鸣？），最后生成 10-15 条优化开头 + Top 3 推荐。

**开头公式**：话题（讲什么）+ Hook（为什么看）+ 可信度（为什么信你）

**反面雷区**：
- 不要假设用户看了标题
- 不要直接给答案（要制造悬念）
- 不要自问自答、书面语

## 4. dbs-goal — 目标审计

**一句话**：把"我想做个人 IP""我想变得更好"这种空话，审计成可以检查的具体交付物。

**什么时候用**：
- 你定了一个目标，但感觉很虚、没法执行
- 你说"我要做有影响力的内容"但不知道算不算完成
- 你想知道自己是真的有目标，还是只有愿望

**怎么用**：
```
/dbs-goal 我想在接下来三个月把公众号做到 5000 粉
```
→ AI 会用维特根斯坦语言哲学做"空转词检测"（更好、真正、深度、系统、影响力等黑名单词），然后走 7 项审计矩阵（可指物性、可否证性、有完成性、可测量、可行动、嵌上下文、有时限），最后输出审计后目标 + 下一步行动 + 完成标准。

**核心原则**：每个词必须做工作。去掉这个词，句子还成立吗？成立 = 空转。

**审计示例**：
- "我想做个人 IP" → 审计后："在接下来 90 天，每周发布 3 条关于 XX 领域的短视频，累计 50 条，从中找出最受欢迎的 3 个主题方向"
- "我想变得更好" → 空转严重，追问具体领域

## 5. dbs-action — 执行力诊断

**一句话**：用阿德勒个体心理学诊断你"知道该做什么但就是不做"的真实原因。不是激励工具，是诊断工具。

**什么时候用**：
- 你一直在拖延发内容、联系客户、写文章
- 你知道该做但每天都在"准备""调研""学习"
- 你觉得自己执行力差，但不知道真正的原因

**怎么用**：
```
/dbs-action 我知道这周该发 3 条视频，但拖了 5 天一条都没拍
```
→ AI 会匹配 8 种逃避模式（完美主义、执行模拟器、需求调研成瘾、找捷径、知识囤积、反复换方向、等正反馈、工具优化成瘾），追根溯源找到核心恐惧，然后给 ≤3 条行动处方（动词开头 + 可执行 + 有数字/时间 + 低到不可能失败的门槛）。

**5 条核心公理**：
1. 拖延是有目的的——维护"能力强但被拖延耽误"的人设
2. "想赚钱"≠ 想赚钱——"正在赚钱"才叫想赚钱
3. 人们主动制造无知——为了让"不行"合理化
4. 课题分离——烦恼也能做业务
5. 自由太沉重——明知答案却逃避

**注意**：不鼓励、不鸡汤。直接说"你不是不知道怎么做，你是不想做"。

## 6. dbs-diagnosis — 商业模式诊断

**一句话**：核心工作不是回答问题，而是消解问题——99.1% 的商业问题在被正确提问前就已经被消解了。

**什么时候用**：
- 有人问你"这个生意能不能做"
- 你在思考自己的变现模式
- 你想知道一个商业想法有没有致命缺陷
- 社群有人问"怎么定价""怎么获客"

**怎么用**（两种模式）：
- **问诊模式**：带具体问题来
  ```
  /dbs-diagnosis 我做了一个知识付费社群，想收 999/年，怎么定价？
  ```
- **体检模式**：没有具体问题，系统拆解你的商业模式
  ```
  /dbs-diagnosis 帮我体检一下我现在的商业模式
  ```

**5 层消解漏斗**：
1. 语言陷阱检测——"赛道""适合""值得"这些词有定义吗？
2. 假设错误检测——你的问题假设了什么不成立的前提？
3. 商业模式 ABC 分类——A 类（有产品）+ B 类（有客户无产品）+ C 类（两者皆无）
4. 心理卡点检测——A-F 六种心理模式在阻碍你吗？
5. 产品/客户/收入三角——三个问题都答不上来 = 没有商业模式

**核心原则**：
- 高利润是唯一标准
- 流量 ≠ 收入
- 定价即产品——引流款和利润款价差最好 10 倍

## 7. dbs-deconstruct — 概念拆解

**一句话**：用维特根斯坦语言哲学和奥派经济学，把模糊商业概念拆到原子级——直到每个词都有明确的含义。

**什么时候用**：
- 你听到一个流行概念（"精准流量""私域""个人 IP""复利"）但感觉模糊
- 你在写内容时用了一个词，但不确定自己真的理解
- 你想知道一个概念是不是"伪概念"
- 社群讨论中有人用了大量行话但意思不清晰

**怎么用**：
```
/dbs-deconstruct 帮我拆一下"精准流量"这个概念
```
→ AI 会做：使用场景分析（不同人用这个词是什么意思）→ 伪概念检测（去掉这个词用大白话还能说清吗？）→ 奥派经济学校准（涉及商业/经济时）→ 输出大白话版定义 + 一针见血的判断。

**伪概念检测法**（核心工具）：去掉这个词，用大白话说同一件事，还能说清楚吗？
- 能 → 这个词只是包装，可有可无
- 不能 → 这个词在掩盖你理解的空白

**经典案例**：
- "精准流量" → 三种含义：卖课的 = 愿付费的人，电商的 = 搜关键词的人，IP 的 = 认识我的人。大白话："能转化成付费客户的访客"
- "个人 IP" → 伪概念，不存在可被算法计算的"正确定位"。大白话："你想让别人怎么记住你"
- "赛道""行业" → 需要删除的词，预设了可选择的线性路径

## 8. dbs-benchmark — 对标分析

**一句话**：用五重过滤法帮你找到值得模仿的对标，排除一切关于"我"的噪音。

**什么时候用**：
- 你想找一个同行来模仿，但不知道选谁
- 你不知道一个内容方向能不能赚钱
- 你想了解某个对手的商业模式是否值得复制
- 你说"我想找一个适合我的对标"（这本身就是问题）

**怎么用**：
```
/dbs-benchmark 我想在小红书做知识付费，帮我找一个值得模仿的对标
```
→ AI 会先搞清楚你的现状，然后走五重过滤法：

**五重过滤**：
1. **他赚钱吗？** 利润至少是你当前收入的 10 倍。
2. **你能看懂吗？** 能看懂获客-转化-交付的完整链条。
3. **你能模仿吗？** 有能力执行他的流程。
4. **他和你有本质差异吗？** 如果差距来自不可复制的资源，排除。
5. **值得长期模仿吗？** 他的模式有复利吗？

**核心信念**：模仿不是方法，是信仰。0 到 1 阶段，模仿是正确答案。模仿的颗粒度决定质量——对标到帧级别。

**反面雷区**：
- "我想找个适合我的对标"→ 立刻打断！不谈"我"，只谈业务
- "差异化"→ 后话，先活下来

## 9. dbs-resonate — 文稿共鸣诊断

**一句话**：写完内容后不确定能不能打中受众——给它诊断共鸣结构。

**什么时候用**：
- 你写完了一条脚本/文章，但心里没底
- 你担心内容"写得很全面但没刺中核心"
- 你想知道稿子发出去会有什么效果

**怎么用**：
```
/dbs-resonate 这是我刚写的脚本，帮我看看能不能引起共鸣
[粘贴完整文稿]
```
→ AI 会提取所有主张 → 找核心机制（如果只能保留一件事，保留哪件？）→ 五维度共鸣诊断（沉默解除、满足动机、立场框架、传播入口、信念结构）→ 给出具体改法（删掉什么、缩短为什么、强化什么、保持不动什么）。

**四个常见问题模式**：
- 模式 1：核心被稀释——3-6 个观点每个都在说不同的事
- 模式 2：机制说了但没说清——结论有了但没解释"为什么"
- 模式 3：立场漂移——开头站服务者那边，中间变建议者，结尾变教育者
- 模式 4：沉默解除弱——内容正确但平淡，受众看完只会说"嗯，有道理"

**注意**：不预测平台算法表现（完播率、点击率）。不评价好坏。只诊断共鸣结构。

## 10. dbs-spread — 传播心理解码

**一句话**：用 5 个经典传播学理论（都是 1980 年前已学术验证的）解码一条内容为什么能引起共鸣。

**什么时候用**：
- 你看到一条爆款内容，想知道为什么能火
- 你想理解受众情绪底层，为下一个选题找方向
- 你想分析一个话题的传播入口和受众心理

**怎么用**：
```
/dbs-spread 这是我看到的一条爆款，帮我分析为什么能火
[粘贴内容]
```
→ AI 会依次通过 5 个经典传播学理论做分析：

| 理论 | 回答的问题 |
|------|-----------|
| 沉默的螺旋（诺依曼,1974） | 受众憋着什么情绪没公开说？ |
| 使用与满足理论（卡茨,1959） | 受众接触这内容满足了什么心理需求？ |
| 框架理论（恩特曼,1993） | 内容用什么框架/立场切入？为什么有效？ |
| 两级传播理论（拉扎斯菲尔德,1944） | 谁会第一个传播？他们的动机是什么？ |
| 认知一致性理论（费斯汀格,1957） | 内容确认了什么信念？挑战了什么行为？ |

**输出**：5 维度分析 + 综合推导（受众情绪底层、有效立场、受众还想听什么、聊天室方向）。

**与 dbs-resonate 的区别**：
- dbs-resonate：你的稿子还没发，诊断会不会有共鸣
- dbs-spread：别人的内容已经火了，解码为什么会有共鸣

## 11. dbs-slowisfast — 慢方法诊断

**一句话**：帮你区分"值得慢做的事"和"只是拖延"。核心逻辑：慢方法 → 摩擦 → 判断 → 资产 → 复利。

**什么时候用**：
- 你在纠结一件事该不该花大量时间慢慢做
- 有人说"你该慢下来"，但你不知道这是对的还是借口
- 你在思考"搭建写作系统""积累客户关系"这类长期投入

**怎么用**：
```
/dbs-slowisfast 我在考虑花 3 个月搭建写作系统，值得吗？
```
→ AI 走 5 个问题：
1. 做完会产生什么资产？（能积累+能复用？）
2. 慢做和不做的区别是什么？（有区别 = 继续；没区别 = 只是拖延）
3. 过程中会形成判断吗？（需要直觉/审美/品味？还是纯机械重复？）
4. 一个月后回头看，有价值吗？
5. 你是不是在用"慢"逃避某个更恐惧的事？

**5 种值得慢做的事**：积累理解、建立系统、培养关系、打磨手艺、验证假设

**经典案例**：
- "花 3 个月搭写作系统"→ 通过。资产：可复用的内容单元库，长期节省每次写作的决策成本
- "慢慢学 Python"→ 不通过。如果是为了"逃避赚钱"= 心理问题。如果为了"做产品"= 有产品需求驱动才值得
- "每天写 1000 字但不发布"→ 不通过。没发布 = 没反馈 = 没判断 = 没资产 = 只是慢

## 12. dbs-save / dbs-restore — 存档与恢复

**一句话**：把任何一次诊断的结论保存下来，下次回来直接接着上次。

**什么时候用**：
- 一次诊断结束，结论有价值，不想忘记
- 下次想继续上次的分析，不需要从头解释
- 长期追踪一个问题的演变

**怎么用**：
```
/dbs-save 把这次对标分析的结论存档
/dbs-restore 恢复上次的对标分析结论
```

# 第二部分：真实场景演练

以下 8 个场景全部基于董辉的真实自媒体工作情境。

## 场景 1：写了一条关于亏 5300 的脚本，但觉得 Hook 不够强

**背景**：你最近亏了 5300 块钱，想写一条短视频分享这个教训。脚本写出来了，但开头总觉得不够吸引人。

**错误做法**：反复改开头，改来改去都不满意，最后随便发了一条。

**正确流程**：

**第 1 步：先诊断内容本身有没有问题**
```
/dbs-hook 这是我的脚本：
[粘贴脚本]
```
→ dbs-hook 会先做内容质量检查。如果内容本身缺乏冲击力素材（数字不够、故事不够、金句不够），它会告诉你"先丰富内容再优化开头"。

**第 2 步：拿到 10-15 条优化开头**
→ 如果内容质量过关，dbs-hook 会生成三类开头：
- 素材搬运（从你的脚本中提取最强素材做开头）
- 素材增补（建议你补充什么素材）
- 悬念制造（制造什么悬念让人想看下去）

**第 3 步：选 Top 3 推荐，决定用哪条**

**第 4 步（可选）：如果还不确定，追加共鸣诊断**
```
/dbs-resonate 这是最终版本，帮我看看能不能打中人
[粘贴定稿]
```

**用时预估**：10-15 分钟

---

## 场景 2：社群有人问"怎么定价"，你回复了但不确定对不对

**背景**：社群里有成员问"我做了 XX 服务，不知道该怎么定价"。你根据自己的经验给了回答，但事后不确定这个回答是否足够好——甚至不确定这个问题的前提对不对。

**错误做法**：凭感觉回复，事后越想越虚。

**正确流程**：

**第 1 步：先走商业模式诊断，消解问题本身**
```
/dbs-diagnosis 有人在社群问"我做了一个课程，不知道定价多少合适"，这问题成立吗？
```
→ dbs-diagnosis 会先做语言陷阱检测："定价多少合适"中的"合适"没有定义。消解后可能发现真正的问题是"他不知道自己的客户是谁"，不是"不知道该定多少钱"。

**第 2 步：如果问题成立，用诊断结论回复社群**

**第 3 步（可选）：如果有人追问"那怎么找对标定价"，追加对标分析**
```
/dbs-benchmark 帮我找几个类似课程的定价对标
```

**第 4 步：存档结论，下次社群再问类似问题直接引用**
```
/dbs-save 社群定价诊断结论
```

**用时预估**：5-10 分钟

---

## 场景 3：不知道选什么选题方向，感觉什么都能写但什么都不够好

**背景**：到了该发内容的时间，但打开空白文档后不知道写什么。脑子里有好几个方向，但每个都觉得"不够好""不够有爆点""别人写过了"。

**错误做法**：打开手机刷同行、看热点，越刷越焦虑，最后啥也没发。

**正确流程**：

**第 1 步：先判断——这是"选题问题"还是"执行问题"**
```
/dbs-action 我到了发内容的时间但不知道写什么，是选题问题还是我在逃避？
```
→ 大概率会被诊断出"执行模拟器"（想法太多一个也不做）或"等正反馈"（没有好数据就不想发）。

**第 2 步：如果确实是选题问题，走目标审计**
```
/dbs-goal 我想写内容但不知道选哪个方向
```
→ dbs-goal 会追问："你想通过内容达到什么？"帮你把模糊的"想做内容"变成可检查的具体目标（"在某个平台上每周发 X 条关于 Y 的内容"）。

**第 3 步：如果方向有了但不知道具体选题，走对标分析**
```
/dbs-benchmark 我确定了做 XX 方向，帮我找一个值得模仿的对标
```
→ 有对标后，模仿对标的选题节奏和角度。

**第 4 步：有了选题后，走内容诊断**
```
/dbs-content 我的选题是"XX"，怎么切入比较好？
```

**用时预估**：20-30 分钟（第一次用这套流程），后续 10 分钟以内

---

## 场景 4：写了一篇公众号文章，改了三遍还是不满意

**背景**：你花了一下午写了一篇公众号文章，自我感觉还行，但反复读了几遍后又觉得"写得像 AI""没什么记忆点""读者可能看不完"。

**错误做法**：继续反复修改措辞、调整段落顺序，不知不觉改了 2 小时还是不满意。

**正确流程**：

**第 1 步：走内容诊断，定位根本问题**
```
/dbs-content 这是我写的文章，帮我诊断哪里有问题
[粘贴全文]
```
→ dbs-content 会做五维度诊断，告诉你问题出在价值密度不够、还是差异化不足、还是语言有 AI 味。

**第 2 步：走共鸣诊断，看看能不能打中人**
```
/dbs-resonate 同一篇文章，帮我看看共鸣结构有没有问题
[粘贴全文]
```
→ 这一步最关键！它会找出"核心被稀释"（同时说了太多事）、"立场漂移"（从服务者变成说教者）、"沉默解除弱"（正确但平淡）等问题。

**第 3 步：根据诊断结论，有针对性地修改——而不是盲目反复改措辞**

**第 4 步（可选）：如果开头是短板，追加 Hook 优化**
```
/dbs-hook 帮我优化这篇文章的开头（如果是视频版本的话）
```

**用时预估**：15-20 分钟

---

## 场景 5：想做知识付费但不确定先做什么产品

**背景**：你已经在输出内容一段时间了，后台偶尔有人私信问"能不能付费咨询"，但你不确定自己的第一个付费产品应该是课程、社群、咨询还是别的什么。

**错误做法**：看同行在卖什么就跟着做什么，或者一直"调研""准备"但迟迟不上架。

**正确流程**：

**第 1 步：走商业模式体检**
```
/dbs-diagnosis 帮我体检一下我现在的商业模式
我是一个自媒体人，目前有[粉丝数]关注，后台私信[情况]，我想做付费产品
```
→ 体检模式会逐项检查：产品是什么？定价合理吗？客户是谁？收入来源可持续吗？壁垒在哪？心理卡点是什么？

**第 2 步：如果检测到心理卡点（A-F 模式），追加执行力诊断**
```
/dbs-action 我知道该上架产品但一直在拖
```

**第 3 步：如果产品方向尚不清晰，找对标**
```
/dbs-benchmark 找几个和我类似体量的知识博主，看他们的第一个付费产品是什么
```

**第 4 步：产品确定后，用内容诊断为产品写宣传内容**
```
/dbs-content 我的产品是 XX，怎么用内容来推？
```

**用时预估**：25-35 分钟

## 场景 6：看了一条爆款内容，想模仿但不知道怎么拆

**背景**：你刷到一条同行的小红书/抖音爆款，点赞过万，你很想知道它是怎么火的，以及自己能不能复制。

**错误做法**：凭感觉分析"它的标题很有吸引力""它的话题选得好"——这些都是正确的废话。

**正确流程**：

**第 1 步：走传播心理解码，用学术理论分析**
```
/dbs-spread 帮我解码这条爆款为什么能火
[粘贴内容]
```
→ 会从五个经典传播学理论逐一分析：受众憋着什么情绪？（沉默的螺旋）满足了什么心理需求？（使用与满足）用什么框架切入？（框架理论）谁会第一个转发？（两级传播）确认了什么信念？（认知一致性）

**第 2 步：走对标分析，判断是否值得模仿**
```
/dbs-benchmark 这个创作者值得当做对标来模仿吗？
```

**第 3 步：走 Hook 分析，拆解开头的具体技术**
```
/dbs-hook 帮我分析这条内容的开头用了什么技术
```

**第 4 步：模仿产出自己的版本，然后走共鸣诊断验证**
```
/dbs-resonate 这是我模仿写的一版，帮我看看效果
[粘贴自己的版本]
```

**用时预估**：20-30 分钟

## 场景 7：社群运营了一段时间，不知道该发什么内容

**背景**：你建了一个付费社群，初期大家很活跃，但最近逐渐沉寂。你不知道该发什么内容来重新激活，也担心发太多变成打扰。

**错误做法**：发一些网上的"干货"截图，或者干脆不发了等大家自己聊。

**正确流程**：

**第 1 步：走商业模式诊断的问诊模式，定位社群的真正问题**
```
/dbs-diagnosis 我的付费社群最近不活跃了，这是内容问题还是商业模式问题？
```

**第 2 步：走传播心理解码，分析社群受众还想听什么**
```
/dbs-spread 我的社群受众是这样的：[描述受众画像]，他们最近对什么情绪最敏感？
```

**第 3 步：走内容诊断，为社群策划内容方向**
```
/dbs-content 我想在社群里持续提供价值，应该做什么形式的内容？
```

**第 4 步：走慢方法诊断，判断社群运营是否值得长期做**
```
/dbs-slowisfast 我该花大量时间做社群运营吗？还是该把精力放在公域内容上？
```

**用时预估**：20-25 分钟

## 场景 8：每天的"选题→写稿→发布"循环效率太低

**背景**：你发现自己的内容生产流程很混乱：今天想到一个选题就写一个，明天没灵感就不发。你想把流程系统化，但不知道从哪里开始。

**错误做法**：到处搜"自媒体工作流模板"，下载一堆 Notion 模板，花了 3 天搭系统但一篇内容都没写。

**正确流程**：

**第 1 步：走慢方法诊断，判断"搭建系统"是否值得**

/dbs-slowisfast 我该花时间搭建写作系统吗？还是先保证每天输出？
```

**第 2 步：走目标审计，把"提高效率"变成可检查的目标**
```

**第 3 步：走对标分析，找内容生产系统做得好的对标**

/dbs-benchmark 哪些博主的内容生产流程值得参考？

```
/dbs-content 我用模板化方式生产的内容，会不会失去个人特色？
```

**用时预估**：25-30 分钟

# 第三部分：常见错误用法和纠正

## 错误 1：跳过 dbs-orchestrator，凭感觉选技能

**表现**：你觉得自己的问题是"执行力"，直接用了 dbs-action，但实际上是因为"目标不清晰"导致无法执行——应该先用 dbs-goal。

**纠正**：任何时候不确定该用哪个技能，先用 dbs-orchestrator 路由。它的存在就是为了解决这个问题。

---

## 错误 2：让 dbs-content 帮你写内容

**表现**：把选题丢给 dbs-content，期待它帮你生成一篇完整的文章。

**纠正**：dbs-content 明确说"不帮人写内容，帮人诊断内容该怎么做"。写是你自己的事。正确的用法是：你写了初稿 → 让它诊断 → 你按诊断结论改。

---

## 错误 3：在内容质量不过关的情况下强行优化 Hook

**表现**：你写了一条内容空洞的脚本，然后让 dbs-hook 优化开头。dbs-hook 告诉你"内容本身有问题，先丰富内容"，但你忽略了这个提示，继续要求它生成 Hook。

**纠正**：dbs-hook 的核心信念是"写不出好开头，90% 是内容本身有问题"。如果它说内容不行，先用 dbs-content 修内容，再回来优化 Hook。

---

## 错误 4：把 dbs-diagnosis 当搜索引擎用

**表现**：你问 dbs-diagnosis "小红书上怎么开店"，期待它给你步骤指南。

**纠正**：dbs-diagnosis 的工作是消解问题（判断问题成不成立），不是回答信息类问题。纯信息获取类问题（"怎么注册公司"）它只会直接回答或指路。商业模式类问题（"我这个生意怎么赚钱"）才是它的领域。

---

## 错误 5：把 dbs-benchmark 的"模仿"理解为"抄袭"

**表现**：你找了一个对标，然后原封不动复制对方的文案和定位。

**纠正**：dbs-benchmark 强调"模仿不是搬运"——模仿是理解后重建，搬运是不理解直接复制。对标到帧级别意味着理解对方的每一个决策为什么那样做，然后用自己的方式做同样的事。

---

## 错误 6：在 dbs-goal 审计中拒绝删除空转词

**表现**：你的目标是"我想做真正有价值的深度内容"。dbs-goal 指出"真正""有价值""深度"都是空转词，你却说"但我就是想要那种感觉"。

**纠正**：dbs-goal 的核心使命是"反对目标语言的空转"。每个词必须做工作。不能说"我就是想要那种感觉"——感觉不是目标，是不能检查的愿望。

---

## 错误 7：用 dbs-slowisfast 合理化拖延

**表现**：你知道该发内容了，但告诉自己和 dbs-slowisfast "我在慢慢搭建写作系统，这是值得慢做的事"。

**纠正**：dbs-slowisfast 的 5 个问题中，第 2 个就是"慢做和不做的区别是什么？"没有区别 = 只是拖延。第 5 个是"你是不是在用'慢'逃避某个更恐惧的事？"。两个问题会直接识别这种"伪慢方法"。

---

## 错误 8：一次性问太多技能，期望一个回答解决所有问题

**表现**：你在一条消息里说"帮我诊断商业模式 + 优化开头 + 找对标 + 拆解概念"。

**纠正**：每个 DBS 技能有独立的诊断流程，需要逐步对话。使用场景 3、4、5 中的"多技能联动"流程，一次解决一个问题，然后自然过渡到下一个。

---

# 第五部分：新手最容易上手的 Top 5 技能

如果你是第一次用 DBS 技能系统，按这个顺序开始：

---

## 🥇 第一名：dbs-orchestrator（总路由）

**为什么先学这个**：你不需要记住 12 个技能各自是干什么的。任何问题丢给 orchestrator，它会帮你判断该用哪个。

**第一次使用**：
```
/dbs-orchestrator 我最近在做自媒体但不知道下一步该做什么
```
→ 它会告诉你：先去 dbs-goal 审计目标，还是先去 dbs-action 诊断执行。

**记忆口诀**："不知道用谁 → 用 dbs"

---

## 🥈 第二名：dbs-hook（开头优化）

**为什么先学这个**：这是最立竿见影的技能。你写一条脚本 → 它给你 10-15 个优化开头。马上就能用，马上就能看到效果。

**第一次使用**：把你最近写的一条脚本（哪怕只有正文没有开头）发给它。

**记忆口诀**："开头不够好 → dbs-hook"

---

## 🥉 第三名：dbs-content（内容诊断）

**为什么先学这个**：这是内容创作的核心技能。你的大多数日常问题（"这个选题怎么做""这篇文章行不行"）都归它管。

**第一次使用**：把你最近写的一篇文章或脚本发给它。

**记忆口诀**："写完了不确定 → dbs-content"

---

## 第四名：dbs-action（执行力诊断）

**为什么第四名**：自媒体最大的敌人不是"不会写"，而是"不想写"。dbs-action 用阿德勒心理学直接戳破你的逃避模式。

**第一次使用**：诚实地告诉它你最近在逃避什么。

**记忆口诀**："知道该做但不想做 → dbs-action"

---

## 第五名：dbs-benchmark（对标分析）

**为什么第五名**：当你不知道"该做什么内容"时，不要自己想，去找对标。dbs-benchmark 用五重过滤法帮你科学地选对标。

**第一次使用**：告诉它你在做的方向，让它帮你找值得模仿的人。

**记忆口诀**："不知道做什么 → 找对标 → dbs-benchmark"

---

## 五步上手法（第一天就能用）

1. **打开 Codex CLI**，输入 `/dbs-orchestrator 我是新人，该从哪里开始`
2. **它会路由你到 dbs-goal** → 把你现在的自媒体目标写下来让它审计
3. **审计完目标后** → 用 dbs-benchmark 找一个对标
4. **找到对标后** → 用 dbs-content 诊断你的第一个选题
5. **写完初稿后** → 用 dbs-hook 优化开头，用 dbs-resonate 验证共鸣

这个过程大约 60-90 分钟，但会帮你建立从"模糊想做"到"具体可执行"的完整路径。
