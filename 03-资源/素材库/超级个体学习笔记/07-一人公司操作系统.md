# 07｜一人公司操作系统

> 使用者锚点：21.8 岁；中国大陆；刚毕业；全职；六个月缓冲；极低成本；内容与服务型一人公司。事实、方法与适用边界统一回查 [98-证据与来源附录](./98-证据与来源附录.md)。

## 一次承诺如何穿过整家公司

一人公司的经营从承诺开始。内容带来一次咨询，产品边界经过沟通被写进报价，对方付款并交付资料，经营者排期、制作、复核、交付、验收，随后处理应收、退款、票据、资料和复盘。任何一环没有留下状态，后续都只能依赖记忆补洞。第 05 章负责让问题、内容与信任形成循环，见 [内容引擎与个人品牌](./05-内容引擎与个人品牌.md)；第 06 章负责把问题写成可以交易和履约的约定，见 [产品化与变现](./06-产品化与变现.md)。本章只处理承诺进入经营以后，怎样在有限注意力下保持可见、可控和可退出。

这里的一人公司指：由一个人保留最终控制权，用极小协作网络完成经营。网络可以包含 AI、软件、平台服务商、会计、律师、设计师、开发者或临时交付伙伴。人数没有教条，是否独自完成全部劳动也不构成定义。关键在于问题选择、客户承诺、资金配置、数据权限与风险承担最终集中到同一控制者。协作扩大能力，责任不会因点击“自动运行”或把任务委派出去而消失。

一项承诺至少要留下这条可回查链路：

`线索与适配判断 → 约定版本 → 收款与资料 → 排期与下一动作 → 制作与复核 → 交付与验收 → 应收/退款/票据收尾 → 资料处理与复盘`

链路不要求购买经营软件。一张本地表格、一个项目文件夹和稳定命名就能起步。每次只维护能够改变下一步行动的字段；尚无稳定需求时搭建销售、交付、财务、客服各自独立的重型系统，会增加同步和维护负担。

## 责任边界：谁可以做，谁必须负责

人的保留区包括问题选择、核心判断、对外承诺、客户关系、数据权限、最终验收，以及现金和风险决策。AI 或工具可以处理候选检索、转录、分类、格式转换、初稿、提醒、字段同步和规则检查，前提是输出可复核、操作可撤回、规则相对稳定。专业协作者适合承接边界清楚的专门任务，例如财税核对、合同审阅、视觉制作或技术实现；经营者仍需决定输入是否合规、范围是否准确、结果是否验收、后续怎样向客户负责。

| 参与者 | 适合承担 | 必须保留的控制点 |
| --- | --- | --- |
| 经营者 | 选择问题、定义承诺、判断例外、维护关系、配置现金 | 批准范围与价格，确认资料权限，验收最终结果，处理投诉与重大异常 |
| AI 与工具 | 规则较稳的整理、草拟、检查、提醒和传递 | 原始输入可回查，关键输出有人复核，保留日志、撤回和人工接管路径 |
| 外部协作者 | 有明确输入、交付物、期限和专业边界的任务 | 书面约定权限与保密要求，由经营者验收，并确认失败后的交接方式 |

交出任务前先回答四个问题：对方会接触哪些资料；什么结果才算完成；哪个节点需要自己批准；出错后由谁停止、恢复并通知相关人。答案含混时，先缩小任务。未经允许的客户材料不进入第三方 AI；未经核对的生成内容不直接发布；工具不得自行扩大报价、退款、数据用途或客户承诺。高风险专业事项可以取得专业意见，最终经营动作仍要由控制者确认。

## 自动化要沿着成熟度前进

合理顺序从删除工作开始。先问这一步能否消除；仍有必要，就收窄对象、输入、输出和渠道；重复发生后再统一命名、状态和完成标准；随后用清单、模板和示例稳定人工执行；稳定部分先做半自动化，让工具生成候选、人完成批准；最后才考虑无人值守自动化或外部协作。这条顺序允许随时退回。手工阶段暴露出来的例外和判断，正是后续设计规则所需的材料。

自动化判断至少检查八组条件：

| 条件 | 要核对的问题 |
| --- | --- |
| 输入与规则 | 输入是否结构化，规则是否在代表性任务中保持稳定，平台规则是否频繁变化 |
| 验收 | 输出能否由清单、样例或明确结果检查，谁执行最终验收 |
| 例外 | 例外是否常见，系统能否识别并停下，还是会把异常当成正常继续处理 |
| 后果与恢复 | 错误会损害多少现金、客户关系、声誉或权利，能否撤回并恢复到人工状态 |
| 审计 | 是否保存输入、版本、执行时间、输出、批准人和失败记录 |
| 数据 | 是否涉及个人信息、商业秘密、账号权限或未公开客户材料，第三方怎样留存、使用与删除 |
| 外部变化 | 平台接口、价格、账号政策或合规要求变化后，谁发现并更新规则 |
| 净节省 | 节省是否仍大于学习、迁移、复核、纠错、维护和异常处理的总成本 |

净节省要在真实任务里比较，不用演示环境的速度代替经营结果。低频任务、规则持续变化、输出难验收、错误后果高、恢复困难、敏感数据边界不清，或人工执行仍在帮助理解客户时，保持手工通常更稳妥。复核时间接近原人工时间，工具只是在改变劳动位置；异常处理持续打断深度工作，自动化还可能增加心力成本。此时应缩小自动化范围或直接停用。

首轮自动化只接管一段可逆链路，保留原流程、抽样复核、失败提示与人工入口。运行记录显示错误下降、净节省持续存在、数据边界清楚后，再扩大覆盖。任何自动化都要能回答“今天停掉后怎样继续交付”；没有答案，就形成了新的单点依赖。

## 一个足够小的经营控制面

早期经营只需要一张承诺总表和几份可追溯明细。总表让经营者看见下一项责任，明细在发生争议、退款、报税、数据请求或工具故障时提供证据。推荐的承诺卡字段如下：

`承诺编号｜客户与联系入口｜约定版本｜范围与不包含项｜输入及授权｜金额和收款状态｜到期时间｜当前状态｜下一动作与责任人｜交付及验收｜应收/退款/票据｜资料位置与处理安排｜异常与决定`

状态可以从少量可行动词开始，例如待确认、待付款、待资料、制作中、待客户确认、已完成、暂停、退款中、已关闭。每次收款、交付、范围变化、客户确认或异常发生时更新；没有变化时无需为了报表而反复填表。

最小控制面还要覆盖以下入口：

| 区域 | 最少看见什么 | 何时立即处理 |
| --- | --- | --- |
| 承诺与交付 | 范围、到期、状态、下一动作、验收、延期原因 | 出现漏记、临近到期仍缺输入、范围变化或无人负责 |
| 现金与应收 | 已收、待收、预计付款条件、退款状态、可用经营现金 | 收入尚未到账却准备形成现金承诺，或应收影响生存缓冲 |
| 成本与准备 | 项目直接成本、固定成本、续费与取消入口、退款和税费准备 | 固定成本无法取消、成本无法归属、准备金被日常支出占用 |
| 客户与资料 | 授权用途、资料位置、访问者、备份、导出和删除安排 | 用途变化、权限扩大、合作结束、客户撤回授权或发生泄露风险 |
| 经营核对 | 平台、合同、广告、消费者权益、个人信息、著作权、登记与许可入口 | 发布、收费、改变交付、采用新工具或进入新业务类型之前 |
| 异常与决定 | 发生事实、影响、临时处置、负责人、决定理由、恢复结果 | 同类异常重复，或一次事件可能影响客户、现金、数据和声誉 |

这张控制面不预测尚未发生的规模。记录模板和最小控制面应在第一笔承诺进入前建好，先留出承诺、现金、成本、授权、异常与决定等必要字段。当前没有真实经营数据，因此漏承诺率、返工率、工具错误、回款周期、投诉与现金压力对应的指标值、事件条目和统计基线保持为空；空白不能填成零，也不能用计划目标冒充运行结果。真实事件发生后按事实填写，后续规则只引用已经发生并可回查的记录。

## 财务保持简单，也要能追到原始凭证

个人生存缓冲与经营资金要分别看得见。经营计划按已到账现金安排，未收应收款单独列示；租用工具、委派协作、退款和其他现金承诺不能依赖尚未到账的收入。每笔收入和成本至少能回查日期、交易对方、对应项目、金额、用途、支付状态与原始凭证。项目直接成本归到具体承诺，固定成本记录续费条件、取消入口、数据导出方式和替代路径。退款与税费准备从可用现金中单独识别，不使用一个适用于所有业务的固定比例。

增加固定成本前，先看支付后还能否保护个人生存底线和现有交付；若答案依赖下一位客户及时付款，承诺已经超出当前现金能力。账目追溯的目标，是随时回答钱从哪里来、为哪个承诺花、是否已经结清、未来还能取消什么。它不要求早期经营者仿照成熟公司建立复杂部门和报表。

主体登记、税务、开票、经营许可与地方执行口径，会随经营地、业务内容和收款方式改变。实际收费前回到当地市场监管、税务机关及相关主管部门的官方入口核对，必要时请具备资质的专业人员处理[ᵃ](./98-证据与来源附录.md)。同样，平台发布与支付规则、合同和退款文本、商业推广与广告标识、消费者权益、个人信息和著作权，只保留会改变动作的核对入口：发布或收费前核对，业务和工具变化时重查，出现争议时保存版本与沟通记录[ᵃ](./98-证据与来源附录.md)。

## 数据边界与经营连续性

客户资料沿一条短生命周期管理：只收本次交付所需内容，说明用途和保存方式，确认访问权限，在受控位置处理，保留可恢复备份，按约定导出、归还、匿名化或删除。交付授权、案例公开授权和向第三方工具提供资料应分别确认；同意接受服务，不自动包含公开案例或用于训练工具的许可。个人信息处理与客户作品使用以当期官方规则和书面授权为准[ᵃ](./98-证据与来源附录.md)。

采用第三方 AI 或工具前，核对它需要什么权限、数据会发往哪里、是否用于训练或其他目的、保留多久、能否导出和删除、账号停用后怎样取回。能去标识化就不提交身份信息，能提供片段就不上传完整资料，能在本地完成就减少外发。敏感边界尚未确认时，使用虚构样例测试流程，真实客户材料继续留在人工路径。

连续性准备只保护关键承诺。为核心账号、资料、收款和交付分别留下：当前入口、权限持有人、最近可用导出、独立备份、人工步骤、替代联系渠道和恢复顺序。账号异常时暂停新承诺并转入人工沟通；支付受限时先核对已收与应收，不绕过规则收款；数据丢失时从独立副本恢复并记录影响；工具锁定时使用可导出格式和原始文件继续交付。

经营者暂时失能也要有可执行的最小恢复机制。先建立核心账号清单，记录各账号的用途与恢复入口；凭证由密码管理器保管，并配置紧急访问，或另备离线密封恢复包，同时妥善保存 2FA 备份码。手册和普通笔记不存明文密码，也不披露具体凭证。预先写明恢复触发条件，并指定可信联系人；联系人平时无需拥有完整权限，只在触发条件满足时获得完成必要动作的最小权限和操作范围，例如联系受影响客户、暂停新业务、停止自动扣费或自动发布、导出约定资料，以及启动账号或数据恢复。联络说明应让对方找到承诺清单、替代联系方式、已完成材料与专业协助入口，同时阻止无关人员接触客户数据。恢复方案越依赖单一平台、设备或经营者的记忆，连续性越弱。

## 零成本阶段先积累可撤回的资产

此阶段优先留下稳定 SOP、检查清单、承诺与交付状态、报价和授权文本、可追溯账目、异常库、决策日志、可导出数据，以及经过真实任务验证的半自动流程。它们直接降低遗漏、返工和迁移成本，也让后续协作者能在清楚边界内接手。为未来规模预建复杂系统、购买长期套餐或外包仍未理解的核心环节，会把现金和学习机会同时交出去。

增加软件、自动化或协作成本，需要几类信号共同出现：重复瓶颈已经留下记录；流程输入、关键步骤和验收逐渐稳定；计入学习、迁移、复核和维护后仍有净节省；错误或心力打断确有下降；方案可取消、数据可导出、人工流程可恢复；已到账现金能够承担试用和退出成本[ᵈ](./98-证据与来源附录.md)。外部协作者还要有边界明确的任务、可检查交付和必要权限。信号消失时停止续费、缩小授权或退回人工，不用沉没成本维持系统。

## 用真实异常改写规则

反馈先进入事件记录，再改变流程。每条记录区分实际发生、影响、当时处置和事后解释；一次只修改最接近问题的规则，观察下一次同类任务是否改善。当前基线为空，因此以下都属于收到对应信号后的处理方向，不构成已经发生的经营结论：

| 信号 | 先改哪里 |
| --- | --- |
| 漏承诺或延期 | 把所有入口汇入承诺表，承诺前检查容量、输入和下一动作；仍重复时缩小并行交付 |
| 返工增加 | 回查范围、样例、输入质量、里程碑和验收；把新增需求与原承诺分开 |
| 例外增多 | 区分一次异常与重复分支；重复例外推动收窄对象或修改流程，零散例外保留人工处理 |
| 工具错误 | 停止自动链路，保留证据并恢复人工；补验证、降权限或移除工具后再小范围测试 |
| 复核成本过高 | 缩小机器处理范围，改善输入与验收；净节省消失就取消自动化 |
| 现金压力 | 暂停新增固定成本，重查应收、退款准备和项目现金占用，只按已到账资金承诺 |
| 客户投诉 | 保存约定版本与沟通，先处理受影响交付，再检查销售表述、范围、过程和售后入口 |
| 数据风险 | 立即停止相关访问和外发，保护记录、收回权限、评估影响，并按适用规则处理通知与补救 |
| 心力消耗上升 | 找出同步沟通、切换、异常或复核来源，减少并行承诺、收窄服务或暂停扩张 |

规则修改完成后记录保留、调整、限缩或撤销的决定及理由。漏承诺下降但复核显著增加，说明问题从一个位置转移到另一个位置；现金改善却让客户等待与投诉上升，也不能判定流程更健康。最终判断同时看履约、现金、数据风险、心力与可复用资产。经营可控的迹象，是每项承诺都有下一动作，每笔钱和资料都能回查，异常能停下并恢复，新增成本能够撤回，真实反馈持续让规则变得更窄、更清楚。
