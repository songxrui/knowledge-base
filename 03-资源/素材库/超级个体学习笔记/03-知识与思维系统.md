# 03｜知识与思维系统

> 使用者锚点：21.8 岁；中国大陆；刚毕业；全职；极低成本；内容与服务型一人公司。事实、作者方法与适用边界统一回查 [98-证据与来源附录](./98-证据与来源附录.md)。

## 知识系统只为四类结果负责

内容服务型一人公司的知识系统，首先要改善四类结果：面对含混问题时能作出更好的判断，公开作品有更完整的论证与事实边界，客户交付中的经验可以被再次调用，重要决定能够追溯到当时掌握的证据。收藏量、笔记数、标签数和资料库体积都只是过程数据。它们若没有改变判断、作品、交付或后续选择，就没有完成经营任务。

这也决定了系统的入口。先写正在处理的问题，再决定需要什么输入。例如，为客户设计内容栏目时，需要了解目标读者、既有内容、成交路径和平台限制；此时收集与这些判断有关的案例和资料。暂时说不清会改变哪个项目、客户问题、公开内容或产品假设的材料，可以留在短期待处理区，也可以直接放弃。输入选择由现实任务牵引，能够缩短从疑问到作品、从交付到复用的距离。

知识系统还要保留未知。资料齐全的外观容易掩盖证据不足，流畅的笔记也可能只是转述。每个关键判断都允许标注“已有证据”“工作假设”“仍待确认”和“暂不处理”。对一人公司而言，知道哪里不能承诺，与知道怎样表达同样重要。

## 从问题到反馈的知识流

知识流包含八个流转步骤：**输入策展 → 捕获 → 组织 → 提炼 → 连接 → 表达 → 现实反馈 → 更新或淘汰**。这些步骤不要求一次走完，同一材料可以在多个项目中逐步加深；每一步只需留下足以回查、并能支持下一次使用的记录。

| 流转步骤 | 当前动作 | 进入下一步的条件或可回查记录 |
| --- | --- | --- |
| 输入策展 | 围绕真实项目、客户问题、公开内容或产品假设选择材料 | 能说明材料准备改变哪个判断 |
| 捕获 | 保存原文位置、作者、日期、关键片段与自己的疑问 | 日后能找回来源，不依赖记忆猜测 |
| 组织 | 放到当前项目、持续责任或主题资源附近 | 下次从问题出发可以找到 |
| 提炼 | 标出关键论点、证据、限制与可用表达 | 能快速判断是否值得重读 |
| 连接 | 与已有问题、概念、观点、案例、方案和决定建立关系 | 新材料改变或加强了某个结构 |
| 表达 | 形成方案、文章、视频、咨询答复、模板或产品模块 | 有明确对象、问题与完成标准 |
| 现实反馈 | 记录采用、追问、异议、返工、付款、数据和实际结果 | 获得了超出自我评价的信号 |
| 更新或淘汰 | 修订内容单元、适用条件、交付步骤和旧规则 | 当前版本与现实一致，历史仍可追溯 |

这条流动由输出倒逼。开始一篇文章前，先写它准备回答的问题、读者需要作出的判断和缺少的证据；开始客户项目时，先写交付物、责任边界和必须确认的信息；验证产品假设时，先写谁会在什么情境下使用。输入随后围绕这些缺口展开。读书和课程仍可保留探索性，但探索区要有容量上限，不能持续挤占正在交付的项目。

公开内容发布后的数据、实际采用和明确异议，要写回对应的项目归档与版本日志，使下一版能够看见修改依据。单个项目中的反馈先用于修订该项目；同一规律跨项目重复出现，才上升为规则更新。

## CODE、PARA 及其改写边界

Tiago Forte 将 CODE 定义为 Capture、Organize、Distill、Express，即捕获、组织、提炼、表达；将 PARA 定义为 Projects、Areas、Resources、Archives，即项目、领域、资源、归档[ᶜ](./98-证据与来源附录.md)。CODE 描述知识怎样被使用，PARA 提供按行动相关性安排信息的一种方法。两者都可以作为起点，不需要被当成四类天然存在的知识对象。

对当前的一人公司，可以把 CODE 扩写成前述八个流转步骤，把「连接、现实反馈、更新或淘汰」显式加入，因为内容和服务的价值要经过读者与客户检验。PARA 也可以按现有目录改写：进行中的稿件和客户任务属于项目；持续经营的内容、客户、财务与健康属于责任领域；书籍、案例和专题材料属于资源；结束项目及旧版本进入归档。若一个资料夹同时服务几个项目，不必为了分类纯度复制多份，保留一个来源，通过链接或索引调用即可。

现有内容单元库可以继续承担**可复用输出层**。正式入库的基本对象统一称为「内容单元」，只使用问题单元、概念单元、观点单元、案例单元和方案单元。每个单元使用独立的 Markdown 文件与 YAML frontmatter，按现有 [内容体系 AGENTS](../../../05-内容生产/内容体系/AGENTS.md)、[内容单元字段规范](../../../05-内容生产/内容体系/00-规则与索引/内容单元字段规范.md) 和对应类型模板执行。原始书籍、来源笔记、项目记录与客户材料仍保留在各自上下文中。兼容比重构重要，本章不要求迁移整个知识库，也不要求为旧文件补齐全部字段。

## 工作过程怎样沉淀为内容单元

来源笔记、日记、决策记录、项目问题记录和项目成品，首先是工作过程中的记录对象。来源笔记保存出处、原意与摘录位置；日记承担情绪卸载和事实留痕；决策记录保留当时的证据、选择与结果；项目问题记录组织当前答案、冲突与未知项；项目成品面向具体读者或客户承担结果。它们可以留在原来的项目和归档位置，不因已经写成文档就自动进入正式内容单元库。

工作记录出现跨项目复用价值后，再判断应沉淀为哪类内容单元。问题单元保留反复出现、值得持续回答的问题；概念单元说明一个概念的定义、作用与边界；观点单元表达一项有适用范围的核心判断；案例单元保留具体情境、过程、结果与限制；方案单元回应明确问题，说明可执行路径与预期结果。证据不单独设为一种内容单元，放在相关观点单元或案例单元中，并保留来源关系。

进入正式内容单元库时，来源笔记提供可追溯依据，日记中的重复信号可以形成问题单元，决策记录可能沉淀为观点、案例或方案单元，项目成品则按可复用部分分别提取。原记录继续保留，不必为适配五类对象而重构已有项目、归档或旧笔记。

这里的「原子性」只用于判断内容单元的粒度：一条单元只承担一个可独立复用的主要问题、概念、观点、案例或方案。单元内部可以保留证据、边界和明确关系，但不同时承载几个彼此独立的主要对象。依赖论证顺序、人物关系、合同条款、客户背景或作者完整定义才能成立时，应保留完整语境，不强行拆分；只有「读过」和「觉得重要」而没有独立用途的摘录，继续留在来源笔记即可。

## 渐进式提炼发生在使用时

渐进式提炼的重点，是让同一材料在反复使用中逐层显出价值，而非读完后立刻加工全部内容[ᶜ](./98-证据与来源附录.md)。第一次捕获只需保存来源和相关片段；进入项目时再标出关键句、写边注、压缩成自己的表述；需要公开表达或客户交付时，再核对原文、补充反例、明确适用条件，并连接到问题笔记与成品。

这种方式允许大量材料停在浅层。一本书只解决了当前项目的两个问题，就先处理相关章节；一门课程没有进入练习、作品或交付，不必为了“完成学习”制作全套笔记。学习技能时，笔记应服务于可观察任务、反馈和纠错；记录方法却不实际练习，无法替代能力形成[ᵇ](./98-证据与来源附录.md)。写作时则从读者问题和结论结构组织材料，不沿着阅读顺序堆放摘录[ᶜ](./98-证据与来源附录.md)。

## 让重要决定可以回查

重要决定至少记录七项：**问题、当时证据、关键假设、可选方案、实际选择、预期结果、实际结果与修订**。其中「当时证据」必须带日期，并区分事实、他人观点和自己的解释；「预期结果」在行动前写下；结果出现后再补记录，不能把后来知道的信息写回原判断。这样才能区分一次好结果是否来自可靠判断，也能看见一次坏结果是否只是可承受波动。

需要记录的是会影响现金、客户承诺、公开声誉、数据版权、产品方向或较长时间投入的决定。低风险、容易撤回的日常选择不必逐条留档，否则系统会变成文书负担。记录也不追求证明自己当时合理，它要暴露被忽略的证据、过强的假设和重复出现的判断偏差。复查时可以保留原记录，在下方追加「结果」「意外」「规则修订」和生效日期，不覆盖旧版本。

日记与复盘承担不同职责。日记用于情绪卸载和事实留痕，可以写身体感受、担忧、当天事件与尚未解决的念头，不要求形成结论；复盘用于跨事件识别模式，判断哪些流程、边界或规则需要更新。同一问题重复出现、开始影响现金、交付或声誉，或者已经需要修改规则时，应从日记升级为复盘或决策记录。只有当记录将改变下一步时才继续追踪某项指标。若每天填写大量评分却很少产生决策，或漏记一次就产生自责，应减少字段、降低频率或暂停。知识系统服务经营者，不承担持续监视经营者的功能。

## AI 扩大处理能力，人保留责任

AI 适合承担检索候选、初步归类、长材料摘要、版本对比、反方论证、练习题生成、格式转换和重复性整理。它也可以把多个客户问题聚成待核对主题，把一份长方案转成不同平台的草稿，或指出论证中缺失的前提。所有输出都应保留来源入口。复核分三档：内部粗摘要至少回看原文关键段；工作草稿核对关键主张、重要遗漏和引用位置；对外发布逐项核验事实、授权、隐私和承诺。

问题选择、证据可信度、亲身经验、价值与伦理判断、客户语境和最终承诺仍由人负责。AI 摘要不能替代对关键原文的阅读，尤其在作者定义、合同、法规、客户材料和可能影响收费承诺的事实中。无法定位原文的准确表述，不进入成品结论；AI 生成的案例不能冒充真实案例，流畅表达也不能替代证据。

中国大陆的平台内容可能因规则调整、账号状态、链接失效或产品变更而难以再次访问，重要资料与自有作品应回存本地，并保留来源、作者、日期和必要的版本信息[ᵃ](./98-证据与来源附录.md)。客户资料遵循最小收集、限定用途和必要保存；未经明确授权，不把可识别个人信息、商业秘密、未公开素材或完整客户文件输入第三方 AI。引用他人作品要保留出处并核对授权边界，匿名案例也要检查组合信息是否仍能识别当事人[ᵃ](./98-证据与来源附录.md)。

## 限制流量，及时清理与归档

系统需要同时限制输入流量和在制品。当前阶段可采用一组可调整的默认值：一个主交付项目加一个维护项目；同时深入的问题笔记不超过三个；待读材料只保留能服务这些问题的队列；捕获箱超过一屏或连续两个工作循环没有清空时，暂停新增收藏。限额不是效率竞赛，作用是让重要材料有机会进入表达与反馈。若项目复杂度上升，可以减少问题数；若持续有稳定输出且检索顺畅，再谨慎放宽。

出现以下信号时开始清理：同一资料被重复收藏却从未调用；标签增长快于作品；工具迁移占用的时间超过检索改善；课程不断入队而练习与交付停滞；来源已经失效或无法追溯；AI 摘要堆积却没有核对原文；输入连续增长，成品、客户采用和规则更新没有相应增加。清理时先删除无来源、无用途和可重新获取的副本，再合并重复笔记，将过时规则标记为停用。对仍有历史价值的内容归档，不必为了整洁永久删除。

项目结束时，把成品、最终采用的来源、关键决定、客户反馈、可公开边界、未解决问题和规则变化放在同一项目归档入口。能够跨项目复用的部分，再按问题、概念、观点、案例或方案提取到现有内容单元库；只对本项目有意义的沟通和过程材料留在归档。规则更新保留旧规则、修改理由、适用条件、生效日期和触发证据。官方要求变化、同类返工反复出现、客户使用结果与原假设冲突，或维护成本长期高于复用价值，都可以触发更新或淘汰。

课程收集、频繁迁移工具、标签过度、笔记完美主义、用 AI 摘要代替阅读，以及输入速度长期高于输出，是同一类失衡的不同表现：处理活动开始脱离现实问题。纠偏时不需要重建整个库，先冻结新增输入，选一个正在承担结果的项目，让现有材料完成一次“问题—表达—反馈—更新”的闭环。系统是否有效，最终看它有没有让下一次判断更清楚、作品更扎实、交付更稳定、决定更可追溯。
