# 08｜计划与优先级：在不确定性中分配有限容量

刚开始全职经营一人公司时，内容、服务、产品、学习与生活会争夺同一批资源。个人计划与公司计划共用时间、心力、现金、声誉和关系；多开一个承诺，返工、沟通与恢复成本也会进入系统。

计划的职责，是把有限容量分给少数承诺，提前暴露这些承诺之间的冲突，并建立足够快的反馈。它无法准确预测市场、平台、客户和自己的状态。把计划当作可修订的资源分配协议，遇到变化时便有东西可以比较、删减和改写；把计划当作未来剧本，变化一来就只剩下自责或强行追赶。

本章以三条北极星作为持续约束：可持续心力、复利资产、个人垄断。短期现金生存同样属于硬现实。任何安排都要回答：它会消耗什么，共享资源是否够用，会留下什么，以及何时根据证据退出。

## 从方向走到下一动作

一个可执行的计划需要自然层级。层级的作用在于逐层缩小选择空间，让上层约束下层，也让下层产生的事实能够反过来修正上层。愿景若直接跳成日清单，中间缺少阶段判断和项目取舍，今天做的事就可能很勤奋，却与当前瓶颈无关。

### 1. 长期方向与边界

长期层回答“想靠近怎样的生活与事业，以及不愿用什么代价交换”。方向可以包括形成可信赖的内容与服务能力、积累可复用资产；边界可以包括不长期透支睡眠、不靠无法履约的销售维持现金、不让单个平台控制全部触达。六个月缓冲、极低成本起步、尚无稳定产品市场匹配等现实约束也要写入。

目标仍然有用，它提供方向、边界与阶段性检验。系统负责把方向转成重复行动和反馈，两者承担不同职责。系统优于目标的判断，只能提醒我们别把一个结果数字当成完整行动机制，不能推出目标应被删除。[ᵇ](./98-证据与来源附录.md)

### 2. 当前阶段主题或瓶颈

阶段层回答“眼下哪一处约束最值得集中处理”。刚开始时，瓶颈可能是没有真实客户对话、交付能力不稳定、缺少可展示作品、现金消耗过快，也可能是心力已经下降。阶段主题应围绕已观察到的瓶颈选择，例如“获得问题证据”“稳定首个服务交付”“修复恢复能力”。它只是一段时期的聚焦声明，不需要预设固定季度长度。

瓶颈会随着证据改变。客户访谈显示需求判断错误，主题可以改写；现金缓冲明显缩短，原本偏长期的资产建设需要让位给可履约收入；心力持续下降，阶段重点应先收缩承诺。杠杆点帮助寻找影响更大的位置，却不能机械推出唯一最优动作。[ᵃ](./98-证据与来源附录.md)

### 3. 有完成标准的项目

项目为造成可观察变化而组织行动，须有完成或停止条件。“完成一份经目标客户反馈、可报价和交付的服务简报”比“研究咨询产品”更能支持取舍。项目承接阶段主题；无关且无硬承诺的想法留在候选区。

### 4. 对外与对内承诺

承诺层把责任显性化。对外承诺包括交付、客户回复、付款与合规；对内承诺包括恢复、学习和里程碑。税务/账务、回款、健康维护、关系修复、资料备份等运行型责任或维护项无须硬包装成项目；它们与项目并行占用容量，按触发条件、检查频率与状态边界管理，触发后形成承诺和下一动作。项目仍以完成或停止条件管理。

### 5. 当前条件下的下一动作

下一动作要能在现有信息、工具、能量和时间内完成，例如“根据访谈记录写出服务简报第一版”“向客户发送三个澄清问题”。若仍写成“推进产品”“优化内容”，说明尚未拆到可执行层。当天从已通过上层约束的活跃项目与硬边界维护项中选择，再按真实能量、临近承诺和可用时间收窄。

行动产生的新事实会修改项目，项目暴露的阻力会改变阶段主题，长期方向也可能更新。新起点有时能促进启动，却无法保证持续；持续性仍取决于容量、反馈和规则是否匹配。[ᵃ](./98-证据与来源附录.md)

## 用项目卡看见完整代价

项目卡不需要复杂软件。一页 Markdown 足以把模糊想法变成可审查承诺。下面是一组可替换问题，可按项目风险删改；它提供检查面，不提供固定答案。

| 项目卡字段 | 需要回答的问题 |
| --- | --- |
| 为什么现在 | 它对应哪个阶段瓶颈、硬边界或已存在承诺？推迟会发生什么？ |
| 预期改变 | 完成后，客户、现金、能力、流程或资产会出现什么可观察变化？ |
| 完成与停止 | 什么事实代表完成？出现什么证据、成本或期限时应暂停、缩小或停止？ |
| 下一里程碑 | 最近一个可验证结果是什么？谁能反馈，何时能获得反馈？ |
| 容量与现金 | 需要多少深度创造、交付、沟通、恢复和现金？这些只是估计还是已有记录？ |
| 依赖与风险 | 等待谁、依赖什么平台或工具？延期会影响哪些承诺与声誉？ |
| 复利资产 | 将留下简报、案例、模板、素材、流程、客户理解，还是只有一次性产出？ |
| 当前下一步 | 在目前条件下，哪个动作可以直接开始并留下可检查结果？ |

项目卡应在开工前揭露冲突。客户沟通与深度创造即使耗时相近，对注意力和恢复的影响也不同。没有历史数据时，容量估计只能标为默认假设[ᵈ](./98-证据与来源附录.md)，后续再用真实记录替换。

## 在制品限制来自容量

一人公司的在制品上限没有通用数字。它由可用容量、任务切换成本、等待依赖、承诺风险和恢复需要共同决定。每多开一个活跃项目，都会增加重新进入情境、同步信息、追踪承诺和处理意外的负担；频繁切换通常会伤害需要持续注意力的工作。[ᵃ](./98-证据与来源附录.md)

判断是否该减少并行，可以观察几个事实：延期反复出现，半成品持续堆积，深度工作被切成碎片，返工增加，客户回复开始遗漏，恢复质量下降，或者每天都在移动任务却没有里程碑完成。出现这些信号时，先停止开启新项目，再完成、缩小、暂停或取消已有项目。固定容量之后削减承诺，比先排满日历再要求自己提高效率更稳妥。

等待型项目或事项要写明下一检查时点、重新激活触发条件、失效/超时默认动作。是否占用 WIP 还看超时后果与注意力占用：低维护、低风险等待可不与活跃创造项目占同等槽位；客户材料、平台审核、授权、回款等高风险等待即使维护低，也不能静默退出控制面，直到重新激活、关闭或执行默认动作。

在制品限制的调整依据来自记录。若连续完成里程碑后仍有稳定恢复余量，可以小幅试验增加承诺；若吞吐下降或心力成本上升，立即收回。当前没有真实经营吞吐、延期和计划命中数据，所以本章不设项目上限，也不把任何作者的作息、产能或项目数量当成普遍事实。[ᵈ](./98-证据与来源附录.md)

## 优先级先过滤，再排序

把所有事项放进一张加权评分表，容易制造精确感，却会掩盖不可比较的代价。更实用的做法是依次过滤。

第一层先过滤现金生存、法定、履约和健康硬边界。自行设定现金缓冲下限、回款断点，列清已承诺现金支出与到期应收；边界由真实支出和风险承受能力确定，不套用固定 runway 数字，也不作财务结果承诺。触线后先执行最低合格动作：看清现金、催回应收、收窄支出与新增承诺、保护已收款交付；再进入瓶颈与复利排序。税务、合同和健康问题也按各自边界处理。紧急不自动等于重要，但真实履约风险不能因“长期主义”被忽略。

第二层检查当前瓶颈。通过硬边界的候选项，优先处理主要约束。缺少客户证据时，真实对话通常高于美化品牌页面。长期事项不自动胜过现金生存，两者由阶段约束协调。

第三层检查反馈速度与复利资产。能较快获得客户、市场或交付反馈的动作，有助于减少错误方向上的投入；能留下案例、模板、方法、受众关系或可复用素材的项目，能让一次劳动服务未来。但反馈快若只带来噪声，资产多若无人使用，都不足以单独决定优先级。系统中的反馈存在延迟，结果也可能晚于行动出现。[ᵃ](./98-证据与来源附录.md)

第四层检查可逆性与机会成本。低成本、可撤回的试验可以更快开始；高声誉风险、高现金投入、长期锁定的决定需要更多证据。选择一个项目也意味着放弃其他项目的时间窗，因此要明确“为了它，本阶段暂不做什么”。经过这些过滤后，剩余选项通常已经不多，再根据最近承诺、能量匹配和依赖条件排序即可。判断过程应保留理由，避免用一串伪精确分数代替责任。

## 先画容量，再安排时间

排程之前，先把共享资源放进同一张图。至少包括深度创造、客户交付、沟通运营、恢复生活四类容量，再补充现金、声誉和关系上的特殊约束。学习、内容、销售、服务与生活会跨越多类容量；只估工作小时，会漏掉沟通后的注意力残留、交付前的心理占用和高压后的恢复需求。

时间块可以保护重要工作，也应允许现实修改。[ᵇ](./98-证据与来源附录.md)先根据历史记录或保守假设划出可用容量，再放入硬承诺与恢复，最后安排阶段项目。没有历史记录时，所有块都标为试行[ᵈ](./98-证据与来源附录.md)。当天若能量低于预期，可保留最低履约动作，缩小创造任务；若出现临时客户事件，调整时间块并记录代价。修改计划并不等于计划失败，隐瞒修改才会让系统失去学习能力。

远期计划只写方向、边界和进入条件，近期才写可执行动作。可以把未来项目保留为候选，并注明“获得三次重复需求证据后进入”“现有交付稳定后进入”。接近执行时再补充里程碑、依赖和动作，这就是滚动细化。缓冲用于吸收返工、等待和状态波动，大小依据真实偏差修订，不采用固定比例。退出条件同样提前写：现金超过承受范围、关键假设被否定、心力持续恶化或机会成本明显改变时，项目应缩小、暂停或终止。

## 让反馈穿过延迟

计划需要同时观察领先信号、滞后结果和反馈延迟。领先信号靠近行动，例如有效客户对话、按约交付、完成可验证里程碑、发布后获得目标人群的具体回应；滞后结果包括收入、复购、稳定触达和口碑。领先信号不能冒充结果，滞后结果也不能脱离前序行动解释。

发布一天没有结果就换方向，可能只是忽略了反馈延迟；长期没有新证据仍坚持，则可能把耐心变成逃避。为每个项目写下“最早何时可能看到什么信号”“到什么条件仍无证据就调整”。时间地标能帮助重新启动和检查，但地标只提供观察点，不保证行为持续。[ᵃ](./98-证据与来源附录.md)

复盘可以由事实触发，无须强制绑定固定周、月或季度。触发点包括里程碑完成、重复延期、客户或市场证据变化、现金边界变化、心力明显下降。每次沿着同一条短链处理：先记录事实，再区分偏差来自估计、执行、依赖、范围或状态，然后决定保留、调整或停止，最后修改项目卡、容量假设或优先级规则。项目复盘的价值在于更新下一轮决策条件，不在于给自己打分。[ᵇ](./98-证据与来源附录.md)

## 从空基线开始积累

当前数据基线为空。第一阶段应如实记录计划承诺、实际完成、延期原因、切换次数、返工、等待、心力成本，以及每个项目留下的资产。目标值、预计工期和希望达到的结果都要与实际结果分栏；空白就保留空白，不能用目标填充结果。

这些记录先服务于几个朴素问题：一个可交付里程碑实际需要多少容量，哪些切换最昂贵，哪些等待可提前解除，哪些项目经常返工，什么类型的工作对心力消耗最高，哪些产出能被再次使用。积累数轮后，才有条件形成自己的在制品范围、缓冲方式和计划命中基线。单次波动不足以形成规则，重复出现的模式才值得写入操作系统。

极低成本阶段优先积累六类资产：项目简报、承诺记录、决策日志、复盘记录、可复用计划模板、真实容量数据。它们都可以用 Markdown、表格或已有日历完成。暂时不要为想象中的复杂度购买项目管理软件。只有重复漏项、检索困难或协作成为可观察瓶颈，流程已经相对稳定，新工具能够净节省时间，并且数据可导出、方案可撤回时，工具成本才有充分理由。工具应承接已经理解的流程，不能替代取舍。
