# DBS 状态追踪 v1.0

## 状态定义

### 内容单元状态

```
draft → ready → published → archived
  ↓                  ↓
deprecated ←──────────┘
```

| 状态 | 含义 | 进入条件 | 退出条件 |
|------|------|---------|---------|
| `draft` | 草稿 | 新建单元 | 通过质量门禁 → `ready`；内容错误 → `deprecated` |
| `ready` | 待发布 | 通过质量门禁 | 发布成功 → `published` |
| `published` | 已发布 | 在至少一个平台发布 | 内容过时 → `archived`；发现错误 → `deprecated` |
| `archived` | 已归档 | 发布超过 6 个月且无引用 | — |
| `deprecated` | 已废弃 | 内容有误或被新版本替代 | — |

### 选题状态

```
池中 → 已认领 → 装配中 → 已发布 → 已复盘
  ↓                              ↓
 放弃                         已归档
```

| 状态 | 含义 |
|------|------|
| 池中 | 选题记录已创建，等待认领 |
| 已认领 | 有人（或 agent）认领该选题 |
| 装配中 | 正在撰写草稿或制作视频 |
| 已发布 | 在至少一个平台发布 |
| 已复盘 | 完成 T+7 数据复盘 |
| 放弃 | 选题方向不成立 |
| 已归档 | 选题已过时效或不再相关 |

### 装配管线状态

| 阶段 | 抖音 | 公众号 |
|------|------|--------|
| 1. 选题入库 | ✅ | ✅ |
| 2. 素材检索 | ✅ | ✅ |
| 3. 脚本/文章撰写 | ✅ | ✅ |
| 4. 制作/配图 | HyperFrames | baoyu |
| 5. 质量检查 | 口播检测 | 6 门禁 |
| 6. 发布 | ✅ | ✅ |
| 7. 数据记录 | T+1 天 | T+1 天 |
| 8. 复盘 | T+7 天 | T+7 天 |

## 状态流转规则

### 自动流转
- `draft` → `ready`：通过质量门禁后自动流转
- `ready` → `published`：发布成功后自动流转
- `published` → `archived`：满足归档条件时批量流转

### 手动流转
- `draft` → `deprecated`：需要人工确认内容确实有误
- `published` → `deprecated`：需要人工确认新版本已覆盖

### 批量操作规则
- 每次批量更新 ≤10 个单元
- 批量变更后必须抽样验证 20%
- 变更理由写在 commit message 中

## 状态检查清单

### 每日检查
- [ ] 是否有 `draft` 状态超过 7 天的单元？（需要推进或放弃）
- [ ] 是否有 `ready` 状态超过 3 天的单元？（需要排期发布）
- [ ] 是否有选题在"装配中"超过 5 天？（需要加速或拆分）

### 每周检查
- [ ] 本周发布量是否达标？（公众号 ≥2，抖音 ≥3）
- [ ] 选题池是否有 ≥5 个有效选题？（低于 5 需要补充）
- [ ] 是否有 `published` 超过 6 个月的单元可以归档？

### 每月检查
- [ ] 统计数据记录完整度（目标 100%）
- [ ] 主题地图覆盖度是否提升？
- [ ] 废弃单元比例是否健康？（建议 <10%）

## YAML Front Matter 规范

每个内容文件头部必须包含状态字段：

```yaml
---
status: draft  # draft | ready | published | archived | deprecated
created: 2026-07-01
updated: 2026-07-01
---
```

## 批量状态更新脚本

```powershell
# 查看所有 draft 状态的单元
rg -l "status: draft" D:\KnowledgeBase\01-内容生产\

# 统计各状态数量
rg -c "status:" D:\KnowledgeBase\01-内容生产\
```
