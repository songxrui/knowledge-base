## 内容单元类型分类

| 类型代码 | 含义 | 判定标准 |
|---------|------|---------|
| QST | 问题 | 以问号结尾，或明确描述一个待解决问题 |
| CON | 概念 | 对一个术语/概念的清晰定义和拆解 |
| OPI | 观点 | 有明确立场的主张，可与主流观点不同 |
| CAS | 案例 | 真实发生的故事或事件，有时间/地点/人物 |
| SOL | 方法 | 可操作的步骤、框架、检查清单 |
| SRC | 来源 | 外部权威来源的引用（书籍/论文/人物） |
| DAT | 数据 | 可量化的统计、数字、指标 |
| GLD | 金句 | 单句可独立引用，有传播力的表达 |

## 内容状态分类

| 状态 | 含义 | 流转规则 |
|------|------|---------|
| `draft` | 草稿 | 新创建，内容不完整 |
| `ready` | 待发布 | 内容完整，通过质量门禁 |
| `published` | 已发布 | 已在至少一个平台发布 |
| `archived` | 已归档 | 内容过时或不适用，保留但不主动使用 |
| `deprecated` | 已废弃 | 内容有误或被新版本替代 |

## 选题优先级分类

| 优先级 | 条件 |
|--------|------|
| P0-紧急 | 有时效性（热点话题），3 天内必须发布 |
| P1-高 | 已有 ≥3 个可复用内容单元 + 数据验证 |
| P2-中 | 有内容单元支撑但无数据验证 |
| P3-低 | 仅有一个想法，无内容单元支撑 |
| P4-待定 | 方向不确定，需要更多研究 |

## 分类操作规范

1. **新建内容单元**：必须指定 TYPE、主题代码、状态
2. **新建选题**：必须指定优先级、目标平台、关联主题
3. **变更分类**：更新文件头部的 YAML front matter，记录变更原因
4. **批量分类**：≥10 个文件时，先抽样验证 3 个，确认分类准确后再批量操作
