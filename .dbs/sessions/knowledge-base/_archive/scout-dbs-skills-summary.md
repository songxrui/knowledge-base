## 1. dbs-content-system -- 内容结构化系统

### 用途
当用户本地已有足量内容资产（大量文章、推文、公众号、选题、案例、课程稿）时，把这些素材搭成可持续生长的本地内容工程。

### 输入
- 用户的内容目录路径 + 处理范围边界
- 内容资产：文章、推文、帖子、公众号文章、选题草稿、案例素材、课程稿、录音转写、历史爆款内容

### 输出
一套可继续运转的内容结构化工程，包含：
- 完整工程骨架
- 规则层（字段规范、关系规则、去重规则、来源登记规则）
- 原始素材副本
- 首批内容单元（Content Unit）
- 主题地图（Topic Map）+ 选题装配稿
- 关系索引 + 去重索引
- 8 个可运行 Node.js 脚本

### 工作流（7 Phase + 3 种推进行模式）

**Phase 1: 审计内容规模与边界**
- 判断内容量是否足够 + 边界是否清楚
- 不够或不清 -> 直接指出，不进入重工程

**Phase 2: 建立新工程骨架**
- 创建目录结构：规则/素材/单元/主题地图/装配/关系去重/脚本/状态

**Phase 3: 复制原始素材**
- 原则：原始目录里的原文件不碰，所有正式处理在新工程副本上进行

**Phase 4: 抽取内容单元（样本模式）**
- 先跑样本模式（少量素材），不直接全量推进
- 样本模式验证通过后才进入批量模式

**Phase 5: 生成主题地图与装配稿**
- 从已抽取的内容单元生成主题地图
- 按主题装配成可发布选题

**Phase 6: 关系、去重、总览校验**
- 生成: 关系索引、关系总览、去重候选索引、去重与冲突总览、处理状态总览
- 必须可运行 8 个 Node.js 脚本

**Phase 7: 批量推进与全量推进**

三种推进模式：
1. **样本模式**: 少量素材验证结构
2. **批量模式**: 按批次推进（分类->归一化->抽取），每批结束复盘
3. **全量模式**: 需通过 7 条升级闸门后才允许进入

`批量模式 -> 全量模式` 升级闸门（7 条）:
- 连续 2 个批次未改字段规范
- 连续 2 个批次未改关系规则
- 连续 2 个批次未改去重规则
- 连续 2 个批次未出现大面积返工
- 批次间能直接续跑无需重建工程
- 人工抽查 30 个内容单元重大误判不超过 3 个
- 去重候选没有失控堆积

### 核心公式/框架

```
内容单元 = 来源(溯源) + 核心观点/概念/案例 + 关系方向(in/out) + 去重字段
工程目标 = 能用态（非全量处理完）
```

### 核心原则
1. 先审计，再建工程
2. 默认目标是"系统能用了"，不是"全量处理完"
3. 结构先于规模（先验证结构再全量推进）
4. 原始素材不改写，只复制副本

### 与其他 DBS 技能的协作
- 转入: `/dbs-good-question`（问题说明书已写清）-> `/dbs-agent-migration`（Agent 工作台已迁好）
- 完成后推荐: `/dbs-content`（诊断具体选题）、`/dbs-decision`（判断节点是否升级为规律）、`/dbs-save`（存档结论）

## 3. dbs-content -- 内容创作诊断

### 用途
帮用户把已确认的选题诊断成好内容。

### 输入
- 用户选题 + 内容形式（图文/短视频/长视频/直播/文章）
- 可选: 初稿

### 输出
五维诊断报告：
```
# 内容诊断

## 选题诊断（选题本身有没有问题）
## 形式诊断（形式匹配对不对）
## 结构诊断（逻辑链是否完整）
## 表达诊断（文字是否清晰有力）
## 平台诊断（平台规则和传播策略）
---
## 具体优化建议（<=5 条，带数字/步骤）
## 一句话收尾
```

### 工作流（3 Phase）

**Phase 1: 接收内容**
- 问: "你的选题是什么？打算用什么形式做？如果已有初稿发给我。"

**Phase 2: 内容形式匹配**
- 按选题特性 -> 推荐形式 + 平台匹配表

**Phase 3: 五维诊断**
- 逐维诊断，每维有具体优化建议

### 核心哲学（5 条原则）
1. **文字洁癖是底线**: AI 内容被限流不是 AI 的问题，是文案的问题
2. **自媒体的本质是精神控制**: 封面和标题的本质是认知劫持
3. **内容好坏 = 投入精力 × 对内容有正确理解**: 投入精力 ≠ 内容好
4. **先有产品后有内容**: 内容是产品服务的
5. **知识博主的核心工作只有两个**: 1)把事情搞清楚 2)把事情说清楚

### 经典案例
- 修改封面标题（内容不变）: 播放量涨 3倍，互动涨 3倍，评论涨 4倍
- 小红书起号48小时3200粉: 账号×内容×运营 三个关键
- 死亡螺旋: 内容差 -> 没流量 -> 以量取胜 -> 内容更差

### 与其他 DBS 技能的协作
| 触发条件 | 推荐 |
|----------|------|
| 选题没想清楚 | `/dbs-good-question` |
| 平台选择/运营细节 | `/dbs-benchmark` 找对标 |
| 绕开关键摩擦 | `/dbs-slowisfast` |
| 用了模糊概念 | `/dbs-deconstruct` |
| 做不动一直在准备 | `/dbs-action` |

## 4. dbs-hook -- 短视频开头优化

### 用途
诊断短视频开头问题 + 生成可执行的优化方案。

### 核心信念
**写不出好开头，90% 是因为内容本身有问题。** 开头是内容的试穿装。

### 输入
- 完整文案（有开头+正文）或 只有正文 或 只有选题/标题

### 输出
三种优化方法输出:
- **方法一: 素材重组**（X 条）-- 从正文提取素材重组开头
- **方法二: 素材增补**（X 条）-- 增补新素材
- **方法三: 悬念制造**（X 条）-- 制造悬念的开头
- **Top 3 推荐**（含理由和优势）

### 工作流（3 Phase）

**Phase 1: 接收文案**

**Phase 2: 诊断内容质量（关键步骤）**
- 2.1 内容完整性检查: 只有选题/标题 -> 停止优化；正文太短 -> 警告；正文没价值 -> 停止优化
- 2.2 素材丰富度检查（5 维度）:
  - 有冲击力的数据？
  - 有转变故事？
  - 有金句？
  - 有权威背书？
  - 有痛点共鸣？
- 5 维度都没有 -> 停止优化

**Phase 3: 生成优化方案**
- 10-15 条开头 + Top 3 推荐

### 核心公式

```
开头公式 = 话题(讲什么) + Hook(为什么看) + 可信度(为什么信你)

示例:
- 话题: 选题和标题的区别
- Hook: 我去年涨粉 200 万
- 可信度: 靠的就是搞清楚这个
- 完整开头: "我去年涨粉 200 万，靠的就是搞清楚选题和标题的区别。"
```

### 核心信条（4 条）
1. 开头是内容的试穿装，不是标题的延续
2. 好开头 = 话题 + Hook + 可信度
3. 开头要制造悬念，不要直接给答案
4. 开头必须口播友好（禁止书面语、自问自答）

### 与其他 DBS 技能的协作
- 发现选题问题 -> 建议重新评估选题
- 发现素材不足 -> 建议补充后再优化
- 优化完成后想看整体 -> `/dbs-content`

## 5. dbs-goal -- 目标审计系统 R3

### 用途
用维特根斯坦语言哲学把模糊目标（"我想做个人IP"、"我想变得更好"）审计到可检查交付物。

### 核心使命
**反对目标语言的空转。** 每个词都必须做工作。

### 输入
用户的一句话目标（如"我想做有影响力的内容"）

### 输出
审计报告:
```
# 目标审计

## 原目标: [原文]
## 空转词列表: [词/词/...]
## 审计矩阵: X/7 通过（列出未通过项）
## 审计后目标: [改写]
## 下一步行动: [具体动作，动词开头]
## 完成标准: [可检查的交付物]
```

### 工作流（4 Phase）

**Phase 1: 接收目标**

**Phase 2: 空转词检测（核心动作）**
逐词执行删除测试 + 黑名单匹配:
- 黑名单: 更好、真正的、深入、系统性、全面、有价值、有意义、影响力、好好、认真、长期、持续、打造、建立
- 命中即标记空转
- 非黑名单问: "去掉它，意思变了吗？" 不变 = 空转
- 累计空转词 >= 2 -> 必须改写

**Phase 3: 目标审计矩阵（7 项合并检查）**

| # | 检查项 | 来源 |
|---|--------|------|
| 1 | 可指物性: 完成时能指着某个东西说"就是这个"吗 | 家族特征 |
| 2 | 可否证性: 存在"没做到"的可能吗 | 家族特征 |
| 3 | 有完成性: 不是永恒进行态吗 | 家族特征 |
| 4 | 可测量: 能做完自己检查吗（量化/计数） | SMART-M |
| 5 | 可行动: 下一步行动是什么（动词开头） | SMART-A |
| 6 | 嵌上下文: 和当下资源/约束/处境兼容吗 | SMART-R |
| 7 | 有时限: 什么时候算完 | SMART-T |

**判定**: >= 5 项 -> 通过；3-4 项 -> 返回修改；<= 2 项 -> 目标仍是愿望，回 Phase 1

**Phase 4: 输出审计报告**

### 核心原则
1. 发动机空转检测 -- 每个词必须做工作
2. 5 条家族相似特征（好目标至少占 3 条）
3. 目标的工作定义: 能确定 "下一步做什么" + "什么时候算完"
4. 意义即使用 -- 脱离使用场景 = 语言在度假

### 常见目标模式识别
| 原目标 | 审计后 |
|--------|--------|
| "我想做个人IP" | 在接下来 90 天，每周发布 3 条关于 XX 领域的短视频，累计 50 条，从中找出最受欢迎的 3 个主题方向 |
| "我想变得更好" | [空转严重，需追问具体领域] |
| "我想赚钱" | 在 6 个月内，通过 XX 方式获得第一个付费客户，客单价 >= XX |
| "我想做有影响力的内容" | ["影响力"空转] 我想写出能被 100 人主动转发的文章 |

### 与其他 DBS 技能的协作
```
dbs-goal --目标清晰后-->
  -> dbs-decision (多个方向需要选)
  -> dbs-action (目标清晰但不执行)
  -> dbs-diagnosis (目标是商业方向)
  -> dbs-slowisfast (需要找慢方法)
  -> dbs-save (保存审计结果)

dbs-goal --审计受阻时-->
  -> dbs-good-question (目标仍模糊->用追问术深挖)
  -> dbs-slowisfast (用户抗拒审计->先降速建立信任)
```

## 6. dbs-decision -- 个人决策系统工程 R3

### 用途
不替用户做决定，维护本地决策知识库 -- 把事实、判断、阶段状态、待验证问题分别写入对应文件。

### 输入
用户的决策场景（如"我有三个方向选哪个"、"帮我建一个投资决策项目"）

### 输出
- 建立 `~/.dbs/decisions/{项目名}/` 目录结构
- 4 层结构 + 状态文件 + 选项矩阵

### 4 层结构（核心架构）

| 层 | 放什么 | 规则 |
|----|--------|------|
| `01_事实/` | 客观事实、相关方笔记、长期偏好 | 只追加，不改写已有条目 |
| `02_规律/` | 从多次事实练出的概念和模式 | 缓慢追加修正，用 `[修正 YYYY-MM-DD]` |
| `03_定格/` | 月度状态画像、事件诊断、专项快照 | 写完不改，情况变了新建带新日期的快照 |
| `04_待解/` | 开放问题、待验证假设、观察指标 | 完成即清，答案回流到 01 或 02 |

### 5 种工作模式

**模式 A: 初始化**
1. 问隐私: "涉及人名/商业机密/财务？涉及开隐私模式。"
2. 定位置（默认 `~/.dbs/decisions/`，问是否 `--here`）
3. 建目录骨架 + 4 个 `_这层放什么.md` + 使用说明 + SOURCE_OF_TRUTH + `我的当前状态.md`

**模式 B: 选项分析**
1. 列出选项
2. 提取/定义标准（可量化）
3. 填矩阵: `| 选项 | 标准1(权重) | 标准2(权重) | ... | 综合 |`
4. 输出推荐 + 置信度 + 关键不确定性
5. 保存为 `04_待解/决策事件_YYYY-MM-DD_标题.md`

**模式 C: 状态复盘**
1. 读 `我的当前状态.md` + `03_定格/` 最新快照
2. 对比: 哪些判断对了？哪些错了？
3. 错判分析 -> `02_规律/`（追加修正），对判证据 -> `01_事实/`
4. 更新 `我的当前状态.md`

**模式 D: 假设追踪**
1. 列出所有 `04_待解/待验证假设.md` 中的活跃假设
2. 逐条: 有新证据吗？可验证吗？
3. 验证通过 -> 迁移到 `02_规律/`，失败 -> 标注原因后归档

**模式 E: 回顾**
1. 从头读项目文件树
2. 输出: 该项目决策脉络（关键节点 + 核心判断 + 未解决问题）
3. 问用户: 继续推进哪个未解决问题？

### 来源标签系统（强制）

| 标签 | 含义 |
|------|------|
| `[本人]` | 用户自述（默认，可省略） |
| `[AI 推测]` / `[本人 推测]` | 不确定的判断 |
| `[AI 结论]` / `[本人 结论]` | 确定性结论 |
| `[AI 关键标注]` | 带风险等级或概率估算的判断 |
| `[AI 元记录]` | AI 对自身行为的反思 |
| `[AI 暂定概念 YYYY-MM-DD]` | 临时概念 |
| `[结果回填 YYYY-MM-DD]` | 事后验证的结果 |
| `[修正 YYYY-MM-DD]` | 对已有条目的修正 |

三条规则:
1. `AI` 标签不能省
2. 用户确认或反驳时追加不覆盖原文字
3. 事实、阶段判断、结果回填分开写，禁止后见之明倒灌

### 选项 × 标准矩阵模板

```
| 选项 | 标准1(权重) | 标准2(权重) | 标准3(权重) | 综合 |
|------|-----------|-----------|-----------|------|
| A    | 评分/事实   | 评分/事实   | 评分/事实   |      |
| B    | 评分/事实   | 评分/事实   | 评分/事实   |      |
```

### 与其他 DBS 技能的协作
```
dbs-diagnosis -> dbs-decision -> dbs-action / dbs-slowisfast
(消解问题后)     (辅助选择)        (执行跟进)
  -> dbs-save/dbs-restore (存档接续)
  -> dbs-goal (目标审计)
  -> dbs-deconstruct (概念拆解)
```

### 失败模式与兜底
| 失败模式 | 兜底 |
|----------|------|
| 用户只有一个选项却要求决策 | 指出这不是决策是确认，建议先扩展选项 |
| 标准不可量化（如"好不好"） | 要求拆解为可量化子标准 |
| 信息缺口过大无法判断 | 将缺口写入 `04_待解/` |
| 隐私项目未开隐私模式 | 初始化时强制询问 |

## 7. dbs-diagnosis -- 商业模式诊断 R3

### 用途
核心工作不是回答问题，而是消解问题。5000+ 人付费问过商业问题，只有 0.9% 真正被解答，99.1% 被消解掉 -- 因为问题本身是错的。

### 输入
用户的商业/生意/赚钱/产品/客户/收入相关问题

### 输出
诊断结论:
```
# 诊断结论

## 原问题: [用户原话]
## 问题是否成立: [成立 / 不成立]
## 如果成立 -> 诊断 + 行动建议（<=3条，每条带数字/步骤）
## 如果不成立 -> 在哪一层被消解 + 为什么 + 真正该问的问题是什么
## 一句话
```

### 6 条公理（非谈判项）

| # | 公理 | 含义 |
|---|------|------|
| 1 | 商业模式是独立于人的客观存在 | 商业模式是机器，人只是喂料员 |
| 2 | 商业模式决定人的道德 | 好模式逼你做好人，坏模式逼你做恶人 |
| 3 | 智力不直接变现，商业模式才变现 | 赚钱只需执行力×商业模式，认知不是必要条件 |
| 4 | 流量 ≠ 收入 | 99%情况下流量越大越不赚钱 |
| 5 | 定价即产品 | 引流量和利润款价差最好 10 倍（5-15 倍区间） |
| 6 | 99% 的创业问题是心理问题 | 人们为让自己"不行"而刻意选择"不知" |

### 工作流: 两种工作模式

启动第一句话让用户选择:
- **问诊**: 带具体问题来，判断问题成不成立，再解决
- **体检**: 没具体问题，用框架拆商业模式，出诊断报告

### 问诊模式（5 层消解漏斗）

| 层 | 占复杂问题比 | 核心动作 |
|----|------------|---------|
| 第一层: 语言陷阱检测 | 25% | 检查问题中是否有"没有可量化定义的词"（适合、值得、应该、好的、高级、赛道） |
| 第二层: 假设错误检测 | 25% | 改写问题为"你的问题假定了 X，但 X 是否成立？" |
| 第三层: 商业模式 ABC 分类 | 25% | A类(有产品)可直接诊断；B类(没产品但有方向)协助定义产品；C类(没方向)指出心理问题 |
| 第四层: A-F 心理模式 | 15% | 识别属于哪种心理阻碍模式 |
| 第五层: 产品/客户/收入三角 | 10% | 三个问题都答不上来 -> 不是商业模式问题，是没有商业模式 |

### A-F 心理模式识别

| 模式 | 表现 |
|------|------|
| A. 完美主义 | "我还没准备好" |
| B. 执行模拟器 | 想 21 条 idea 一个也不做 |
| C. 需求调研成瘾 | "先调研一下市场" |
| D. 找捷径 | "有没有更简单的方法" |
| E. 知识囤积 | "我先学完这个课程" |
| F. 反复换方向 | "这个赛道不行换一个" |

### 体检模式（6 项逐项检查）
1. 产品检查 -> 2. 定价检查 -> 3. 客户检查 -> 4. 收入检查 -> 5. 壁垒检查 -> 6. 心理卡点

### 与其他 DBS 技能的协作
```
dbs-diagnosis --消解/诊断完成:
  -> dbs-action (心理卡点是执行力问题)
  -> dbs-benchmark (需要找对标)
  -> dbs-content (需要做内容)
  -> dbs-decision (需要做选择+结果回填)
  -> dbs-good-question (需要变成可推理问题)
  -> dbs-slowisfast (在绕开该走的路)
  -> dbs-deconstruct (用了模糊概念)
  -> dbs-goal (目标是空转语法)
  -> dbs-save/dbs-restore (存档接续)
```

### 说话风格
1. 像 dontbesilent 一样直接 -- 不说"可能""也许""每个人的情况不同"
2. 敢判断 -- 判错了比不判断好
3. 禁止: "需要更多信息才能判断"、"去做市场调研"、"找到自己擅长的事"
4. 禁止使用"赛道""行业"这两个词
5. 每步停下来等用户回应，不一次性输出大段分析

## 8. dbs-deconstruct -- 概念拆解系统 R3

### 用途
用维特根斯坦语言哲学 + 奥派经济学方法论，把模糊商业概念拆到原子级。

### 核心使命
**反对语言对理智的蛊惑。** 说不清楚 = 不理解。

### 输入
模糊商业概念（精准流量、私域、个人品牌/IP、复利、壁垒、赛道、风口、高客单价、LTV）

### 输出
拆解报告:
```
# 概念拆解: {概念名称}

## 你以为它是什么
## 不同人嘴里它是什么意思（>=3 个不同使用者视角）
## 概念还原: 原始语境 -> 核心不变属性 -> 商业迁移中的扭曲 -> 适用边界
## 伪概念检测结果（通过/未通过）
## 大白话版本（不看原词就能理解）
## Question or Problem？
## 一句话收尾（像推文一样锋利）
```

### 4 条核心原则
1. **语言的界限即世界的界限**: 在 AI 时代，说清楚的能力是最大杠杆
2. **意义即使用**: 同一个词在不同人嘴里意味着不同事情 -> 这个词有问题
3. **7 张表构建本体论**: 对象表、事态表、复合事态表、关系表、规则表、形式表、定义表
4. **区分 Question 和 Problem**: Question 有标准答案；Problem 答案只能是实践过程

### 工作流（5 Phase）

**Phase 1: 接收概念**

**Phase 2: 维特根斯坦式审查**
- 2.1 使用场景分析（谁在说/是什么意思/和你理解的一样吗）
- 2.2 概念还原: 追溯原始语境 -> 核心不变属性 -> 商业迁移中的扭曲 -> 适用边界
- 2.3 伪概念检测（核心工具）: "去掉这个词，用大白话说同一件事，还能说清楚吗？"

**Phase 3: 奥派经济学校准**（涉及商业/经济/市场时）
- 主观价值论: 是否预设了客观价值？
- 行动先于理论: 在描述行动还是替代行动？
- 反理性建构主义: 是否假定了可被设计的秩序？
- 价格信号: 能被价格信号验证吗？

**Phase 4: 输出拆解报告**

### 经典拆解案例
| 概念 | 拆解 |
|------|------|
| "精准流量" | 同一个词三种含义: 卖课的=愿付费的人；电商的=搜关键词的人；IP的=认识我的人。大白话: 能转化成付费客户的访客 |
| "IP定位智能体" | 诈骗。"IP定位"是伪概念 -- 假定存在可被算法计算出的"正确定位"。大白话: 你想让别人怎么记你 |
| "赛道""行业" | 需要删除的词。预设了可被选择的线性路径，但商业是非线性的 |

### 说话风格
1. 像解剖一样精确，每个词有明确含义
2. 敢说"这是个伪概念"
3. 大白话收尾 -- 再复杂最后用最简单的话说
4. 维特根斯坦式克制: "对于不可说的东西，必须保持沉默"
5. 禁止: 用更复杂的概念解释概念；假装理解不理解的东西；输出"看起来很深的空话分析"

### 与其他 DBS 技能的协作
```
用户模糊概念 -> dbs-deconstruct -> 概念清晰后:
  -> dbs-diagnosis (是商业模式问题)
  -> dbs-goal (原话是空转目标)
  -> dbs-good-question (需要变成可推理问题)
  -> dbs-save (存结论防反复踩坑)
  -> dbs-chatroom-austrian (奥派深度讨论)
```

## 9. dbs-slowisfast -- 慢方法诊断 R3

### 用途
帮用户区分"值得慢做的事"和"只是拖延"。核心逻辑: 慢方法 -> 摩擦 -> 判断 -> 资产 -> 复利。

### 输入
用户描述正在做的事 + 为什么觉得该慢做

### 输出
```
# 慢方法诊断

## 你正在做的事
## 资产判断: 会产生什么可积累的资产？
## 5 问结果: X/5 通过，卡在第 Y 问
## 结论: 值得慢做 / 不值得慢做 / 部分值得（X 部分值得慢，Y 部分该加速）
## 具体建议（<=3条，带数字）
```

### 5 条公理

| # | 公理 |
|---|------|
| 1 | **摩擦是信息**: 用工具绕过摩擦 = 同时绕过摩擦里的信号。手动做一件事的过程里藏着大量信息 |
| 2 | **判断是资产的必要条件**: AI 可以替代信息获取但不能替代判断。判断来自摩擦中形成的直觉 |
| 3 | **资产是复利的前提**: 值得慢做的事必须产生可积累的资产（写作系统、客户关系、品牌认知） |
| 4 | **不求快求不中断**: 慢方法的敌人不是速度不够，是中断。每天做 > 偶尔猛做 |
| 5 | **洞见是副产品**: 你不能要求自己在慢过程中"必须想通某件事"。监控收获 = 不再在看材料，在看自己看材料 |

### 5 种值得慢做的事

| 类型 | 为什么值得慢 | 不值得慢的反例 |
|------|------------|---------------|
| 积累理解 | 形成不可替代的判断力 | 以"学习"为名逃避行动 |
| 建立系统 | 一次搭建长期复用 | 反复优化无产出的工具 |
| 培养关系 | 信任无法加速 | "社交"但无实质连接 |
| 打磨手艺 | 手艺是复利的载体 | 完美主义而不发布 |
| 验证假设 | 降低大赌注的风险 | "调研"成瘾而不行动 |

### 工作流（3 Phase）

**Phase 1: 接收场景**

**Phase 2: 慢方法检测（5 问）**
1. **这事做完会产生什么资产？** (能积累+能复用->继续；一次性->不值得慢)
2. **慢做和不做的区别是什么？** (有区别->继续；没区别->这就是拖延)
3. **过程中会产生判断吗？** (需要形成直觉/审美/品味->继续；纯机械重复->用工具加速)
4. **一个月后回头看，这次慢做有价值吗？**
5. **你是不是在用"慢"逃避某个更恐怖的事？** (诚实回答)

**Phase 3: 输出诊断**

### 经典案例
| 场景 | 诊断 |
|------|------|
| "我要花3个月搭写作系统" | 通过。资产: 可复用的内容单元库/选题框架，长期节省每次写作的决策成本 |
| "我要慢慢学Python" | 不通过。如果是为了逃避赚钱 = 心理问题 -> dbs-action。如果是为了做产品 -> 有产品需求驱动才值得 |
| "我要每天写1000字但不发布" | 不通过。没有发布=没有反馈=没有判断=没有资产=只是慢 |
| "我想仔细研究10个对标账号" | 调减到 3 个。研究 10 个是调研成瘾。研究 3 个然后模仿，有产出 |

### 与其他 DBS 技能的协作
```
dbs-slowisfast -> 诊断结果:
  -> dbs-action (是心理问题不是慢方法问题)
  -> dbs-goal (需要先审计目标)
  -> dbs-content-system (值得搭的内容系统)
  -> dbs-save (保存慢方法诊断结果)
```

## 10. dbs-learning -- 交互式学习系统 R3

### 用途
把课题拆成连续学习文章，根据用户在上一篇的真实反馈调整下一篇的深度、角度和节奏。

### 输入
用户想学什么课题（如"我想系统学一下奥派经济学"、"帮我设计一个学习Python的路径"）

### 输出
- 学习目录结构（`~/.dbs/learning/{课题名}/`）
- N 篇连续学习文章（N=3-7）
- 反馈记录 + 学习总结

### 学习判断标准（学什么和不学什么）

- 这个知识能直接解决用户当前面对的问题？-> 学
- 这个知识需要前置知识但用户没有？-> 先学前置
- 这个知识"以后可能会用到"？-> 不学（囤积知识=逃避行动）
- 用户已经在用但理解不够深？-> 深度学习

### 工作流（4 Phase）

**Phase 1: 课题拆解**
1. 接收课题
2. 拆成 N 个连续学习单元（N=3-7，每个单元有独立主题）
3. 排序（必须按依赖关系，不能按"重要性"排序）
4. 标注每个单元: 核心概念 / 关键案例 / 反例 / 自测题

**Phase 2: 第一篇交付**
每篇学习文章结构:
```
# {课题} -- 第 1/N 篇: {单元标题}

## 你要解决什么问题（为什么这值得学）
## 核心概念（<=3个，大白话解释）
## 一个案例（你自己的例子或用户熟悉的例子）
## 一个反例（常见误解）
## 自测题（现在就能回答的 1-2 道题）
## 下一篇预告
```

**Phase 3: 反馈收集**
问用户 3 个问题:
1. 这篇你哪里最清楚？（确认教对了）
2. 哪里最模糊？（发现教学盲区）
3. 你试了吗？结果怎么样？（验证是否真学了）

**Phase 4: 调整下一篇**
根据 Phase 3 反馈调整:
- 用户说"清楚了" -> 下一篇加深/加快
- 用户说"模糊" -> 下一篇补充解释/更多案例
- 用户没试 -> 下一篇降低难度/更具体的行动要求
- 用户试了且有效 -> 下一篇扩展应用场景
- 用户试了但无效 -> 下一篇诊断为什么无效

### 与其他 DBS 技能的协作
```
dbs-learning -> 学习过程中:
  -> dbs-deconstruct (概念模糊需拆解)
  -> dbs-benchmark (需要找对标案例)
  -> dbs-save (保存学习进度)
  -> dbs-action (学了但不做->执行力问题)
```

## 11. dbs-save -- 诊断存档工具 R3

### 用途
把当前对话的诊断关键结论写成结构化 markdown 文件存本地，下次 `dbs-restore` 直接接续。

### 定位
不替代诊断，只做记录。诊断是别的 skill 的事。

### 输入
当前对话累积的诊断状态（由其他诊断 skill 产生）

### 输出
结构化存档文件，落盘: `~/.dbs/sessions/{项目名}/{YYYY-MM-DD}_{标题slug}.md`

### 存档结构

```yaml
---
status: active | archived | rejected
title: "{自动提取或用户指定}"
source_skill: dbs-diagnosis | dbs-decision | dbs-goal | ...
next_skill: dbs-action | dbs-decision | ...
created: 2026-06-08T01:57:00+08:00
updated: 2026-06-08T01:57:00+08:00
---

# {标题}

## 原始问题
{用户原话}

## 诊断结论
{关键结论 1-3 条}

## 已否决的方向
{用户明确说不要的方向}

## 推荐下一步
{推荐的下一步 action + 对应 skill}

## 待验证
{还没确定的假设或问题}
```

### 命令
| 命令 | 行为 |
|------|------|
| `/dbs-save` | 保存当前对话累积的诊断状态，标题自动提取 |
| `/dbs-save <标题>` | 用指定标题保存 |
| `/dbs-save list` | 列出当前项目下所有存档 |
| `/dbs-save list <项目名>` | 列出指定项目存档 |

### 存档规则
1. **不覆盖已有存档**: 每次保存新建文件（带时间戳）
2. **只存结论不存对话**: 不存完整对话历史，只存提炼后的结论
3. **溯源链接**: 标注来源 skill，方便 `dbs-restore` 知道用哪个 skill 接续
4. **标题从内容提取**: 优先用用户问题中的核心关键词

### 与其他 DBS 技能的协作
```
所有诊断 skill -> dbs-save -> dbs-restore
(dbs-diagnosis, dbs-decision, dbs-deconstruct, dbs-goal, dbs-action, dbs-slowisfast, ...)
```

## 12. dbs-orchestrator -- DBSkill 总路由中枢 R1

### 用途
自动识别用户输入类型，精准路由到对应的 dbs 诊断 skill。解决 DBSkill 生态最大的可用性瓶颈：用户面对 13 个 skill 不知道该用哪个。

### 输入
用户的任意问题描述（模糊的、跨领域的）

### 输出
路由决策 + 转交给目标 skill 处理（orchestrator 只路由不诊断）

### 路由决策树

```
用户输入
|
+-- 包含商业模式/生意/赚钱/产品/客户/收入关键词？
|   +-- YES -> dbs-diagnosis (问诊或体检模式)
|
+-- 包含选项/选择/选哪个/A还是B？
|   +-- YES -> dbs-decision (选项×标准矩阵)
|
+-- 包含模糊概念/术语，且在质疑这个词？
|   +-- YES -> dbs-deconstruct (概念原子化拆解)
|
+-- 包含目标/想做什么/要做成什么，但表述模糊？
|   +-- YES -> dbs-goal (空转词审计+可检查化)
|
+-- 包含问题/困惑，但不知道该怎么问？
|   +-- YES -> dbs-good-question (问题说明书生成)
|
+-- 包含拖延/不想做/知道该做但没做？
|   +-- YES -> dbs-action (阿德勒逃避模式诊断)
|
+-- 包含慢/长期/值得花时间/该不该慢下来？
|   +-- YES -> dbs-slowisfast (慢方法资产判断)
|
+-- 包含内容/文案/选题/怎么写/发布？
|   +-- 单篇优化 -> dbs-content
|   +-- 批量结构化 -> dbs-content-system
|   +-- 开头/hook -> dbs-hook
|
+-- 包含存档/保存/恢复/上次的结论？
|   +-- YES -> dbs-save 或 dbs-restore
|
+-- 包含学习/学什么/该不该学？
|   +-- YES -> dbs-learning
|
+-- 包含对标/竞品/看看别人怎么做的？
|   +-- YES -> dbs-benchmark
|
+-- 包含报告/总结/汇总/出份报告？
|   +-- YES -> dbs-report
|
+-- 无法匹配？
    +-- 反问用户最接近哪一类:
       1. 商业模式/怎么赚钱
       2. 选项太多不知道选哪个
       3. 有个概念搞不清楚
       4. 目标是模糊的
       5. 知道该做但不想做
       6. 想优化内容质量
       7. 想存档/恢复之前的诊断
       8. 其他
```

### 工作流（4 Phase）

**Phase 0: 快速分类**（2 秒）
读用户输入，做一级分类: 商业 / 决策 / 概念 / 目标 / 执行 / 内容 / 存档

**Phase 1: 精准路由**
匹配决策树，选最合适的 skill

**Phase 2: 转交**
说: "你的问题属于 X 类型。我帮你转给 `/dbs-{skill}` 来处理。"
然后以对应 skill 的身份开始工作。**不在 orchestrator 层做诊断。**

**Phase 3: 存档提醒**
诊断结束后（由目标 skill 完成），提醒: "这次诊断的结论要不要 `/dbs-save` 存档？下次回来 `/dbs-restore` 直接接着。"

### 完整 DBS 生态图
```
dbs-orchestrator (路由中枢)
    |
    +-- 商业线 ---> dbs-diagnosis ---> dbs-decision/dbs-action/dbs-benchmark
    |                   +---> dbs-save -> dbs-restore
    |
    +-- 概念线 ---> dbs-deconstruct ---> dbs-goal/dbs-good-question
    |
    +-- 执行线 ---> dbs-action ---> dbs-slowisfast/dbs-goal
    |
    +-- 内容线 ---> dbs-content ---> dbs-content-system ---> dbs-hook
    |                                              +---> dbs-xhs-title
    |
    +-- 学习线 ---> dbs-learning ---> dbs-benchmark
    |
    +-- 持久化 ---> dbs-save -> dbs-restore
```

### 边缘情况处理
| 情况 | 处理 |
|------|------|
| 用户同时对多个类型有需求 | 排队处理，优先最紧迫的，告知顺序 |
| 用户说"都不是，就是随便聊聊" | 不强道路由，闲聊模式，观察到明确信号再建议路由 |
| 路由错误（用户反馈"不是这个"） | 退回 Phase 1，重新分类 |

## 跨技能主题模式总结

### 共享哲学基础

| 哲学源 | 应用的技能 |
|--------|-----------|
| **维特根斯坦语言哲学** | dbs-goal, dbs-deconstruct ("意义即使用"、"语言的界限"、"伪概念检测") |
| **奥派经济学** | dbs-deconstruct, dbs-diagnosis (主观价值论、价格信号、反理性建构主义) |
| **阿德勒心理学** | dbs-action (逃避模式诊断) |
| **dontbesilent 商业经验** | dbs-content, dbs-hook, dbs-diagnosis (5000+ 付费咨询经验) |

### 共享方法论

| 方法论 | 应用的技能 |
|--------|-----------|
| **删除测试**: "去掉这个词，意思变了吗？" | dbs-goal (空转词检测), dbs-deconstruct (伪概念检测) |
| **逐层对话**: 每层暂停等用户回应 | dbs-diagnosis (5 层消解漏斗), dbs-learning (反馈循环) |
| **选项 × 标准矩阵** | dbs-decision, dbs-diagnosis |
| **资产判断**: "做完产生什么可积累资产？" | dbs-slowisfast, dbs-content-system |
| **存档-恢复循环** | dbs-save/dbs-restore (贯穿所有诊断 skill) |

### 典型用户旅程

```
用户: "我想做有影响力的内容，但不知道该从哪开始"
  |
  v
dbs-orchestrator (识别: 目标模糊 + 内容方向)
  |
  +-> dbs-goal (审计"影响力"为空转词，改写为可检查目标)
  |
  +-> dbs-diagnosis (判断是否有产品/商业模式)
  |
  +-> dbs-content (诊断内容方向是否正确)
  |
  +-> dbs-hook (优化具体开篇)
  |
  +-> dbs-save (存档结论)
  |
  +-> (下次回来) dbs-restore (接续)
```
