# 05 · 产品 B：DBS 控制台（dbs）· 内容流水线

> 把 `.dbs` 编排层 + `05-内容生产/内容体系/` 工程层的手工流程软件化。目前状态散落在 markdown 表格与 YAML 里、靠 PowerShell 脚本推动——这是全知识库最值得软件化、也最高频的一条动线。

## 一、定位与对标

- 一句话：**一人内容公司的心脏控制台**——选题、装配、质检、发布、数据、反哺六段闭环在一块看板上转完。
- 对标：Linear（状态机 + 键盘优先）、Substack Stats（数据舱）、Buffer（发布节奏）。
- Windows 为主力端（渲染管线在 Windows）；安卓端只做速记与数据录入。

## 二、六段流水线 → 六个功能域

### 2.1 选题池（含真实性准入）
- 闪念捕获（桌面 `Ctrl+K` / 安卓速记）→ 池中。
- 认领前强制通过**选题真实性准入表**（对齐 `05-内容生产/选题管理/00-选题记录.md` v2.0）：真实问题三验（谁在问 / 在哪问的 / 问过几次）+ 证据等级 + 是否在 5 域 17 主题内（`COG/WTH/SMD/GRW/PRD`）。
- 硬约束：进行中 WIP ≤ 3（软件强制，超出不可认领）；池中 <5 条时首页亮黄条提示补池（对齐 `.dbs/rules/03` 每周节律）。

### 2.2 看板（状态机可视化）
- 选题状态机：`池中 → 已认领 → 装配中 → 已发布 → 已复盘`（+ 放弃/归档）。
- 内容单元状态机：`draft → ready → published → archived`（+ deprecated）。
- 看板列 = 状态机；卡片显示超期角标（draft>7 天、ready>3 天、装配中>5 天，对齐 `.dbs/rules/03` 检查节律）。
- 双轨制显式化：同一选题可挂两条装配线（抖音脚本 / 公众号长文），卡片上双轨道颜色区分。

### 2.3 装配工作台（桌面核心界面）
- 左栏：内容单元库检索（195+ 单元，按主题代码 `COG-DOP` 等过滤，显示质量分级 S/A/B/C 徽章）。
- 右栏：装配稿编辑器 + 顶部模板选择（`05-抖音口播脚本模板` / `06-公众号文章模板`）。
- 装配动作自动写 YAML 元数据与命名规范（`{平台}_{日期}_{主题}_{标题关键词}.md`，对齐 `.dbs/rules/naming-convention.md`）。
- "生成初稿"按钮调 LLM：只允许基于所选单元拼装改写，**禁止无中生有**——生成稿自动标 `ai_derived: true`（B 级），必须人工过一遍才能推进到"待质检"。

### 2.4 质检引擎（faith-humanizer v6.5 内置）
- `packages/humanizer` 把 98 检测模式 + 红线规则表外置为 JSON（来源：`C:\Users\董辉\.agents\skills\faith-humanizer\references/`），规则可升级不动代码。
- 一键质检输出报告：A-K 类常规项逐条命中位置 + 红线布尔门禁（L1-L6 / M1-M4 / N1/N3 / O1-O4 / P1-P2，任一命中 = FAIL）+ 声部检测（A/B/C/D 四声部，500-1500 字自动判别）+ 声部签名与 U1-U12 校准得分。
- "去 AI 味"按钮：audit → replace → verify → calibrate 五遍流程跑完输出修订稿（紫色水印，人工确认后摘牌）。
- 六门禁检查表（对齐 `.dbs/rules/quality-gates.md`）：AI 味零命中 / 深度引用≥3 / 3 个月耐久 / 选题在域内 / 商业化钩子 / 字数线（公众号≥2000 字、抖音≥300 字）。全绿才允许"发布"按钮点亮。

### 2.5 发布执行（复用不重写）
- 公众号：内联样式 HTML 生成 + 配图提示词 → 调用现有 `new-wechat.ps1`；抖音：HyperFrames 渲染 → 调用现有 `new-douyin.ps1`（Tauri shell 执行，输出流式回显在控制台）。
- 发布成功自动追加 `05-内容生产/运营与发布/数据/数据统计表.csv`（脚本已含此逻辑，软件只做触发与校验），实际发布稿归档到 `运营与发布/已发布/`。
- 发布完成页 = 品牌瞬间（AQUA 唯一仪式动效）：流水线六段图标依次点亮。

### 2.6 数据舱（反哺闭环）
- T+1 / T+3 / T+7 录入提醒（对齐 `.dbs/rules/05-数据记录规范.md`）：到点未录的条目在数据舱置顶。
- 录入字段按实际 CSV 13 列中文口径（`发布日期,平台,内容标题,章节来源,阅读量,点赞,在看,评论,转发,收藏,新增关注,转化动作,备注`）；抖音另计完播率。**软件内统一为英文 schema 存储、导出时转中文 CSV**，一次性解决现有"中文实际表 vs 英文规范表"口径分裂。
- 曲线：单篇生命周期曲线（T+0..T+14）+ 平台周趋势；指标纪律：绿只给"完成"，增长数据一律中性蓝（防数据情绪化）。
- 自动周报：接管 `weekly-report.ps1`，六格复盘 + Top/Bottom 分析，输出到 `04-知识/方法论/周报/`。
- 反哺提示：单篇 T+7 数据进入同主题 Top 20% → 提示"跨平台扩展"；Bottom 20% → 提示"方向调整"并在选题池标记该主题降温（对齐 `.dbs/assembly/_pipeline-status.md` 反哺规则）。

## 三、信息架构

### 3.1 Windows
- 左侧栏：看板 / 选题池 / 装配 / 质检 / 数据舱 / 设置。
- 看板：全宽 6 列状态机，`J/K` 移卡、`Enter` 进详情、卡片拖拽改状态并写变更日志。
- 装配工作台：三栏（单元库 / 编辑器 / 质检侧板），编辑器 720px 阅读宽度。
- 数据舱：上（待录队列）+ 中（曲线区，`Ctrl+滚轮` 缩放）+ 下（周报生成与归档入口）。

### 3.2 安卓（6.74 英寸，360×800dp）
- 两屏即可：①速记（打开即输入框，一句话落池，附主题快捷标签 17 主题横滑）②数据录入（到期列表逐条表单，数字键盘优化）。
- 看板只读视图（第三 Tab），供发布后随时瞄一眼状态。

## 四、数据模型（表前缀 `dbs_`）

```
dbs_topic        选题：content, three_checks(三验json), evidence_level, domain, topic_code, status, wip_slot
dbs_assembly     装配线：topic_id, platform(douyin/wechat), template, status, file_path
dbs_unit_link    装配稿↔内容单元引用（保证"检索复用已有证据"闭环可审计）
dbs_qc_report    质检：assembly_id, gates(json 六门禁), redline_fails(json), voice, signature_score, passed
dbs_publish      发布：assembly_id, published_at, csv_row_id, archive_path
dbs_metrics      数据：publish_id, t_offset(1/3/7...), reads, likes, comments, shares, saves, new_followers, completion_rate, conversion, note
dbs_feedback     反哺：metric_snapshot → action(扩展/降温/调整), applied_to_topic_id
dbs_llm_usage    继承统一账本
```

## 五、LLM 能力

| 能力 | 说明 | 约束 |
|---|---|---|
| 标题工厂 | 按声部生成 10 个候选 + 自动过 N 类红线（冒号前≤5 字、禁"如何"开头等） | 命中红线的候选直接不显示 |
| Hook 生成 | 抖音口播前 3 秒候选 | 必须引用单元库真实内容 |
| Humanizer 修订 | 五遍流程 | 修订稿标 B 级待人工确认 |
| 门禁解释 | 点门禁项显示"为什么这条不过 + 原文出处" | 只解释，不改稿 |
| 数据周解读 | 周报里加一段模型解读 | 只描述模式，禁止预测爆款 |

## 六、v0.1 边界（M3-M4 交付）

做：选题池+准入表、看板双状态机、装配工作台（抖音+公众号双模板）、humanizer 引擎（红线+98 模式）、双脚本调用、CSV 自动追加、T+1/3/7 录入与曲线。
不做：批量渲染 UI 化（继续用 `batch-render.ps1`）、小红书/B 站新平台（17 主题内的扩展平台等有真实发布再接）、自动发布（发布动作永远人工确认）。

## 七、完成标准

- M3：1 篇稿件在软件内走完 池中→发布 全流程，CSV 与归档路径正确。
- M4：连续 2 周数据完整度 100%（T+1/3/7 零漏录）；周报自动生成并被实际用于选题决策。
