# 06 · 产品 C：Cortex（cortex）· 第二大脑终端

> 把"捕获 → 分流 → 提炼 → 复用"的知识闭环做成常驻终端。Cortex 不替代 Obsidian，替代的是"打开文件管理器找文件"和"忘了库里有没有"这两件事。

## 一、定位与对标

- 一句话：**全局呼出、三秒命中**——检索、捕获、巡检、回顾四件事在 3 秒内完成。
- 对标：Raycast（呼出式交互标杆）、Obsidian（本体的补充而非竞争）、Rewind（被动回顾的主动化）。
- 启动前置：**先用 Obsidian + ZCode 手工跑 2 周**检索/捕获日志，确认高频真实需求（阶级跃迁原则：先手工验证再写产品），本规格才允许开工。

## 二、四个功能域

### 2.1 呼出面板（Raycast 式，Windows 核心体验）
- `Ctrl+Space`（可配置）全局呼出，屏幕上 1/3 居中毛玻璃面板（AQUA 命令面板规格），Esc 逐层退出。
- 输入即检索，结果分区显示：**文件 / 深度卡 / 内容单元 / 选题 / 历史捕获**，每条带路径与质量分级徽章（S/A/B/C，来自 YAML `evidence_level`）。
- `↑↓` 选择、`Enter` 打开（默认 Obsidian URI 或资源管理器）、`Ctrl+Enter` 复制路径、`Tab` 预览。

### 2.2 快速捕获
- 呼出面板输入 `cap ` 前缀或独立快捷键 → 一句话 + 自动打标（LLM 按 5 域 17 主题代码建议标签，用户一键确认/改）。
- 落点：`00-收件箱/` 单文件，YAML 含 `{status: inbox, created, domain, source: cortex}`，对齐收件箱分流规则（7 天内分流）。
- 安卓端：速记落本地库，回到同 Wi-Fi 自动同步进收件箱。

### 2.3 知识库问答（RAG）
- 面板输入 `ask ` 前缀进入问答模式："我的知识库怎么说 X？"
- 检索：v0 用 SQLite FTS5 全文索引（中文按 jieba 分词预索引，索引文件存 `99-系统/元数据/` 侧）；v1 叠加向量检索（embedding 走 LLM 设置里的供应商）。
- 回答硬约束（对齐 `SOURCE_OF_TRUTH` 冲突规则）：
  - 每个断言必须挂引用（可点击跳转原文件行）；
  - 引用徽章显示质量分级，B/C 级来源自动加"未确认"角标；
  - 库里没有 → 只说"库里没有"，**禁止用模型常识补答案**（可手动切换"联网脑补模式"，默认关）。
- 问答历史落库，可一键把优质问答转成捕获卡片进收件箱（提炼闭环的入口）。

### 2.4 巡检（防熵引擎）
- 每日静默巡检，发现项在面板顶部显灰条，一键修复：
  - 收件箱超 7 天未分流（对齐 AGENTS 规则）；
  - 断链/坏链扫描（md 相对链接）；
  - 状态超期：draft>7 天、ready>3 天、装配中>5 天（对齐 `.dbs/rules/03`）；
  - 缓冲区堆积：各 `00-缓冲区/` 超 30 天文件清单；
  - MOC 漂移：新增文件未进自动索引（触发 `99-系统/脚本/rebuild_mocs.ps1`）。
- 巡检只报告与触发既有脚本，**不自动移动/修改任何知识库文件**（对齐"90-归档默认只读"与防熵规则的人工确认精神）。

### 2.5 每日回顾（安卓与桌面）
- 从深度卡库按遗忘曲线轮换 3 张卡（间隔重复参数可调）；
- 与知行联动：复盘页可引用"今天写过的卡"；与 DBS 联动：装配工作台可"从回顾卡生成素材候选"。

## 三、信息架构

### 3.1 Windows
- 主形态是呼出面板（无常驻主窗口；设置与巡检报告从面板进入一个轻量窗口）。
- 面板页序：搜索 → 问答 → 巡检 → 设置。托盘常驻，开机自启（内存占用预算 <150MB）。

### 3.2 安卓（6.74 英寸，360×800dp）
- 两屏：①速记捕获（大输入框 + 标签横滑）②今日回顾卡（卡片翻面动效是唯一允许的玩具感）。
- 不做移动端全库检索（索引在桌面）。

## 四、数据模型（表前缀 `cortex_`）

```
cortex_index      FTS5 虚表：path, title, body, evidence_level, domain, updated_at
cortex_capture    捕获：text, tags(json), inbox_path, synced(bool), created_at
cortex_qa_log     问答：question, answer, citations(json: path+offset+level), created_at
cortex_review     回顾：card_path, due_date, interval, ease, history(json)
cortex_patrol     巡检：kind(断链/超期/堆积/漂移), target_path, detail, fixed_at
cortex_llm_usage  继承统一账本
```

## 五、LLM 能力

| 能力 | 说明 | 约束 |
|---|---|---|
| 捕获自动打标 | 建议 17 主题代码 + 证据等级初判 | 建议≠决定，用户确认后落库 |
| RAG 问答 | FTS(→向量) 检索 + 带引用回答 | 无引用不输出；B/C 级来源强制角标 |
| 卡片建议 | 从问答/捕获提炼"可收进 04-知识 的原子笔记候选" | 产物一律 B 级进缓冲区，转正需人工 |

## 六、v0.1 边界（M5 交付）

做：呼出面板 + FTS 全库检索 + 快速捕获 + 巡检四类 + 安卓速记与回顾。
不做：向量检索（v1）、自动写回知识库正文、Obsidian 插件化、多库支持（只认 `D:\KnowledgeBase`）。

## 七、完成标准

- 前置：2 周手工验证期产出至少 20 条真实检索/捕获记录，证明需求成立。
- M5：连续 7 天每天至少 1 次真实命中；巡检发现项人工确认修复率 ≥80%。
