# 01 · 产品组合总览与路线图

## 一、设计总纲：把已写成的操作系统编译成软件

知识库里真正稀缺的不是新方法论，而是已经写成、却仍靠意志力手工运行的系统。本产品线的总纲只有一句话：

> **凡在书里成系统的，就在软件里自运行；凡软件能闭环的，就不留给意志力。**

三件产品各编译一条已经存在的闭环，而不是发明新闭环：

| 产品 | 编译的闭环 | 闭环在知识库中的原文载体 |
|---|---|---|
| 知行 | 人生操作闭环：默认 → 脚本 → 能量 → 纠错 → 自更新 | 《人生操作系统 v2》（意志力不是杠杆） |
| DBS 控制台 | 内容生产闭环：选题 → 装配 → 质检 → 发布 → 数据 → 反哺 | `.dbs/` 全套规则 + faith-humanizer v6.5 |
| Cortex | 知识闭环：捕获 → 分流 → 提炼 → 复用 | 本知识库目录规则 + 质量分级 S/A/B/C |

每件产品都必须通过同一个准入测试（源自阶级跃迁路线图的"减少自嗨式开发"原则）：

- **知行**：手工流程已在《人生操作系统 v2》中运行过、且 v2 全书本身就是流程验证 → 可建。
- **DBS 控制台**：`.dbs` 已有 PowerShell/Node 脚本与真实队列文件 → 可建。
- **Cortex**：尚无手工验证的自动化流程 → 排最后，先用 Obsidian + ZCode 手工跑 2 周确认需求，再动工。

## 二、为什么是三件，而不是五件或十件

1. `01-项目/README.md` 规定 WIP 上限 3，这是硬约束。
2. 《人生操作系统 v2》自己的话："一个不愿删除的系统，最后会变成一个不愿行动的系统。" 决策簿、跃迁仪表盘这类常见独立 App，全部作为模块并入知行——少一个 App，多一分长期维护概率。
3. 三件产品覆盖三条最高频动线：**每天怎么活（知行）、每天怎么赚（DBS）、每天怎么想（Cortex）**。

## 四、全产品第一性原则

这三条凌驾于所有功能设计之上，任何新功能提案若与之冲突，默认拒绝：

1. **软件拉人回现实，不替人逃避现实。** 所有 LLM 能力只做教练、审计、检索，不代写人生、不生成情绪价值表演。
2. **记录来自真实，指标不可刷。** 沿用可撤回进展循环的"不可刷指标"思想：能被连续打卡刷出来的指标不进首页；"回来的速度"才是指标。
3. **LLM 只引用用户的记录。** 教练类功能的上下文只允许来自本机数据库与本知识库，禁止模型自由发挥个人评价。

## 七、明确不做的事（删除也是更新）

- 不做云服务、账号系统、多人协作、公开分享页（私有化是产品，不是缺陷）。
- 不做连续天数打卡、金钱惩罚、摄像监督、公开处刑（调研已明确否定）。
- 不做"远期资本目标"字段——1 亿不进入任何待办（阶级跃迁原文）。
- 不重写渲染管线与公众号 HTML 排版（PowerShell 已验证，调用即可）。
- 不做通知轰炸；每日主动通知不超过 1 条（晚间复盘）。
- 首版不做跨设备实时同步（桌面为主库，安卓速记走局域网/导出，v1 再议）。
