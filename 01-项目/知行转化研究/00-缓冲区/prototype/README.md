# 下一次证据原型

## 打开

直接打开 `index.html`。原型使用普通脚本而非模块加载，因此 `file://` 场景可运行，不需要开发服务器、安装依赖或联网。

数据保存在浏览器本地存储接口（`localStorage`）的 `next-evidence:v1` 键。换浏览器或清理站点数据前，先在页面导出 JSON 数据文件。

## 测试

在本目录或知识库根目录运行：

```powershell
node --test ".\tests.mjs"
```

当前 29 条规则与协议测试覆盖合同版本与状态时间线、当前版本证据完成率、无机会分母与客观原因、证据布尔类型、风险快照一致性、每日 20 分钟、退出终态、非法导入后数据保留、诊断建议适配、备份往返、未知字段拒绝、UI 状态不进入 v1 备份、工作区矩阵、账本筛选和清空。

## 当前交互

- 有序进度轨配合单任务工作区；页面同时只呈现一个工作区和一个主操作，未满足前置条件的步骤不可进入。
- 合同按活动证据、边界指标、决策预览三段填写，错误关联具体字段。
- 390px 及以下账本使用纵向记录；当前版本与全部历史明确切换。
- 数据操作进入工具菜单，清空在危险分组中隔离。
- 合同锁定前显示可复述预览；历史显示字段差异和可用的修订依据。
- “无机会”即时说明分母语义，`0 / 0` 明确不解释为失败。
- “无机会”必须填写客观原因；当前版本的完成率与无机会数不混入旧版本记录。
- 七种下一决定分别提示要记录的事实，退出写入前需要二次确认。
- 备份先验证并预览，第二次确认才替换；错误留在导入对话框内。
- 损坏的本地数据先隔离并阻断写入，可下载原始文本或明确弃用。
- 另一标签页改写同一数据后，本页阻断提交、导入、清空和恢复弃用，避免静默覆盖。

## 文件

- `index.html`：语义结构和所有交互控件。
- `styles.css`：桌面与移动端布局，无外部字体或图标请求。
- `logic.js`：可在浏览器和 Node.js 运行环境中执行的纯数据逻辑。
- `ui-state.js`：只管理当前工作区、合同阶段和账本筛选，不进入备份。
- `app.js`：文档对象模型、本地存储、文件导入导出和状态呈现。
- `tests.mjs`：使用 Node.js 内置测试能力，无第三方依赖。

## 自有备份数据格式

自有备份的顶层结构如下：

```json
{
  "app": "next-evidence",
  "schemaVersion": 1,
  "createdAt": "2026-07-12T08:00:00.000Z",
  "updatedAt": "2026-07-12T08:00:00.000Z",
  "goal": null,
  "contracts": [],
  "observations": []
}
```

导入会完整校验引用、连续版本时间线、目标与合同风险快照、证据布尔类型、无机会原因、退出终态、指标、机会状态和每日分钟。任何错误都会拒绝整个导入，并返回导入前状态。有效备份也必须经过预览和第二次确认才会替换本地数据。

## 诊断 JSON 数据适配

当前诊断工具的主动导出结构如下。适配器只读取 `draft.goal` 和
`assessment.routeCopy.instruction`；不会读取 `draft.context`、`draft.answers`
或 `assessment.findings`。

```json
{
  "schemaVersion": "1.0",
  "draft": {
    "schemaVersion": "1.0",
    "goal": "完成一次低风险用户访谈",
    "context": "不会导入",
    "answers": {}
  },
  "assessment": {
    "schemaVersion": "1.0",
    "currentRoute": "measurement_first",
    "canContinue": true,
    "routeCopy": {
      "instruction": "先定义一个能区分两种结果的观察。"
    },
    "findings": []
  }
}
```

导入只会把建议放进尚未提交的目标表单。用户必须人工确认；已有目标不会被覆盖，成因标签和诊断措辞不会进入产品数据。
若 `assessment.currentRoute` 为 `urgent_support` 或 `canContinue` 为 `false`，
导入会拒绝预填生产力目标，只显示诊断工具提供的安全支持提示，现有数据保持不变。

## 损坏数据恢复

若启动时 `next-evidence:v1` 无法通过校验，页面保留原始文本、显示恢复面板并暂停新写入。用户可以下载 `.txt` 恢复快照，再明确弃用；该快照可能无效，只用于人工恢复，不应直接重新导入。

## 数据清除

页面的“清空”在确认后移除本地存储，并清空目标、合同与观察。该操作不可撤销；需要留存时先导出 JSON 数据文件。

## 安全边界

高风险（`high`）和安全关键（`safety-critical`）目标不能锁定直接接触（`direct`）合同。该规则同时存在于界面和 `logic.js`，导入的备份也必须通过同一验证。原型不替代医疗、法律、财务或其他专业判断。
