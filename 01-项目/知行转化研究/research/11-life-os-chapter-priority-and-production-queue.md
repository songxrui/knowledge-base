# 《人生操作系统》章节优先级与无人干预生产队列

> 版本：2026-07-17
> 适用范围：元系统章完成后的 13 个剩余章节。
> 说明：排序是生产决策，不是对章节价值的客观排名。

## 1. 为什么下一步先做健康章

同时并行处理 13 章会快速制造 13 份风格相似、证据边界不同的半成品。更稳妥的顺序是先用最高伤害风险的健康章验证模板，再依次扩展。健康章包含医学建议、机制解释、名人故事和大量精确数字；一旦写错，影响不只是可信度，还可能改变读者的睡眠、饮食和运动行为。它也能复用元系统章已经核过的循环叹气与表达性写作来源，因此最适合作为第二个样板。

## 2. 评分模型

每项 1-5 分，总分越高越先处理。

| 维度 | 权重 | 5 分含义 |
|---|---:|---|
| 错误伤害 | 30% | 错误可能导致健康、财务或重大人生损失 |
| 风险密度 | 25% | 精确数字、因果机制、名人故事和强结论密集 |
| 产品核心度 | 20% | 是长期内容产品和社群交付的核心模块 |
| 核验可行性 | 15% | 有较多一手研究、指南或原作者材料可定位 |
| 证据复用 | 10% | 可复用现有台账、来源和框架 |

加权总分 = 错误伤害×0.30 + 风险密度×0.25 + 产品核心度×0.20 + 核验可行性×0.15 + 证据复用×0.10。评分用于排队，不伪装成统计测量。

## 4. 单章无人干预 SOP

### Stage 0：基线锁定

1. 记录原稿路径、字节、字符、行数和 SHA-256。
2. 提取标题结构、数字句、引语、人物故事、机构、书籍、论文和因果词。
3. 设派生稿最低字符门槛为原稿 90%，并登记必须保留的功能结构。
4. 原稿路径加入保护清单，任何哈希变化立即停止。

### Stage 1：主张拆分

1. 一行只登记一个可判断主张，禁止把人物、数字、机制和结论捆在同一 claim。
2. 为每条主张登记身份：研究支持、官方指南、作者方法、历史描述、编辑推断、实验参数、个人事实、库存快照或阻断。
3. 优先处理医学、财务、法律、精确数字、因果机制和名人故事。
4. 无来源不等于错误，但无来源的精确事实不得进入证据版正文。

### Stage 2：证据检索

1. 优先原始论文、系统综述、官方指南、作者原文和机构档案。
2. 每个来源记录样本、任务、设计、结果、局限及“不支持什么”。
3. 观察性研究只写关联；动物研究必须写物种；短期实验不得外推终身结果。
4. 来源之间冲突时保留冲突，不用多数票制造确定性。

### Stage 3：处理决定

- `keep`：主张身份和来源匹配，可直接保留。
- `qualify`：缩小对象、任务、时间或因果强度后保留。
- `parameterize`：改为可撤回的首轮参数，记录指标和停止条件。
- `remove`：与主论点无关、造成伪精确或增加认知负担。
- `block`：撤稿、错配、虚构、未定位或伤害风险不可接受。

### Stage 4：派生重写

1. 先写读者真实问题，再写证据边界，不以名人故事充当证明。
2. 每个数字附近放 claim 标识；每个操作协议说明它是指南还是作者参数。
3. 保留原章的任务功能，删除无法承担结论的装饰性证据。
4. 不编造作者经历、用户案例、后台数据、收入或效果反馈。

### Stage 5：自动终验

1. 原稿哈希一致。
2. 台账 claim ID 唯一、来源 ID 可解析、决定值合法、边界字段非空。
3. 派生稿所有含数字正文段落都带 claim；blocked 来源命中为 0。
4. 医疗章必须有就医边界；财务章必须有适用边界；AI 章必须有核验日期。
5. 字符、标题结构、引用、UTF-8、链接、绝对路径、秘密模式和 `git diff --check` 全部通过。

## 5. 自动停止条件

出现任一条件，该章不得自动进入“完成”：

- 原稿哈希变化；
- 高伤害主张只有二手营销材料；
- 人物故事无法找到一手出处；
- 台账仍有未决的医学、财务或法律处方句；
- 派生稿把观察性关联写成因果；
- 为满足长度门槛重复填充；
- 修复循环超过 3 轮；
- 需要用户提供个人事实，却试图根据旧稿推断。
