# 市面产品形态研究与交互优化

> 调查日期：2026-07-17。事实只采用产品官网、官方帮助中心和官方定价页；产品效果数字若没有独立证据，不用于本项目的效果判断。文中的“分析”与“建议”是本项目推断，不代表相关公司观点。

## 一、结论先行

“下一次证据”不应变成又一个习惯打卡器、待办清单或惩罚型承诺应用。本次调查的七个相邻产品已经分别提供提醒、连续追踪、同伴监督、付费惩罚或人工验收等机制，主要围绕计划、启动、追踪和完成约束。本项目选择回答一个更窄的问题：

> 当一个人已经会学习、规划和设计系统时，怎样判断下一次真实机会有没有出现、有没有留下可回看的活动证据，以及这条证据应当让合同保持、修订、补知识、补资源、修测量、退出还是求助。

因此，当前的本地单页应用形态继续成立。产品的核心差异不是压力更大，而是四件事更可信：

1. 合同版本不可静默覆盖；
2. noOpportunity 不进入证据完成率分母；
3. 高风险、资源不足和反馈不可读不会被误写成“执行失败”；
4. 每次观察必须通向一个明确的下一决定，退出是合法结果。

## 二、研究范围与比较方法

本次选择七个相邻产品，覆盖七种不同机制：

| 产品 | 主要形态 | 主要机制 |
|---|---|---|
| WOOP | 免费应用与纸面练习包 | 固定顺序的愿望、结果、障碍、计划 |
| stickK | 网页承诺合同 | 合同、裁判、支持者与可选金钱赌注 |
| Beeminder | 量化目标追踪服务 | 可绘图数据、红线、自动接入与金钱承诺 |
| TaskRatchet | 一次性任务承诺工具 | 任务、截止时间、提醒与金钱赌注 |
| Forfeit | 移动端与 Mac 端证据验收、约束工具 | 照片、视频、定位、健康数据、人工或 AI 验证 |
| Focusmate | 在线同伴工作服务 | 预约、目标声明、共同专注、结束回顾 |
| Coach.me | 习惯追踪、社群与教练服务 | 免费打卡、社群支持、付费私聊教练 |

比较不按功能数量评分，而看六个问题：

1. 用户第一次进入后被要求做什么；
2. 承诺何时锁定、能否静默修改；
3. 什么被当成完成证据；
4. 未完成、无机会和外部阻断如何区分；
5. 产品施加多少外部压力、隐私代价和维护成本；
6. 用户如何修订、申诉、退出或转向支持。

## 三、逐项调查

### 1. WOOP：用固定顺序保护一次完整思考

**官方事实**

- 官方应用按 Wish、Outcome、Obstacle、Plan 四步引导，要求保持顺序；应用免费，并支持简体中文。
- 用户可以保存愿望和观察进展，也可以使用离线纸面练习包。
- 保存后的 WOOP 不能整体就地编辑；不满意时创建一个新的 WOOP，计划部分可以单独修改。
- 当愿望超出行动范围时，官方建议调整、推迟或放下；一个 WOOP 聚焦一个具体计划。

来源：[WOOP 官方练习页](https://woopmylife.org/en/practice)。

**分析**

WOOP 的价值不是字段本身，而是用固定顺序减少跳步，并用“新建而非覆盖”保存前后判断。它同时承认目标可能不可行，这与本项目的退出边界一致。

**对本产品的建议**

- 借鉴固定顺序和单一焦点；
- 借鉴“新版本替代静默编辑”；
- 不复制其内在障碍优先假设。本项目必须先检查资源、权限、风险和反馈，不能把结构约束重新解释为个人内在问题。

### 2. stickK：把承诺拆成合同、裁判、赌注与支持

**官方事实**

- 创建承诺合同时，用户可以设置起止日期，并可选择裁判、金钱赌注和支持者。
- 创建合同本身免费；只有用户主动加入金钱激励并报告未成功时才收费。

来源：[stickK 官方帮助中心](https://stickk.zendesk.com/hc/en-us/articles/206833247-Create-a-Commitment-Contract)。

**分析**

stickK 把“自己说了算”拆成多个可选外部接口。裁判提高证据可信度，支持者提供社会承诺，金钱赌注提高违约成本。但这些机制没有自动解决目标是否重要、机会是否真实、反馈是否有效。

**对本产品的建议**

- 保留“合同必须可复述”的设计；
- 不迁移“可选证据见证人”；它会改变个人本地工具边界；
- 不默认加入金钱、羞耻或社交曝光。目标人群的问题未必是惩罚不足，金钱压力还可能掩盖资源与风险问题。

### 3. Beeminder：把承诺变成可绘图数据和不可临时逃避的红线

**官方事实**

- Beeminder 将量化自我与承诺合同结合：用户设定可绘图目标，手动或通过集成提交数据，越过红线时可能被收费。
- 用户可决定赌注上限；修改赌注有等待期，归档目标也有倒计时。
- 官方当前允许免费账户建立最多三个活动目标，但仍要求添加支付方式；偏离目标可能产生承诺费用，首周未建立目标也可能产生五美元费用。具体限制与价格以官方当前页面为准。

来源：[Beeminder 官方概览](https://www.beeminder.com/overview)、[官方费用说明](https://www.beeminder.com/money)、[官方帮助中心](https://help.beeminder.com/article/19-how-much-does-beeminder-cost)。

**分析**

Beeminder 的强项是把长期目标转换为可观察轨迹，并防止用户在最后一刻放宽规则。弱点是任何单一红线都可能把机会、资源和行为混成同一个数字；对不适合连续量化的目标，图表本身也会制造维护负担。

**对本产品的建议**

- 借鉴“规则变更必须延迟或生成新版本”的完整性；
- 借鉴自动数据只在信号与目标高度匹配时使用；
- 不做红线、连续趋势、赌注升级或跨用户比较；
- 保留原始计数“完成证据数 / 有机会数”，不把它升级为目标成功概率。

### 4. TaskRatchet：一次性任务比长期系统更容易理解

**官方事实**

- 用户创建任务、设置截止时间和自定赌注，系统在截止前提醒；按时完成则结束，错过则收取赌注。
- 产品可与 Beeminder、Todoist 和日历连接。

来源：[TaskRatchet 官网](https://taskratchet.com/)、[官方文档](https://docs.taskratchet.com/)。

**分析**

一次任务、一个截止时间、一个后果，使首次使用成本很低。它适合已经明确、可独立完成的任务，不负责判断任务本身是否值得、是否存在机会。

**对本产品的建议**

- 保持“一次活动、一个截止、一个证据”的清晰性；
- 首屏只突出当前唯一动作，不要求用户先建立完整项目系统；
- 不复制金钱赌注和泛化提醒。

### 5. Forfeit：让证据方式匹配任务，但隐私与强制代价很高

**官方事实**

- 用户设置任务、截止时间、赌注和验证方式；证据可来自照片、视频或延时摄影、GPS、Apple Health、屏幕使用或电脑活动。
- 照片和视频可能由 AI 或人工审核；官方提供申诉和不同严格度设置，并称人工会在十二小时内审查申诉。
- 部分模式还会采取收费、联系他人、阻止应用或网站等强制动作。

来源：[Forfeit 官网](https://www.forfeit.app/)。

**分析**

Forfeit 最值得借鉴的是“不同任务需要不同证据”，而不是把所有完成都变成勾选框。它也承认误判和不可控事件需要申诉。部分验证方式会要求用户提交敏感的行为、健康、位置或屏幕数据；某些强制机制也可能带来隐私或胁迫风险。

**对本产品的建议**

- 在合同锁定前显示一条可复述的证据预览，迫使活动与证据匹配；
- 保留 noOpportunity 和事实备注，作为本地、低成本的例外记录；
- 不上传照片、定位、健康、银行、通信或屏幕数据；
- 不采用“无申诉”“设备锁死”“联系亲友”或自动扣费。

### 6. Focusmate：同伴在场解决启动，不解决证据解释

**官方事实**

- 用户预约时间，系统匹配一位伙伴；双方开场声明目标，各自工作二十五、五十或七十五分钟，结束时回顾进展。
- 免费方案每周提供三次会话；官方说明会话不录制。

来源：[Focusmate 官方问答](https://www.focusmate.com/faq/)、[官方定价页](https://www.focusmate.com/pricing/)。

**分析**

Focusmate 把“开始”变成一个预约事件，并通过极简开场和收尾形成社会约束。这种设计旨在降低启动摩擦；是否改善具体用户结果仍需独立验证，而且同伴在场本身不能判断目标风险、资源是否到位或反馈是否有效。

**对本产品的建议**

- 借鉴“开始前一句承诺，结束后一次回顾”的短循环；
- 后续可以测试可选的二人见证服务，但不得要求摄像头或暴露工作内容；
- 当前版本继续离线单人使用，避免社交机制成为进入门槛。

### 7. Coach.me：免费自助与付费人工支持分层

**官方事实**

- Coach.me 提供免费的习惯追踪和目标社群问答，也提供私聊习惯教练、个人或小组教练等付费服务。
- 官方帮助中心在调查日列出的习惯教练价格为每周 25 美元或每月 87 美元；自定义个人或小组套餐可由教练自行定价，其他项目以官方页面所列条件为准。

来源：[Coach.me 官方首页](https://app.coach.me/)、[官方帮助中心](https://support.coach.me/article/108-coaching)。

**分析**

这是一条“自助工具—社群—人工服务”的产品梯度。人工支持适合目标澄清、资源协调和持续复盘，但它也可能把普通记录变成长期依赖。

**对本产品的建议**

- 将“寻求支持”保留为七个合法决定之一，而不是隐藏在失败之后；
- 若未来增加服务，必须由用户主动选择，并明确服务不能替代医疗、法律或财务专业判断；
- 不在最小版本中加入信息流、公开打卡或教练市场。

## 四、市场产品的六种基本形态

| 形态 | 解决的问题 | 典型优势 | 主要风险 | 本项目选择 |
|---|---|---|---|---|
| 自助练习与模板 | 不知道如何形成计划 | 低成本、可离线 | 容易成为新的收藏品 | 保留纸面合同作为对照 |
| 本地单页工具 | 需要版本、计算和可迁移记录 | 低隐私成本、规则可验证 | 缺少外部见证 | 当前主形态 |
| 目标追踪与提醒 | 忘记或难以保持频率 | 连续反馈、自动接入 | 维护和数字焦虑 | 不做连续追踪 |
| 承诺与惩罚工具 | 明知可做但临时反悔 | 后果明确 | 金钱、羞耻和胁迫 | 不作为默认机制 |
| 同伴或社群 | 启动困难、缺少在场感 | 社会承诺 | 隐私、匹配和人际负担 | 后续可选验证 |
| 教练或陪跑 | 问题复杂、需要共同判断 | 能处理情境和例外 | 成本高、质量不稳定 | 仅作为求助路线 |

## 五、不可直接复制的市场惯例

### 1. 不复制连续天数和统一达标线

连续天数会把“没有机会”与“有机会但没有行动”压成同一种失败，也会诱导用户为了保住数字而降低证据质量。

### 2. 不复制默认金钱惩罚

惩罚只有在目标重要、资源充足、风险可控、知识足够和反馈有效时才可能针对真实反悔。本项目的五道门尚未通过时，收费只会惩罚约束。

### 3. 不复制公开打卡和摄像监督

社会在场可以帮助启动，但本项目涉及工作、关系、健康和个人目标。默认公开或录像与本地隐私原则冲突。

### 4. 不复制自动教练替用户决定

系统可以提示缺失字段和协议冲突，不能替用户判断医疗、安全、职业或关系风险，也不能根据一次结果生成“你就是某种人”的结论。

### 5. 不复制越来越复杂的仪表盘

产品只需要显示合同版本、完成证据机会、无机会记录和事实账本。更多图表在获得真实用户证据前只是新的系统维护。

## 六、交互优化原则

### 原则一：每个状态只有一个主要任务

- 空状态：确认一个目标；
- 有目标无合同：锁定活动证据合同；
- 有合同：记录今天的机会与证据；
- 有观察：复核下一决定；
- 已退出：导出或清空，不推动继续。

界面仍保留历史信息，但视觉上只突出当前主任务。

### 原则二：先预览承诺，再锁定版本

合同表单实时生成一句人能复述的话，包含活动、截止时间、时间盒、接触方式和证据。锁定按钮明确显示即将生成的版本号。修订时列出相对上一版发生变化的字段，不允许就地覆盖。

### 原则三：在选择点解释分母，而不是事后纠错

选择“无机会”时立即说明它不进入分母，并提示“机会出现但没有完成”仍应选择“有机会、未留痕”。这条说明比事后展示一个比率更重要。

### 原则四：每个下一决定都给不同的记录提示

- 保持：记录什么信号支持保持；
- 修订：记录哪一个合同字段需要改变；
- 有界学习：记录缺失知识和停止学习的条件；
- 补资源：记录缺少的权限、时间、设备或协作；
- 修测量：记录当前证据为什么不可判读；
- 退出目标：确认关闭目标和活动合同；
- 寻求支持：记录支持对象和不自行推进的边界。

提示只帮助用户写清事实，不替用户选择决定。

### 原则五：高影响操作采用“预览—确认—执行”

- 备份导入先显示目标、风险、合同数和观察数，再确认替换；
- 诊断导入只显示将预填的目标，不直接保存；
- 退出在提交前二次确认；
- 清空继续保留不可撤销确认；
- 损坏的本地数据在下载或明确弃用前不得被新写入覆盖。

## 七、本轮交互升级清单

### P0：本轮必须完成

1. 增加四步状态导航和“当前下一步”提示；
2. 提交目标、合同和观察后，将焦点移动到真实下一步；
3. 增加合同锁定预览和版本差异摘要；
4. 增加 noOpportunity 即时语义说明；
5. 为 0 / 0 增加“不代表失败”的空态解释；
6. 根据七种决定切换事实备注提示；
7. 退出二次确认；
8. 导入先预览、后替换，错误显示在对话框内部；
9. 损坏本地数据隔离、下载与明确弃用；
10. 修复风险快照、证据布尔值和退出终态三类导入漏洞。
11. 当前合同版本单独计算证据完成率与无机会数，旧版本只进入历史账本；
12. 无机会记录必须填写客观原因；
13. 合同版本状态必须形成连续、不可倒置的时间线；
14. 写入前检测其他标签页对本地数据的修改，冲突时停止覆盖。

### P1：个人试用后决定

1. 可打印纸面合同与数字版本对照；
2. 追加式观察纠错事件。

证据见证人、同伴工作时段和其他多人机制不再进入后续排期；当前产品边界固定为个人、本地、单目标工作台。

### P2：没有证据前不做

账号、云同步、通知、连续天数、积分、排行榜、金钱赌注、公开社群、教练市场、自动健康或位置数据接入、AI 自动下一步。

## 八、验证指标与失败标准

本轮不声称产品改善长期行为，只验证交互是否减少协议误用：

| 问题 | 可观察证据 | 失败信号 |
|---|---|---|
| 用户能否找到下一步 | 首次任务是否无需解释即可继续 | 在四个区块间反复寻找主按钮 |
| 合同是否可复述 | 锁定前能否准确复述活动、证据与截止 | 用户锁定后才发现证据无法取得 |
| 无机会是否被正确使用 | 用户能否区分没有场景与有场景未行动 | 为保护比率而把未行动记成无机会 |
| 修订是否保留理由 | 版本历史是否看得出改了什么、为什么 | 新版本覆盖旧判断或没有修订依据 |
| 导入是否可控 | 替换前是否看见内容摘要 | 误覆盖本地有效数据 |
| 退出是否清楚 | 用户是否知道退出会关闭目标与合同 | 误触退出或认为退出等于人格失败 |

七天试用后，如果这些误用没有下降，或用户为了维护合同投入的时间超过其带来的版本与分母价值，应停止扩展数字产品，回到纸面合同与开放 JSON 格式。

## 九、最终产品判断

本项目不把市场缺口当作已经证实的事实。它选择探索一种低压力证据工具：允许用户记录“这次没有机会”“真正缺的是资源”“这个反馈不能更新判断”或“可以退出”，再用真实试用判断这种组合是否有额外价值。

“下一次证据”应继续是一块克制的本地工作台，而不是行为管理平台。它的竞争力不来自更强的督促，而来自更少的误判、更清楚的版本、更可信的分母和更合法的退出。
