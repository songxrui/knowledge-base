# “下一次证据”1.0：低摩擦行为工作台重构 PRD

> 版本：1.0（研究版）  
> 日期：2026-07-21  
> 上一版：0.2 单任务工作区与苹果视觉重构  
> 产品边界：单人、单目标、本地数据  
> 证据状态：行为心理学支持局部机制；本产品整体流程仍是待验证假设

## 一、为什么要重构

0.2 已经解决了“所有区块同时展开”，但没有解决更深的问题：用户每次记录仍像在填一张小问卷。

当前一次观察要面对日期、机会、证据、分钟、决定和备注；第一次建合同还要填十个字段。这个设计对研究者完整，对使用者费劲。用户真正需要的通常只是：

1. 这次有机会吗？
2. 做到了吗？
3. 要不要改一下？

1.0 的目标不是再加一个更聪明的评分系统，而是把复杂性放回系统内部，把前台变成几秒能完成的白话记录。

## 二、产品判断

### 2.1 已有证据支持什么

- 具体的 if–then 计划有一定行为帮助，但效果不大且因情境而异。
- 进度监测平均有帮助，实际记录比只想一想更有价值。
- 行为要看能力、机会和动机，不能把所有未完成都归为“不自律”。
- 稳定情境中的重复有助自动化，但习惯形成时间差异很大。
- 网络工具的持续使用会受到工作量、界面和生活适配影响。
- 表单应该只问有明确用途的问题，并让用户只回答与自己有关的部分。

### 2.2 尚无证据支持什么

没有权威书籍、论文或竞品资料直接证明下面这套完整流程有效：

> 10 个合同字段 + 6 个观察字段 + 7 种下一决定 + 证据完成率。

因此，1.0 的所有简化都写成可测试假设，不写成“行为科学已经证明”。

## 三、面向用户的产品承诺

> 事情发生时，点两下，记住事实；想改时，再多说一句。

不要求每天打卡，不要求每天写日志，不要求用户懂心理学术语。用户可以漏记、暂停、退出，也不会被连续天数、分数或提醒追着走。

## 四、用户语言规则

### 4.1 前台禁用术语

以下词只保留在帮助、导出和开发文档中，不放在主要按钮或必填标签里：

`活动证据合同`、`机会观察`、`证据完成率`、`接触方式`、`指标`、`决策规则`、`风险快照`、`分母`、`ECR`、`修订版本`。

### 4.2 前台白话替换

| 系统术语 | 用户看到的文案 |
|---|---|
| 活动 | 这次要做的事 |
| 完成证据 | 做完后留下什么 |
| 机会 | 今天有机会吗？ |
| evidenceObserved | 做到了吗？ |
| noOpportunity | 没遇到 |
| 决策规则 | 如果不顺，下一步怎么办？ |
| 修订 | 换个方法 |
| 有界学习 | 先补一个问题 |
| 补资源 | 先把条件补齐 |
| 修测量 | 先把看法改清楚 |
| 退出目标 | 先停一停 |
| 寻求支持 | 找人一起看 |
| 账本 | 以前的记录 |
| 恢复数据 | 先把旧数据保住 |

### 4.3 文案口吻

- 一句话只说一件事。
- 尽量用“做、没做、遇到、没遇到、改、停”这类常用词。
- 不用“你应该”“坚持一下”“失败”“达标”“得分”。
- 错误告诉用户下一步怎么修，不解释内部规则。
- 解释材料放在“为什么”或帮助里，不挡住主按钮。

## 五、核心流程

### 5.1 第一次设置：一条约定，不填研究表

默认路径最多三屏，每屏一个问题：

#### 第 1 屏：这次要做什么？

字段：一个输入框。

示例占位：`写一个能在 20 分钟内完成的小动作`。

按钮：`继续`。

#### 第 2 屏：什么时候算有机会？

首选：一个白话选择或一句话输入。

示例：`明天下午打开电脑后`、`对方回复后`、`今天出现空档时`。

按钮：`继续`。

如果用户暂时说不清，允许选择 `我还不知道，先记一次`，不阻止创建低风险草稿。

#### 第 3 屏：做完后留下什么？

字段：一个可选短句。

示例：`发出邮件`、`保存一张截图`、`记下实际用时`。

如果用户跳过，系统用“留下一条事实”作为暂时提示，不要求重新填长表。

#### 低风险默认保存

低风险、无敏感接触时，三屏后直接生成一句约定：

> 如果“明天下午打开电脑后”出现，我就“写一封邮件”；做完后留下“发出邮件”这条事实。

按钮：`保存这次约定`。

#### 高风险分支

高风险或安全关键目标不能走快速保存。系统先显示：

> 这件事不适合自己直接试。你可以改成模拟、找合适的人一起看，或先停下来。

这条安全分支保留 0.2 的双层阻断，不因减少字段而绕过。

### 5.2 快速记录：两问三选，不做每日问卷

用户主动打开产品，或点击当前约定旁的 `记一下`。

#### 第一步：有机会吗？

三个按钮：

- `有，刚刚出现`
- `没有，今天没遇到`
- `说不清`

默认日期自动填今天；不要求用户先看合同版本、统计或帮助说明。

#### 第二步：如果有机会

两个大按钮：

- `做到了`
- `没做到`

分钟数自动使用约定里的时间盒；用户需要时点 `改一下用时`。这不是必填。

#### 第三步：要不要改？

先只显示三个白话选项：

- `先照这样做`
- `换个方法`
- `先停一停`

选择 `换个方法` 后才展开四个原因：`不会做`、`条件不够`、`看不清结果`、`别的原因`。这些原因再映射到现有七类业务决定，不直接让用户选择七个术语。

选择 `先停一停` 时，根据风险显示 `暂时停下` 或 `找人一起看`，保留退出与求助的安全含义。

#### 没有机会

只显示几个常见原因按钮：

- `场景没出现`
- `没时间`
- `没权限或资源`
- `其他`

其中一个原因即可保存；补充说明是可选的。系统自动保存 `noOpportunity`，分钟、证据和指标保持协议要求的零值，不进入当前统计。

#### 说不清

保存为“待确认”状态，提示：

> 先不猜。下次看清楚再记。

此状态不能被当成“完成”或“没机会”，避免强迫用户选错。

### 5.3 详细说明：默认收起

在快速记录保存后，显示 `想多写一句？`。

展开后可以填写：

- 发生了什么；
- 实际用了多久；
- 哪个数字或事实值得留下；
- 为什么想换方法。

全部是可选项。用户不展开也不影响保存、版本和安全校验。

### 5.4 回看：看事实，不先看分数

账本默认显示：

1. 最近一次记录；
2. 当前约定的一句话；
3. 最近发生的事实；
4. `继续 / 换个方法 / 先停一停` 的选择。

“证据完成率”改为二级信息，放在 `看完整统计` 内，并明确说明：

> 这是记录的统计，不是你的分数。

## 六、P0 需求

### P0-00：研究边界与可证伪假设

正常路径：所有产品文档区分事实、推断和待验证假设；不把书籍、论文或竞品宣传写成产品有效性证明。

失败路径：发现用户跳过、停用或反复误选时，记录为产品摩擦，不把责任推给用户。

测试接口：研究报告中的来源分级；PRD 中每个行为假设都有对应观察指标。

证据：研究报告、来源 URL、14 天个人试用记录和反例日志。

### P0-01：一句话约定

正常路径：低风险用户在三屏内完成一次约定；系统生成一句 if–then 白话句。

失败路径：输入不清楚时允许保存草稿；高风险时必须进入安全分支；刷新和退出不丢草稿。

测试接口：设置屏数、必填字段数、合同数据完整性、风险阻断和恢复。

验收目标：与 0.2 基线比较，首次保存时间和放弃点下降；不预先宣称具体改善百分比。

### P0-02：两问快速记录

正常路径：打开“记一下”后，最多处理机会、完成和下一步三个决策；日期、合同版本、默认分钟和统计字段由系统填入。

失败路径：用户退出或关闭时不产生半条记录；“说不清”不能被转换成完成或没机会；损坏数据和跨标签冲突不覆盖原数据。

测试接口：有机会/没机会/说不清、做到/没做到、三种下一步、空态、恢复态、键盘路径。

验收目标：记录所需的必处理交互不超过 3 个；详细文字不作为保存前置条件。

### P0-03：渐进式细节

正常路径：常见路径只显示一到两个问题；高级字段按情境出现；用户可以在保存后补写。

失败路径：任何高级字段异常都不能阻止最小安全记录；风险字段仍必须在安全分支完成。

测试接口：字段显示矩阵、分支问题、跳过、返回、键盘和屏幕阅读顺序。

验收目标：默认界面不出现“指标、接触方式、决策规则、证据完成率”等专业词。

### P0-04：白话文案与可发现性

正常路径：所有当前任务、按钮、空态和错误均使用短句和常用词；主按钮只表达下一步动作。

失败路径：不依赖颜色、术语或长解释传达错误；文字放大到 200% 仍不截断。

测试接口：文案扫描、中文可读性人工审查、320/390/735/1024/1440px 截图、高对比度和屏幕阅读器。

验收目标：一眼能回答“现在要做什么”，不要求用户先学习产品词汇。

### P0-05：持续使用成本

正常路径：不强制每日打卡，不要求没机会时每天来填；用户可以暂停、漏记、恢复和退出。

失败路径：记录耗时上升、反复跳过或出现连续放弃时，产品显示“可以先停”，不加提醒、惩罚或排行榜。

测试接口：打开到保存时间、点击数、展开高级字段次数、放弃点、连续使用天数、主动暂停原因。

验收目标：以 0.2 和纸面为对照；只报告个人数据，不外推群体效果。

### P0-06：数据与业务协议兼容

正常路径：快速记录映射到现有 `next-evidence:v1` 业务字段；版本、风险、无机会分母、每日分钟和导入校验继续有效。

失败路径：不为了省步骤而删除安全字段、绕过风险阻断或改变历史统计；无法映射时保留原数据并提示用户。

测试接口：v1 导入导出、旧版本账本、快速记录三路径、损坏数据、跨标签冲突。

## 七、现有数据协议的映射

| 用户动作 | v1 数据映射 |
|---|---|
| 有机会 + 做到了 | `opportunity=available`、`evidenceObserved=true` |
| 有机会 + 没做到 | `opportunity=available`、`evidenceObserved=false` |
| 没有机会 | `opportunity=noOpportunity`、客观原因、分钟/证据/指标清零 |
| 说不清 | 进入待确认草稿，不直接写成完成或无机会 |
| 先照这样做 | `decision=keep` |
| 换个方法 | 根据原因映射到 `revise / learning / resources / measurement` |
| 先停一停 | `exit` 或 `support`，按安全情境确认 |

原则：内部字段可以复杂，用户不需要看到字段名；界面状态不写入备份协议。

## 九、验收指标与证据

### 开发验收

- 默认记录路径最多 3 个必处理交互；
- 详细备注、指标和高级设置不阻挡保存；
- 页面不出现横向溢出；
- 现有规则测试继续通过；
- v1 导入导出和风险阻断继续通过；
- 键盘、屏幕阅读器、高对比度、深色和减少动画继续通过；
- 320、390、735、1024、1440px 截图覆盖设置、快速记录、没机会、说不清、换方法和恢复态。

### 个人试用验收

每天只记录：

1. 打开到保存用了多久；
2. 点了几次；
3. 是否展开了详细说明；
4. 是否中途放弃；
5. 这条记录是否让下一步更清楚。

不记录“连续天数分数”，不把试用结果写成群体效果。

### 继续标准

- 个人能在不看说明的情况下完成最小记录；
- 记录时间比 0.2 更短，或至少不更长；
- 详细信息仍能在需要时回查；
- 没机会不会被误记成失败；
- 不降低高风险阻断和数据恢复能力；
- 数字版至少在一个具体维度比纸面更有用，且没有增加明显维护成本。

### 停止标准

- 为了少填而丢失关键安全信息；
- 用户开始为了“看起来完成”而乱点按钮；
- 低摩擦记录让事实更模糊，无法支持下一决定；
- 仍然需要每天完整填写才知道产品状态；
- 个人使用比纸面更慢，或没有任何可回查价值。

## 十、引用与背书的使用规则

引用只放在帮助、研究页和 PRD，不放在主操作路径中制造权威压力。

- BJ Fogg / Tiny Habits：说明小动作和稳定线索是作者方法，不证明本产品有效。
- Gollwitzer：支持一句 if–then 约定，不支持长合同必然更好。
- Harkin：支持保留可回看的最小记录，不支持长日志。
- Michie：支持在后台分析能力、机会和动机，不支持让用户填写 COM-B 问卷。
- Norman / Krug：支持可发现、能理解、少费脑，不支持某个固定字段数量。
- EAST：作为“简单、及时”的设计检查表，不作为效果保证。

## 十一、明确不做

- 不增加 AI 自动判断、情绪诊断或行为预测；
- 不增加每日提醒、连续天数、积分、排行榜或金钱惩罚；
- 不把名言、书籍或竞品宣传当作效果证明；
- 不把简单记录扩展成更大的问卷；
- 不新增账号、云同步、社交比较、定位、健康数据上传或外部埋点；
- 不为了减少点击而绕过高风险阻断、版本历史和数据恢复；
- 不在真实个人试用前宣布“数字版优于纸面”。
