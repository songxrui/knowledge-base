# “下一次证据”产品规格与验证

## 定位

面向已经知道一个可行起步动作、却反复增加目标相关准备的高信息摄入者，提供一个本地、克制的活动证据合同。产品不要求“立刻做大事”，只把一个安全、有限的活动放进真实约束，并在观察后允许保持、修订、学习、补资源、修测量、退出或求助。

它不是医学诊断、心理治疗、习惯打卡、任务管理器或知识库。诊断工具可以提供待确认建议，但不能替用户创建合同。

## 用户与进入条件

适用用户同时满足：有一个本人认可的目标；能说出一个不超过 20 分钟的候选活动；任务风险能够判断；愿意记录结果，即使结果是否定目标。

以下情况不直接进入低风险测试：真正缺少起步知识；目标依赖尚未获得的权限或资源；医疗、法律、财务、人身安全等高风险任务；反馈高度延迟或无法归因。产品在这些情况下只允许有界模拟、监督下测试、补资源、修测量、退出或寻求专业支持。

## 核心对象

### 1. 一个目标

同一数据空间只有一个活动目标。目标记录标题、验证理由和风险等级。退出是有效结果；退出后不再生成新合同，用户可先导出，再清空开始新的目标。

### 2. 一个活动证据合同

每个版本包含：唯一活动、可回看的完成证据、截止日期、1 至 20 分钟时间盒、直接/模拟/监督接触方式、1 至 2 个观察指标、观察后的决策规则。

锁定即生成版本号。修订不是编辑旧合同，而是创建新版本；旧版本标记为“已被替代”（`superseded`），历史观察继续引用当时的合同标识符和版本号。

### 3. 一次机会观察

每天可以记录：当天是否存在约定机会、是否留下合同证据、使用分钟、1 至 2 个指标值、事实备注和下一决定。同一天全部证据活动累计不得超过 20 分钟。

`noOpportunity` 表示约定机会客观没有出现。该记录保留原因，但强制将分钟、证据和指标清零，不进入证据完成率分母。它不能用来掩盖“机会存在但没有做”；后者必须记录为“有机会但未留下证据”（`available + evidenceObserved=false`）。

### 4. 下一决定

| 决定 | 含义 | 下一步约束 |
| --- | --- | --- |
| 保持 | 合同仍适配当前瓶颈 | 不改活动，等待下一次合格机会 |
| 修订 | 活动、证据或时间盒不合适 | 新建合同版本，不覆盖旧版本 |
| 有界学习 | 观察暴露了具体知识缺口 | 写明要回答的问题和返回测试的边界 |
| 补资源 | 缺少权限、时间、设备或协作条件 | 资源到位前不把无机会计作失败 |
| 修测量 | 反馈噪声高、延迟或不可归因 | 先提高指标效度，不追求更多接触次数 |
| 退出目标 | 目标不重要、代价不合理或证据否定假设 | 关闭目标和当前合同 |
| 寻求支持 | 风险、能力或情绪负荷超出自助边界 | 转向合格同伴、主管或专业人员 |

## 机制与指标

产品只显示一个派生指标：

`证据完成率 = 已留下合同证据的“有机会”观察数 / 全部“有机会”观察数`

当分母为零时显示 `0 / 0`，不解释为失败。`noOpportunity` 始终排除。证据完成率不是分数、概率或人格判断；不能跨用户排名，也不设统一达标线。界面默认只计算当前活动合同；目标已退出时计算最近关闭的合同。历史观察仍完整保留在账本中，不与当前版本的分子、分母或无机会数混算。

核心机制不是提高证据完成率，而是让四件事可追溯：用户事前承诺了什么；现实中是否有机会；出现了什么证据；证据改变了哪个决定。

## 用户旅程

1. 用户创建或从诊断工具导出的 JSON 数据文件载入一个待确认目标。
2. 用户确认风险等级。高风险与安全关键目标的“直接测试”在界面和逻辑层同时禁用。
3. 用户写下一个不超过 20 分钟的活动、完成证据、1 至 2 个指标和决策规则，锁定版本 1（`v1`）。
4. 机会出现后，用户记录证据；没有机会则记录 `noOpportunity` 和事实原因。
5. 用户选择下一决定。选择“修订”会进入新版本；选择“退出”会关闭目标和合同。
6. 用户随时导出完整的 JSON 数据文件；不受支持的数据格式、越界时间或风险违规不会替换当前数据。

## 交互架构

### 1. 状态导航

页面顶部呈现“目标—合同—观察—账本”四步状态，不要求用户同时理解所有表单。系统根据数据状态只突出一个当前任务：空状态先确认目标；有目标无合同时填写合同；合同锁定后记录机会；作出修订决定后返回合同；退出后只允许查看、导出或清空。

步骤导航是现有状态的投影，不是新的任务清单。已完成步骤可以回看，尚未满足前置条件的步骤保持禁用。

### 2. 合同锁定预览

合同表单实时生成一条可复述的预览句，包含截止日期、接触方式、唯一活动、时间盒和完成证据。用户确认这句话后才锁定版本。修订历史显示相对上一版改变的字段；若修订来自一次“修订”观察，历史同时显示该观察的事实备注，手动修订则明确标为“未记录修订依据”。

### 3. 机会与决定提示

选择“无机会”时，界面即时说明该记录不进入分母，并提醒“机会出现但没有行动”必须选择“有机会”。七种下一决定分别切换事实备注提示，但产品不替用户选择决定。分母为零时，账本显示“还没有有机会记录，不代表失败”。

### 4. 高影响操作

- 退出目标在写入前二次确认；取消后状态字节不变。
- 备份导入先校验并显示目标、风险、合同数和观察数，第二次确认才替换本地数据。
- 诊断导入只预览并载入目标表单，不直接保存。
- 导入错误显示在对话框内部，用户无需离开当前上下文寻找错误。
- 浏览器存储若无法通过校验，原始文本进入隔离状态；在下载或明确弃用前，创建目标、导入和普通导出都不能覆盖它。
- 每次提交、导入、清空或弃用恢复数据前，都会比较页面载入时的本地快照；若另一标签页已经修改数据，本页停止写入并提示重新载入。

## 首次体验

| 时间 | 操作 | 完成状态 |
| --- | --- | --- |
| 0-3 分钟 | 确认一个目标、理由和风险 | 页面只保留一个目标 |
| 3-10 分钟 | 写活动、证据、日期、时间盒和指标 | 合同字段完整但尚未产生结果 |
| 10-12 分钟 | 锁定版本 1 | 版本进入历史，不可静默覆盖 |
| 12-20 分钟 | 若机会存在，执行并记录；否则只记无机会原因 | 形成第一条可回看的机会观察 |

## 最小版本

- 单目标和退出状态。
- 合同锁定、替代和版本历史。
- 每日 20 分钟硬上限。
- 1 至 2 个指标及原始观察。
- 证据完成率按当前合同版本计算，并正确排除 `noOpportunity`；无机会记录必须填写客观原因。
- 七类下一决定。
- 高风险和安全关键目标的直接测试双层阻断。
- 自有备份 JSON 数据文件的严格校验、预览、二次确认、导入、导出与清空。
- 损坏本地数据的隔离、原文下载和明确弃用流程。
- 诊断工具 JSON 数据到待确认目标表单的有限适配。
- 四步状态导航、合同锁定预览、版本差异和决定相关提示。
- 浏览器本地存储；无账号、后端、分析脚本或网络请求。

## 明确不做

- 不生成诊断结论、疾病标签或治疗建议。
- 不承诺提高生产力、收入、健康或行为改变概率。
- 不做连续天数、勋章、总分、概率、排名、同伴比较和惩罚性提醒。
- 不自动拆解整个项目，不允许同时管理多个目标或活动合同。
- 不把“更多接触”默认为更好；错误、延迟或危险反馈应先修测量或求助。
- 不在无有效机会时制造分母，也不允许把客观存在但未执行的机会改记成无机会。

## 数据与导入边界

自有备份数据要求 `app="next-evidence"`、`schemaVersion=1`，并校验目标、合同、连续版本时间线、风险快照、证据布尔类型、无机会原因、退出终态、指标、观察引用和每日分钟。目标风险与合同风险快照必须一致；`evidenceObserved` 必须是布尔值；退出观察必须对应已退出目标和最近关闭的合同。校验失败返回原状态，界面不写入本地存储。

导入采用“验证—预览—确认替换”两阶段流程。若启动时发现已有浏览器存储不合法，系统保留原始文本并暂停一切新写入；用户可以先下载恢复文件，再明确弃用。这个恢复文件只是原始故障快照，不被宣称为有效备份。

诊断导入显式支持诊断工具的 `schemaVersion="1.0" + draft + assessment` 数据格式，只提取目标字段 `draft.goal` 和路线说明字段 `assessment.routeCopy.instruction`。背景字段 `draft.context`、回答字段 `draft.answers` 与判断字段 `assessment.findings` 不进入产品。若当前路线 `assessment.currentRoute` 为紧急支持（`urgent_support`），或继续标记 `canContinue` 为否，产品拒绝预填生产力目标，只显示安全支持提示，状态保持不变。旧版带明确应用标识的 `schemaVersion=1` 建议结构仍可兼容；已有目标时不会覆盖。

## 个人双条件验证

### 目的

当前只有一个实际操作者，因此验证采用 N-of-1 双条件协议，不设置招募人数或群体达标率。它只回答“这个个人工具是否比纸面更容易找到下一步、追溯版本和形成决定”，不验证整套理论，也不外推为他人效果。

### 日程

| 阶段 | 任务 | 核查证据 |
| --- | --- | --- |
| 第 0 天 | 锁定目标、风险边界、原型哈希和纸面格式 | 可复现基线；不填写试用结果 |
| 第 1–7 天 | 使用数字原型，每天不超过 20 分钟 | JSON、每日耗时、修订、误分类、放弃点和主观负担 |
| 第 8–14 天 | 使用纸面合同处理同类目标 | 纸面照片或文字、每日耗时、修订、误分类和放弃点 |
| 第 14 天 | 逐项比较数字与纸面，不做群体推断 | 版本追溯、下一决定、事实完整性、耗时和反例 |

### 继续标准

- 操作者无需展开长页面即可找到当前下一步。
- 高风险或安全关键目标无法锁定直接测试。
- 单日记录不超过 20 分钟，`noOpportunity` 不进入证据完成率分母。
- 仅凭版本历史可以说明“改了什么、为什么改”。
- 导出后重新导入，目标、合同版本和观察条数保持一致。
- 数字版在版本追溯、分母正确性或下一决定上至少有一项提供纸面没有的可复核价值，且没有显著增加步骤或耗时。

这些是单个操作者的产品决策条件，不是人群效应估计。

### 立即失败条件

- 任一高风险直接测试可通过界面或导入被锁定。
- 任一非法导入覆盖已有有效数据。
- 任一 `noOpportunity` 增加证据完成率分母，或一天可写入超过 20 分钟。
- 旧合同内容在修订后被覆盖，导致历史观察失去原版本。
- 操作者为了改善显示值而拆分微小证据或把未执行机会改记成无机会。

### 产品退出标准

出现立即失败条件时停止试用并修复。完成 14 天双条件试用后，若数字版本相对纸面合同没有增加版本可追溯性、分母正确性或下一决定清晰度，或完成任务更慢，则停止开发应用，保留纸质合同与开放数据格式。若真实问题主要需要资源协调、专业监督或医疗支持，而不是证据合同，则产品退出该场景，不扩张成万能教练。空白记录和未发生的试用不得写成阴性或阳性结果；执行模板见[14 天个人双条件试用记录模板](../experiment/14天个人双条件试用记录模板.md)。
