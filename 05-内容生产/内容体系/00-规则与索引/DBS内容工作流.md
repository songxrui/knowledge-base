# DBS 内容工作流

DBS 只在当前节点选择一个 Skill。不得预写固定长链，也不得把模拟演练写成作者经历。

## 使用方式

1. 把当前材料、目标和卡点交给 `/dbs`。
2. `/dbs` 根据已有上下文路由到一个 Skill，并立即执行。
3. 检查该 Skill 的实际结论和新证据。
4. 需要继续时再次回到 `/dbs`，由当前结果决定下一步。

## 内容场景

| 当前问题 | 可能路由 | 边界 |
|---|---|---|
| 选题通过后判断内容怎么做 | `/dbs-content` | 诊断内容，不补造素材 |
| 已有文稿需要共鸣检查 | `/dbs-resonate` | 给删改建议，不虚构受众反馈 |
| 逐字稿衔接或口播流畅度 | `/dbs-script-flow` | 只处理结构与表达 |
| 短视频开头 | `/dbs-hook` | 内容主体不足时先返回主体问题 |
| AI 味识别 | `/dbs-ai-check` | 只诊断，不把真实经历改成合成故事 |
| 对标账号 | `/dbs-benchmark` | 区分原稿事实、分析和推断 |
| 内容资产结构化 | `/dbs-content-system` | 先审计、后迁移，保留来源 |

## 事实门禁

- 示例必须标成 `模拟案例`、`合成案例` 或 `可追溯公开案例`。
- 未经本人确认的损失、收入、用户和社群结果不得进入示例。
- Skill 输出不能自动升级主张身份；证据状态仍由 `内容证据契约.md` 决定。
- 不自动发布、推送、同步或修改第三方资源。
