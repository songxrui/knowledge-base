# 内容证据契约

> 版本：1.0
> 生效日期：2026-07-16
> 适用范围：选题、研究、内容单元、草稿、产品说明、发布稿与复盘
> 事实源地位：内容生产中的主张身份、证据定位、数字使用和边界表达以本文件为准。其他文档只引用本契约，不复制维护状态定义。

## 1. 这份契约解决什么

内容系统必须把四件事分开：

1. 来源说了什么；
2. 证据实际支持什么；
3. 作者如何综合或设计；
4. 产品准备试什么。

结构整齐、作者知名、数据精确、案例动人，都不能替代证据身份。一个主张没有身份和边界时，只能留在缓冲区，不能进入正式内容单元、发布稿或产品承诺。

## 2. 唯一主张身份

每条可独立判断真假的句子只允许使用以下一种 `claim_status`。

| `claim_status` | 含义 | 最低证据 | 可以写 | 不能写 |
|---|---|---|---|---|
| `research-supported` | 某项研究在特定样本和任务中观察到结果 | 原始论文或权威数据库记录，含方法和定位 | “在该样本与任务中……” | “禁止写：科学证明对所有人都有效” |
| `historical-description` | 可由档案、原文或一手记录支持的历史描述 | 一手档案、原文或可核对版本 | “该作者在该版本中写道……” | 用历史描述证明方法有效 |
| `author-method` | 某位作者明确提出或采用的方法 | 作者原文、书中页码、课程原始材料 | “作者建议……” | “研究证明……” |
| `personal-fact` | 用户本人、账号后台或交易记录能够确认的事实 | 本人确认或原始记录；记录时间和口径 | “后台在该时间窗显示……” | 用未确认草稿补写经历和结果 |
| `inventory-snapshot` | 某一时点由目录或台账重建的库存事实 | 清单、生成时间、统计规则和重建命令 | “截至某日，按该规则计数为……” | 把快照写成长期固定资产量 |
| `editorial-inference` | 基于多个来源形成的编辑判断或解释 | 明确列出输入来源和推理链 | “据此可推断……” | 把推断改写成来源原话 |
| `product-hypothesis` | 等待真实使用、付费或交付数据检验的产品判断 | 假设、观测字段、推翻条件 | “当前假设是……” | “用户一定会……” |
| `experiment-parameter` | 为一次试运行预先设定的频率、阈值、价格或周期 | 参数所有者、采用日期、复盘日和停止条件 | “本轮先按……运行” | “最佳频率/科学阈值是……” |
| `blocked` | 来源不足、已撤稿、无法定位或与现有证据冲突 | 阻断原因 | “当前证据不足，暂不使用” | 进入事实陈述、案例或承诺 |

`claim_status` 只说明证据身份，不是质量评分。状态只能由新增证据和人工核验升级，不能因为文案更顺、引用更多或模型更自信而自动升级。

## 3. 来源等级

来源等级写在 `source_level`，与主张身份分开。

| 等级 | 来源类型 | 典型对象 | 使用限制 |
|---|---|---|---|
| `S1` | 一手研究、档案、后台、交易或本人确认 | 原始论文、作者原文、原始数据导出 | 仍需写样本、任务、口径和边界 |
| `S2` | 权威二手综合 | 系统综述、官方说明、严谨传记 | 不得替代可获得的一手定位 |
| `S3` | 普通二手解释 | 媒体、博客、课程转述 | 只能作线索或背景，关键主张需回源 |
| `S4` | 未定位摘录、模型生成、口耳相传 | 无页码书摘、无链接笔记、AI 草稿 | 不得支持事实主张 |
| `SX` | 撤稿、伪造、无法访问或身份错误 | 撤稿论文、错配作者、失效证据 | 主张进入 `blocked`，除非只讨论撤稿史 |

名人、畅销书、大学名称和精确数字不会自动提高来源等级。

## 4. 最小主张记录

每条关键主张至少包含以下字段：

```yaml
claim_id: LOS-001
claim_text: 一句话、可独立核验的判断
claim_status: research-supported
source_level: S1
source_title: 来源标题
source_author: 作者或机构
source_url_or_path: URL 或仓库相对路径
locator: 页码、章节、表格、图、段落或行号
published_at: YYYY-MM-DD 或年份
verified_at: YYYY-MM-DD
sample_or_record: 样本、任务、时间窗或数据口径
observed_result: 来源实际观察或记录到的结果
boundary: 不能据此推出什么
retraction_status: clear | retracted | corrected | unknown
usage: 当前使用位置
decision: keep | qualify | parameterize | remove | block
```

没有适用值的字段写 `not-applicable`；尚未核实写 `unknown`。不得为了填满 schema 猜测信息。

## 5. 精确定位规则

### 5.1 本地来源

至少写：仓库相对路径、行号或标题、文件哈希或版本日期。来源原稿与派生稿必须分开，不能让派生稿反向证明原稿。

示例：

```text
03-资源/素材库/人生操作系统-v3-01-元系统.md:23
```

### 5.2 网页与作者原文

至少写：页面标题、作者或机构、URL、页面内标题或可搜索短语、核验日期。只给域名或首页不算精确定位。

### 5.3 研究论文

至少写：论文标题、作者、年份、DOI 或数据库记录、实验/表格/结果段定位、样本与任务。若文章撤稿或更正，必须记录状态和日期。

### 5.4 后台与个人事实

至少写：平台或记录类型、统计时间窗、指标定义、原始记录位置、本人确认状态。截图数字、口头数字和草稿设想不得混为同一口径。

## 6. 数字契约

任何百分比、倍数、人数、金额、频率、周期和阈值都必须先回答：

1. 它是观察结果、库存快照，还是准备采用的参数？
2. 分母、样本、任务或时间窗是什么？
3. 来源能否定位到具体位置？
4. 能外推到谁、什么场景、多久？
5. 什么新证据会让它失效？

无法回答时，按以下顺序处理：删除伪精确数字；保留有价值的定性判断；必要时降级为 `experiment-parameter` 或 `product-hypothesis`；仍可能误导则设为 `blocked`。

### 6.1 六类高风险数字

| 数字 | 默认身份 | 何时可成为事实 |
|---|---|---|
| 发布频率 | `experiment-parameter` | 有发布台账后，已发生频率可成为 `personal-fact` |
| 复习间隔 | `experiment-parameter` | 只描述某研究任务时可为 `research-supported`，不可外推为通用最佳间隔 |
| 产品价格 | `product-hypothesis` 或 `experiment-parameter` | 有真实报价与交易口径后，已发生价格可为 `personal-fact` |
| 用户数 | `blocked`，直到后台或交易记录确认 | 有去重口径、时间窗和原始记录后为 `personal-fact` |
| 留存率 | `blocked`，直到定义分子、分母和窗口 | 有队列、窗口和原始记录后为 `personal-fact` |
| 停止阈值 | `experiment-parameter` | 它始终是决策参数，不因执行过一次变成科学规律 |

## 7. 实验参数记录

频率、价格、复习间隔、样本量、内容长度和停止阈值采用以下结构：

```yaml
parameter_id: EXP-CONTENT-001
parameter_name: 公众号发布频率
value: 1
unit: 篇/周
owner: 当前项目
adopted_at: 2026-07-16
review_at: 2026-08-16
rationale: 以现有产能启动一轮可观察试验
evidence_needed: 发布记录、完成耗时、质量退化、读者反馈
stop_or_change_rule: 连续两轮无法按证据门禁完成时，降低频率并复盘瓶颈
status: active-experiment
```

参数可以帮助行动，但不得用“黄金比例”“最佳实践”包装。复盘后可以保留、修改或停止，不能事后改写初始门槛。

## 8. 第一人称、案例与承诺

### 8.1 第一人称

- 只有本人确认或原始记录支持时，才写具体经历、收入、用户数、连续天数和结果。
- 未确认的草稿示例一律改成中性情境、编辑提示或待采集问题。
- “我会”“我准备”属于计划，不得改写成“我做过”“我发现”。

### 8.2 用户案例准入规则

案例至少需要：案例对象同意、起点、干预、时间窗、结果口径、其他可能解释。缺少任一关键项，只能写匿名问题情境，不能写结果案例。

### 8.3 产品承诺

行动建议可以承诺交付动作，不能承诺收入、增长、转化、康复、留存或身份变化。没有真实数据时，价格、用户规模和留存目标只能是实验参数或产品假设。

## 9. 写作使用规则

### 9.1 选题进入草稿前

- 有一个真实问题或可定位来源；
- 至少一个核心 `claim_id`；
- 写明当前最强反例或边界；
- 作者方法与研究事实没有混写；
- 需要试验的数字已登记为参数。

### 9.2 草稿进入发布前

- 每条关键事实能定位；
- 所有数字有样本、任务或数据口径；
- 第一人称和用户结果已确认；
- 撤稿来源命中数为 0；
- `blocked` 主张没有进入标题、正文结论、案例或 CTA；
- 发布频率、价格和停止阈值没有冒充普适规律。

### 9.3 发布后

发布数据只能增加 `personal-fact` 或更新实验参数，不能反向证明文章观点正确。传播、理解、使用、反例、购买和交付成本应分开记录。

## 10. 状态变更协议

状态变更必须记录：原状态、新状态、新证据、核验人、日期和影响位置。

允许的典型变更：

- `blocked` -> `author-method`：找到作者原文，但只支持作者确实这样主张；
- `blocked` -> `research-supported`：找到未撤稿的一手研究并补齐样本、任务与边界；
- `product-hypothesis` -> `personal-fact`：只能把已经发生的交易或使用记录升级为事实，不能把因果解释一并升级；
- `experiment-parameter` -> `experiment-parameter`：复盘后调整数值并保留旧版本；
- 任意状态 -> `blocked`：发现撤稿、错配、无法复现定位或个人事实未获确认。

禁止的变更：因为多个二手来源互相转述、文章发布、数据表现好、AI 判断可信或作者名气大而升级状态。

## 11. 与内容单元的关系

正式观点、案例和方案单元除通用字段外，至少增加：

- `claim_ids`
- `claim_status`
- `source_level`
- `source_locators`
- `boundary`
- `verification_state`

历史单元可以渐进补齐，但在补齐前不得标记为 `已核对`。`quality` 只描述内容完整度，不表示事实已验证。

## 12. 冲突处理

当文档之间出现冲突时：

1. 原始来源优先于摘要；
2. 可定位一手来源优先于二手转述；
3. 当前可重建清单优先于旧文档中的手写库存；
4. 已确认后台或交易记录优先于计划数字；
5. 本契约中的身份定义优先于其他内容生产文档；
6. 证据不足时选择较低状态，不做平均和猜测。

## 13. 最小审计输出

每次高风险内容审计至少留下：

- 审计范围与原文件哈希；
- 主张清单及处理决定；
- 来源定位与撤稿状态；
- 修改前后字符、段落和实质引用对比；
- 未解决项及阻断原因；
- 原始资源未改动证明；
- 差异审查和关键词扫描结果。

这份审计记录是可追溯性证据，不是给内容自评打分。
