# 内容单元字段规范

> 主张身份、来源等级、数字边界和状态变更统一遵循 `内容证据契约.md`。本文件只定义内容单元字段，不另行维护证据状态词表。

## 通用字段

每个内容单元必须包含以下字段：

- `id`
- `type`
- `title`
- `source_documents`
- `source_authors`
- `themes`
- `keywords`
- `status`
- `canonical`
- `version`
- `created_at`
- `updated_at`
- `relationships`

观点、案例和方案单元还必须包含：

- `claim_ids`
- `claim_status`
- `source_level`
- `source_locators`
- `boundary`
- `verification_state`

## 历史导入单元兼容字段

`02-内容单元库/UNIT-*.md` 中的 42 个历史导入单元使用较早 schema：`source`、`topics`、`created` 和 `quality`。在完成逐条迁移前，这些字段继续保留，不得为了格式统一而删除或改写正文。

历史导入单元至少必须补齐：

- `status`：统一使用 `待核对`、`已核对` 或 `deprecated`
- `source_status`：只允许 `linked` 或 `unresolved`
- `source_match`：可选；只允许 `direct`、`direct-with-drift`、`partial` 或 `synthesis`
- `canonical`：同一 ID 的当前对象为 `true`
- `updated_at`：最近一次治理日期

`source_status: linked` 表示原稿足以支持该单元的主要来源归属，不只是“磁盘上存在一个相关文件”。`direct-with-drift` 表示来源明确但摘要存在压缩或改写偏差；`partial` 和 `synthesis` 必须继续保持 `source_status: unresolved`。

`quality: A/B/C` 只表示内容完整度，不等于事实已验证。只有来源可定位、精确数字和第一人称事实完成核验后，才能把 `status` 改为 `已核对`。

## 类型字段

### 问题单元

- `question_text`
- `question_type`
- `user_stage`
- `applicable_topics`

### 概念单元

- `concept_definition`
- `concept_function`

### 观点单元

- `core_claim`
- `claim_scope`
- `why_it_matters`

### 案例单元

- `case_subject`
- `case_summary`
- `case_process`
- `case_result`

### 方案单元

- `target_problem`
- `solution_summary`
- `action_steps`
- `expected_result`

## relationships 写法

空关系统一写：

```yaml
relationships: []
```

存在关系时统一写：

```yaml
relationships:
  - type: 解释
    target: CON-20260602-001
    note: 用于定义判断边界
```
