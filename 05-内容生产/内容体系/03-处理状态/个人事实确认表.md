## 1. 当前状态

知识库中的旧选题池、脚本样例和规划稿包含年龄、学校、城市、交易损失、游戏经历、身体指标、连续发布、账号数据、社群用户和收入等第一人称材料。本轮没有取得本人逐条确认、原始记录或平台后台，因此这些材料统一为 `blocked`。

`blocked` 不表示内容必然错误，只表示当前不能把它写成事实、案例、标题数字、个人故事或产品证明。AI 不得根据相邻稿件、文件名、重复出现次数或“看起来合理”自动确认。

## 3. 确认记录模板

只有本人或授权记录维护者可以把状态改为 `confirmed`。

| personal_fact_id | 事实表述 | 类别 | 原始记录 | 时间窗/口径 | 本人确认 | 允许公开范围 | verified_at | status |
|---|---|---|---|---|---|---|---|---|
|  |  |  |  |  | yes/no | private/anonymous/public |  | blocked/confirmed |

确认一条事实不自动确认它的因果解释。例如，后台能确认连续发布，只能证明发布发生过，不能证明它导致涨粉、收入、身份变化或方法有效。

## 4. 写作接口

- `confirmed` 且允许公开：可以进入第一人称事实，但仍需引用 `personal_fact_id`。
- `confirmed` 但仅限私有：只能用于内部决策，不能进入对外草稿。
- `blocked`：改成中性问题、方法模板或待采访问题，不保留精确数字和结果。
- 用户案例：即使匿名，也必须满足同意、起点、过程、结果口径和替代解释。
- 发布前：扫描所有第一人称数字，并逐条回到本表；找不到记录即退回。

## 5. 历史文档处理

四份生产总控和旧选题池中的已填充第一人称示例保留为历史脚手架，不是事实库。读取这些文档时，只能复用结构，不能复用其中的人名化细节、数字、场景或结果。需要真实故事时，先在本表建立记录，再回到草稿写作。
