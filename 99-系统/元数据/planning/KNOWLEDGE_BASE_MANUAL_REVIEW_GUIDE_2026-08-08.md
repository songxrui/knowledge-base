# KnowledgeBase 人工审查大计划与阅读方向指示

## 1. 这份文档解决什么问题

这不是一次自动清理脚本的说明，也不是要求人把全库三千多篇 Markdown 从头读到尾的阅读清单。它规定人工如何判断：什么值得继续相信、什么只能作为资料、什么已经可以进入自己的知识和作品、什么必须回到原始来源、什么应该降级或停止使用。

当前知识库的主要风险不是“没有内容”，而是内容、来源、项目、生成物、索引和发布状态没有始终代表同一套事实。人工审查的目的，是把以下链条重新接起来：

```text
现实问题 → 原始资料 → 主张与解释 → 本人判断 → 行动/作品
    ↑                                      ↓
    └──────────── 反馈、反例与纠错 ←───────┘
```

人工审查的最终对象不是文件本身，而是文件正在影响的判断和行动。

本轮审查不授权：

- 批量删除、移动、重命名或格式化；
- 修改 `book-v7` 等冻结来源版；
- 把 AI 摘要升级成原始证据；
- 发布内容、同步第三方平台或修改凭据；
- 用“已审查”替代专业医学、法律或金融判断。

## 3. 核心审查原则

### 3.1 先看现实影响，再看文字质量

高风险健康、财务、法律、心理和 AI 能力预测，即使文字很短，也应优先于低风险长文。结构完整、语言流畅和引用很多，不代表结论可信。

### 3.2 先分事实、解释、经验和价值

每个重要段落都标注其命题类型：

| 命题类型 | 人工审查方式 |
|---|---|
| 事实 | 回到原始数据、原文、官方文件或可重复记录 |
| 机制模型 | 查模型的适用边界、竞争模型和反证 |
| 个人经验 | 保留第一人称范围，不推广成普遍规律 |
| 作者综合 | 明确是综合推断，而不是来源原话 |
| 价值判断 | 检查规范前提、受影响者和责任后果 |
| 产品假设 | 检查是否被本人使用或真实用户验证 |

### 3.3 AI 是审查助手，不是最终裁判

AI 可以提取主张、找重复、对照来源、生成反方问题和检查结构；人必须决定是否相信、是否采用、是否发布以及是否承担后果。

### 3.4 先建立可回滚记录，再做任何文件处置

任何移动、归档、合并和降级之前必须保留：原路径、目标路径、文件哈希、理由、依赖、引用关系和回滚方式。没有映射和基线，不执行批量操作。

## 4. 优先级算法

### 4.1 五维评分

每个待审文件从 0 到 3 评估五项：

| 维度 | 0 分 | 3 分 |
|---|---|---|
| 现实伤害 | 仅历史记录或低影响 | 会影响医疗、金融、法律、安全或关系决策 |
| 传播范围 | 个人草稿 | `canonical`、发布稿、模板或被多人复用 |
| 证据不确定性 | 原始官方材料或可重复数据 | 无来源、AI 派生、单一观点或过期来源 |
| 复用程度 | 一次性材料 | 被多个项目、卡片、书稿或脚本调用 |
| 状态矛盾 | 元数据一致 | `status: 待核对` 与 `canonical: true`、`quality: A` 并存 |

总分不是科学测量，只用于排序：

```text
P0：现实伤害、传播范围和证据不确定性中至少两项为高，或存在状态矛盾
P1：高复用/高风险，但尚未进入公开传播
P2：影响导航、维护、项目判断或版本一致性
P3：格式、命名、低价值重复和历史整理问题
```

任何 P0 文件在审查完成前不得进入发布、旗舰、教学或自动化流程。

### 4.2 当前首批队列

首批人工阅读不按字数排序，按以下顺序进入队列：

1. `05-内容生产/内容体系/02-内容单元库/` 中 `quality: A`、`status: 待核对`、`canonical: true` 的单元；
2. 健康、心理、营养、睡眠、成瘾和创伤相关卡片；
3. 标题含“真凶、必然、决定、基线崩塌、提升 X 倍”等强断言的文件；
4. `01-项目/meta-abilities/` 的 15 个 `blocked-claim-audit` 章节；
5. `99-系统/元数据/INDEX.md`、MOC、旧路径脚本和自动生成报告；
6. `05-内容生产/进行中/`、发布队列和待发布内容；
7. 被项目、书稿或自媒体内容引用的高风险资源；
8. `01-项目/` 中被依赖、构建、缓存和测试产物淹没的子目录；
9. 收件箱与超过保留期限的缓冲区；
10. 一般性卡片、低复用原子笔记和归档抽样。

第一批必须人工决定的样本包括：

- `04-知识/卡片/C1-1_多巴胺基线崩塌与修复.md`；
- `04-知识/卡片/topics/T2-01_肥胖的真凶是胰岛素.md`；
- `05-内容生产/内容体系/02-内容单元库/UNIT-001_多巴胺基线崩塌与修复.md`；
- `01-项目/meta-abilities/` 章节源；
- `99-系统/元数据/INDEX.md` 与当前权威入口。

## 5. 固定阅读顺序

### 阶段 0：权威入口和保护边界

固定阅读顺序：

1. `HOME.md`；
2. `SOURCE_OF_TRUTH.md`；
3. `KNOWLEDGE_MAP.md`；
4. `99-系统/元数据/planning/KNOWLEDGE_BASE_MISSION_V2_2026-08-08.md`；
5. `99-系统/元数据/planning/KNOWLEDGE_BASE_MAJOR_REPAIR_PLAN_2026-08-05.md`。

审查输出必须回答：

```text
当前权威入口：
当前冻结版本：
当前发布事实：
当前阻断事项：
索引与文件系统的冲突：
仍需核实的事实：
```

不要先读兴趣最高的长文。先读规则，是为了知道哪些内容不能被旧索引、生成稿或 AI 摘要覆盖。

### 阶段 1：资源层

对象：`03-资源/`。

逐文件检查：

- 作者、标题、日期、平台和原始链接是否齐全；
- 是否保留原文上下文和版本信息；
- 转录、摘要和 AI 总结是否被误标为原始资料；
- 作者观点、受访者观点和本人解释是否分开；
- 是否存在断章取义、二次转述和来源漂移；
- 来源是否过期、失效或已被新版替代；
- 该资源是否实际支持某个主张、项目或作品。

人工输出：来源等级、可引用命题、不可引用部分、被谁使用、保留理由和后续动作。

### 阶段 2：知识层

对象：`04-知识/`。

阅读顺序：标题 → 元数据 → 原始证据 → 核心主张 → 推理链 → 反例 → 行动建议 → 实际使用记录。

重点审查：

- 标题是否预设答案；
- 相关性是否被写成因果；
- 理论模型是否被写成生理事实；
- 个案、名人和单本书是否被用来证明普遍规律；
- 精确数字是否能定位原始研究；
- 心理、健康和社会问题是否被道德化；
- AI 推断是否被写成“研究已经证明”；
- 是否写出适用范围、反方证据和不可推出结论。

### 阶段 3：内容生产层

对象：`05-内容生产/`。

阅读顺序：选题 → 研究单元 → 进行中草稿 → 发布队列 → 已发布 → 发布数据。

人工必须确认：

- 第一人称故事确实由本人提供；
- 研究整理没有冒充实践经验；
- AI 贡献和本人判断可以区分；
- 标题的确定性不超过证据；
- 用户价值没有被提前宣称；
- “写完”没有被当作“验证过”；
- 发布后的失败、反例和反馈是否回流。

### 阶段 4：项目层

对象：`01-项目/`。

先三路分流：

```text
代码/依赖/构建产物 → 运行资产审查
项目说明/决策/假设 → 项目知识审查
实验结果/作品/用户反馈 → 现实验证审查
```

每个项目只需要先回答六个问题：

1. 解决谁的什么问题；
2. 最小可交付对象是什么；
3. 当前假设是什么；
4. AI 做了哪些工作；
5. 人做了哪些不可替代的判断；
6. 什么结果会导致继续、修改或停止。

任何代码、依赖或构建物的分离，都必须先完成路径映射、哈希基线、依赖确认、迁移演练、结果核验和回滚确认。

### 阶段 5：媒体与产品层

对象：`08-媒体与产品/`。

重点不是外观，而是对象是否真实存在、可使用并值得维护：

| 类型 | 必查问题 |
|---|---|
| 软件 | 能否运行、测试、维护并解决明确摩擦 |
| 游戏 | 是否真的可玩，核心循环是否成立，有无人工试玩记录 |
| 书稿 | 论点、来源、作者立场和章节顺序是否一致 |
| 图文/视频 | 是否有真实表达者责任，是否冒充亲历或专业意见 |

### 阶段 6：系统与索引层

对象：`99-系统/`。

阅读顺序：权威入口 → 元数据索引 → MOC → 脚本 → 自动报告 → 日志和第三方快照。

检查：

- 索引是否仍引用旧路径；
- 文件数量是否来自最新扫描；
- 脚本是否硬编码已废弃目录；
- 自动生成报告是否被当作当前事实；
- `canonical`、`status`、`quality` 是否冲突；
- 日志是否超过保留期限；
- 自动化是否保留人工批准、责任和纠错记录。

### 阶段 7：缓冲区与归档

缓冲区只按三类分流：有下一步转项目/草稿，有长期复用价值转知识层，无后续价值进入归档或删除候选。归档只抽样检查权威版本、活跃引用和原始证据恢复需求，不进行全量重读。

## 6. 单文件审查 SOP

### 6.1 阅读前

记录：路径、大小、最后修改时间、哈希、所属层、引用者、当前状态、是否冻结、是否被发布或自动化使用。

### 6.2 阅读中

按以下五层分色或标记：

| 层 | 标记内容 |
|---|---|
| 事实 | 可以被外部来源或记录核对的句子 |
| 解释 | 对事实的机制、因果或心理解释 |
| 经验 | 本人亲历、使用、观察和失败 |
| 行动 | 建议、实验、产品决策或发布承诺 |
| 责任 | 受影响者、风险承担者和不可逆后果 |

### 6.3 阅读后

逐项回答：

1. 这份文件要解决什么问题？
2. 核心主张是什么？
3. 哪些内容是事实，哪些是解释？
4. 来源是否能定位到原文？
5. 是否存在伪精确数字？
6. 是否把相关性、模型或个案写成普遍因果？
7. 是否存在反方、反例和文化边界？
8. 哪些内容来自本人亲历？
9. AI 做了什么，人做了哪些选择？
10. 是否亲自使用、测试或验证？
11. 他人相信后可能受到什么伤害？
12. 最终应保留、升级、降级、拆分、归档还是阻断？

## 7. 审查记录模板

每个 P0/P1 文件至少记录以下字段：

```yaml
file:
review_date:
reviewer:
layer:
source_origin:
current_status:
current_canonical:
risk_level:
main_claims:
claim_types:
evidence_quality:
counterevidence:
personal_experience:
reality_test:
ai_contribution:
human_judgment:
known_limits:
decision:
next_action:
stop_condition:
```

重大主张还要进入主张审查台账：

| 字段 | 要求 |
|---|---|
| 主张 | 使用可核查的陈述句，不写宣传口号 |
| 命题类型 | 事实、机制、经验、价值、产品假设或推测 |
| 来源 | 原始 URL、论文、书籍、官方文件或个人记录 |
| 证据等级 | 原始研究、综述、官方框架、个人经验或 AI 派生 |
| 反证 | 至少记录一个限制、反例或竞争解释 |
| 适用范围 | 人群、情境、时间和条件 |
| 不可推出 | 明确禁止的扩大解释 |
| 处置 | 保留、软化、补证、降级、阻断或归档 |

## 8. 处置决策规则

| 情况 | 默认动作 |
|---|---|
| 来源清楚、命题有限、状态一致 | 保留 |
| 有价值但来源、边界或人工判断不足 | 降级并补证 |
| 原始资料与解释混在一起 | 拆分 |
| 多份文件表达同一事实集 | 指定一个权威入口，其余链接或归档 |
| 健康、金融、法律或安全主张无法核验 | 阻断发布和复用 |
| 个人经验被写成普遍结论 | 改为第一人称并保留边界 |
| AI 生成但无人使用、测试或承担 | 保留为候选，不得进入 `canonical` |
| 历史有效但不再影响当前行动 | 归档 |
| 空模板、精确重复、无来源且无引用者 | 删除候选，等待人工确认 |

“重写”不是默认动作。优先保留原始证据和真实经历，只修正命题边界、来源状态和元数据。

## 9. 人工与 AI 的分工

AI 可以执行：

- 文件清单和引用关系提取；
- 重复标题和状态冲突扫描；
- 句子级主张候选抽取；
- 来源缺口和反方问题生成；
- 目录、路径和索引对照；
- 根据人工决定生成候选修订稿。

人必须执行：

- 判断什么是事实；
- 判断自己的经验是否足以支持表述；
- 阅读关键原始来源；
- 决定是否相信、使用、发布或归档；
- 亲自运行、使用、游玩和检查产品；
- 承担错误传播和不可逆行动的后果。

AI 输出必须保留为“审查候选”，不能直接写入审查结论。

## 10. 批次执行规则

每个审查批次只处理一个主题和一个层级，例如“健康卡片中的高风险主张”，不要同时处理目录迁移、内容改写和发布。

批次流程：

```text
锁定文件清单和哈希
→ 人工阅读三份代表样本
→ 确认判定标准
→ AI 做候选抽取和对照
→ 人工逐项确认
→ 记录处置决定
→ 抽查修改前后差异
→ 才能进入下一批
```

任何批量移动或删除前必须另行生成映射表和回滚方案。本指导文档本身不授权这些动作。

## 11. 停止条件

出现以下任一情况，立即停止扩大审查范围：

- 路径迁移无法逐项解释；
- 原始证据可能被覆盖；
- 高风险主张只有免责声明而没有来源；
- `canonical` 与 `待核对` 冲突仍未处理；
- 人工判断记录不足；
- 审查退化为格式整理；
- 只能增加标签，无法改变保留、降级或阻断决定；
- 审查者的注意力和判断质量明显下降。

停止不是失败，而是防止审查本身变成新的自动化幻觉或生产力暴政。

## 12. 输出物

后续执行本计划时，审查记录应分别存放为：

1. `MANUAL_REVIEW_QUEUE_2026-08-08.csv`：路径、优先级、风险、状态冲突和当前结论；
2. `MANUAL_REVIEW_DECISIONS_2026-08-08.md`：每批审查的保留、升级、降级、拆分、归档和阻断决定；
3. `CLAIM_REVIEW_LEDGER_2026-08-08.csv`：主张、来源、反证、范围和不可推出结论；
4. `REALITY_FEEDBACK_INDEX_2026-08-08.md`：项目、产品、内容与真实使用结果的回流索引。

这些文件记录审查事实和决定，不得把“计划”“候选”或“待核对”写成“已经修复”。

## 13. 验收标准

人工审查计划可交付的最低标准：

- 覆盖 `HOME.md`、`SOURCE_OF_TRUTH.md`、`KNOWLEDGE_MAP.md`、使命规范和旧大修计划；
- 首批 P0/P1 文件有明确人工决定；
- `quality: A + status: 待核对 + canonical: true` 的冲突全部进入队列；
