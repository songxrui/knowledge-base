# KnowledgeBase 90 天升级计划

## 目标

把知识库从“存储大量材料”升级为“每周稳定产出判断、实验和作品”的闭环系统。

## 成功指标

| 指标 | 当前基线 | 90 天目标 |
|---|---:|---:|
| 根目录临时文件 | 0 | 持续为 0 |
| 收件箱平均停留 | 新建 | 少于 7 天 |
| 进行中草稿 | 需继续审计 | 不超过 12 个 |
| 无来源精确断言 | 未建立统一台账 | 新增内容为 0 |
| 发布记录 | 0 | 至少 12 条 |
| 发布后数据记录率 | 无基线 | 100% |
| 每周形成的常青笔记 | 无稳定节奏 | 1–3 条 |
| 旧版本在活跃区的数量 | 已完成首轮清理 | 每主题最多 1 个当前版 |

## Phase 1：架构与事实层，Day 1–14

- 收敛根导航与事实源。
- 建立收件箱、项目、内容、资源、知识、发布、归档的职责边界。
- 把错位项目从 `进行中` 移入 `01-项目`。
- 修复 MOC 自动重建脚本。
- 为归档操作建立 manifest。

完成标准：任何文件都能用一句话解释“为什么在这里”。

## Phase 2：信息与学习效率，Day 15–35

- 所有新增来源回答“服务哪个问题”。
- 学习笔记加入无提示回忆、反例和行动字段。
- 选择 10 个高频主题，把重复摘录压缩成原子洞察。
- 对健康、财富和研究类精确断言建立来源台账。

完成标准：随机抽查 20 条成熟笔记，来源可定位率达到 90%。

## Phase 3：内容创作闭环，Day 36–65

- 每周选择一个真实问题。
- 复用来源、原子笔记和主题卡完成一篇主内容。
- 派生平台版本，但不复制维护多份事实。
- 发布后同步数据表、已发布目录和复盘记录。

完成标准：连续 4 周完成“问题 → 发布 → 数据 → 沉淀”。

## Phase 4：低质量内容治理，Day 66–90

- 扫描空壳、精确重复、旧版本、模板残留和无来源精确断言。
- 高置信度垃圾删除；有潜在价值但低置信度的内容归档。
- 每类内容保留一个当前版、一个来源台账和必要历史版本。
- 删除无法重建价值、只记录单次会话的过期报告。

完成标准：活跃区不存在 `tmp`、`final2`、空模板和已被替代副本。

## 每周检查表

- [ ] 收件箱清空。
- [ ] 进行中草稿没有超过 30 天无动作。
- [ ] 新增精确断言都有来源。
- [ ] 至少完成一次无提示回忆。
- [ ] 至少发布或验证一个观点。
- [ ] 发布数据已经记录。
- [ ] 一个旧结论被修正、限制或删除。

## 内容质量门禁

新增大文档、批量编辑或归档迁移完成后运行：

```powershell
pwsh -NoProfile -File '99-系统\脚本\audit_content_quality.ps1' -Root 'D:\KnowledgeBase'
```

P0 必须为0。P1 的新增命中必须在批次记录中说明修复、接受或归档决定。规则和误报边界见 `99-系统/元数据/inventory/CONTENT_QUALITY_GATE_RULES.md`。

## 停止规则

- 不为“未来可能有用”批量导入资料。
- 不为每次任务创建新框架文件。
- 不在没有真实反馈前扩建内容系统。
- 不让 AI 生成第一人称故事或不可核验数字。
- 不把阅读、划线和收藏计为学习完成。
