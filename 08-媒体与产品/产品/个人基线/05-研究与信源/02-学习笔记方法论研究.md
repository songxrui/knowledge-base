# 学习笔记方法论研究

> 研究日期：2026-07-15。结论不追求选出唯一流派，而是明确每套方法负责什么、不能证明什么，以及怎样进入本产品。

## 核心结论

最稳妥的分工是：

- PARA 管“东西放哪里”；
- CODE 管“信息怎样流向表达”；
- Luhmann 与 Ahrens 管“长期知识单元怎样连接”；
- McKinsey 与 Minto 管“问题怎样拆、结论怎样表达”；
- 提取练习、自我解释、生成和间隔练习管“人是否真的学会”。

把这些方法揉成一个万能模板，会同时损害来源准确性和使用效率。

## 一、Luhmann 卡片箱：重点是连接结构

### 可由史料支持的部分

Johannes F. K. Schmidt 基于 Bielefeld 的卢曼档案指出，卢曼卡片箱包含阅读结果、自己的论点、概念和问题；其创造性依赖四个要素：固定地址与编号、可在任意位置分支、内部引用、关键词索引与独立书目装置。[Bielefeld 研究](https://www.uni-bielefeld.de/fakultaeten/soziologie/forschung/luhmann-archiv/pdf/jschmidt_niklas-luhmanns-card-index_-sociologica_2018_12-1.pdf)

卢曼 1981 年德文原文 [Kommunikation mit Zettelkästen](https://ckrybus.com/static/papers/luhmann1981.pdf) 进一步描述：

- 固定地址比预先建立完整主题层级更重要；
- 新卡可以在任何旧卡后分支生长；
- 多重引用解决一个想法属于多个语境的问题；
- 关键词索引只负责少数入口；
- 书目卡和内容卡分开，并互相链接；
- 卡片箱的价值来自连接网络，而不是单张卡的“高质量”。

### 不能倒推的部分

- “一卡一念”不是卢曼明确制定的普遍法则；
- 卡片箱没有被实验证明是所有学习者的最佳方法；
- 双链数量、图谱密度和文件数不能代替思考质量；
- 卢曼为终身理论项目设计的系统，不应原样复制给七天行动实验。

### 对本产品的取舍

保留固定 ID、明确关系和独立来源台账。放弃为了“像卢曼”而制造大量碎卡和链接。

## 二、Sönke Ahrens：把卡片箱变成写作工作流

[Sönke Ahrens 作者页](https://www.soenkeahrens.de/en/takesmartnotes) 把方法面向学生、研究者和非虚构写作者重新组织，强调笔记系统服务阅读、思考和写作。

当前锁定的作者页没有列出“临时、文献、长期、项目”四类笔记，因此本研究不把这组分类归给 Ahrens。若要使用，必须补书中页码或作者明确说明，也不能标成卢曼原制。

本产品采用三条：

1. 长期主张用自己的话写，并能脱离原上下文理解；
2. 来源摘录、长期主张和项目装配包分开；
3. 笔记在写作中形成，而不是“先把知识库建完再开始输出”。

## 三、McKinsey 与 Minto：不是一种统一“笔记术”

### McKinsey 公开的七步问题求解

[McKinsey 七步流程](https://www.mckinsey.com/capabilities/strategy-and-corporate-finance/our-insights/how-to-master-the-seven-step-problem-solving-process) 可压缩为：

1. 定义问题；
2. 用逻辑树拆解；
3. 按影响和可推动性排序；
4. 建立工作计划；
5. 先做简单分析，再使用复杂工具；
6. 综合发现，回答“所以怎样”；
7. 推动行动并暴露假设和不确定性。

这是一套问题求解流程，不是一套官方统一笔记格式。

### Minto 金字塔

[McKinsey 对 Barbara Minto 的官方访谈](https://www.mckinsey.com/alumni/news-and-events/global-news/alumni-news/barbara-minto-mece-i-invented-it-so-i-get-to-say-how-to-pronounce-it) 给出三条核心规则：

- 上层必须概括下层；
- 同组内容必须在逻辑上同类；
- 同组内容必须按逻辑顺序排列。

MECE 是分组检查，不是事实正确性的保证。产品应当先自下而上检查证据，再自上而下表达结论。

### 对本产品的取舍

- 选题前先写统领问题；
- 对复杂问题至少尝试两种拆法；
- 只研究高影响、可推动的分支；证据缺口排序是本产品的编辑补充，不归给 McKinsey；
- 文章先给受材料支持的结论，再给论据和证据；
- “空—雨—伞”可作为事实、解释、行动的编辑器综合，但不冒充 McKinsey 官方标准。

## 四、“费曼学习法”：名称需要辨伪

可定位的归因是：Scott H. Young 在 2011 年发布了题为 [Learn Faster with the Feynman Technique](https://www.scotthyoung.com/blog/2011/09/01/learn-faster/) 的教学文；他在 [2024 年回顾](https://www.scotthyoung.com/blog/2024/03/26/5-keys-feynman-technique/) 中称这是自己提出的学习建议，并明确说只松散借鉴 Richard Feynman。

这两页不能证明 Feynman 本人从未使用类似练习，但足以说明：网络固定步骤不应直接写成“费曼本人发明”。James Gleick 笔记本说法在补入书中页码前不用于本产品归因。

因此本产品不用“费曼本人发明且科学验证”这类表述，而把它拆成可研究的机制：

- 从记忆生成解释；
- 暴露卡点；
- 回查来源纠错；
- 用更简单语言重新组织；
- 必要时用例子和类比测试迁移。

## 五、第二大脑：面向行动组织，不替代学习

Tiago Forte 的 [Building a Second Brain](https://fortelabs.com/blog/basboverview/) 用 CODE 描述 Capture、Organize、Distill、Express；[PARA](https://fortelabs.com/blog/para/) 用 Projects、Areas、Resources、Archives 按行动性组织材料。

其 [Progressive Summarization](https://fortelabs.com/blog/progressive-summarization-iii-guidelines-and-principles/) 有一个经常被忽略的原则：不要把每份材料一次处理到最深层。只在材料重新进入真实项目时继续压缩，让注意力成本与复用价值匹配。

本产品的边界：

- PARA 解决检索和职责，不证明记忆形成；
- CODE 解决从输入到表达的流程，不证明结论正确；
- “共鸣”适合第一次筛选，不足以升级事实主张；
- 第二大脑必须服务当前问题，不能成为推迟输出的基础设施项目。

## 六、学习科学：真正的学习动作

### 提取练习

Roediger 与 Karpicke 的实验比较重复学习与无反馈自由回忆：短延迟下重复学习占优，2 天和 1 周的延迟测试中，先前提取带来更好的保持。[Test-Enhanced Learning](https://doi.org/10.1111/j.1467-9280.2006.01693.x)

这支持“关闭资料后尝试回忆”，不支持把搜索笔记称为提取练习。错误答案需要随后对照和反馈。

### 自我解释

Chi 等人研究学生学习力学例题时的自我解释，理解更好的学习者更常解释步骤与原理的关系，也更准确监控自己不理解的地方。[Self-Explanations](https://doi.org/10.1207/s15516709cog1302_1)

对本产品，自我解释必须回答 why、how、条件、因果和与旧知识的关系，而不是把笔记写长。

### 生成效应

先尝试生成答案通常比直接阅读更有利于记忆，但生成不保证答案正确，也不自动形成复杂迁移。因此流程必须是“先生成，再核对，再纠错”，不能停在自信解释。

参考：[Slamecka & Graf 1978](https://doi.org/10.1037/0278-7393.4.6.592)、[Generation Effect Meta-analysis](https://doi.org/10.3758/BF03193441)。

### 间隔练习

Cepeda 等人的元分析支持分散练习，但最佳间隔会随目标保持时间和材料变化。[Distributed Practice](https://pubmed.ncbi.nlm.nih.gov/16719566/)

因此 `2、7、30 天` 只能是产品的默认操作假设，不能写成研究证明的通用最优安排。

## 七、整合后的信息对象

| 对象 | 必需字段 | 主要职责 |
|---|---|---|
| `Question` | 决策、范围、完成标准、当前假设、推翻条件 | 限定研究 |
| `Source` | 作者、标题、日期、URL/路径、定位、来源类型 | 保存出处 |
| `Evidence` | 支持/反驳哪个主张、方法、限制、强度 | 约束论断 |
| `Claim` | 一句话判断、自己的推理、证据、反证、边界、状态 | 长期复用 |
| `RetrievalAttempt` | 问题、闭卷回答、置信度、纠错项、日期 | 证明是否学会 |
| `Relation` | 起点、终点、关系类型、理由 | 形成可解释网络 |
| `ProjectPacket` | 交付物、当前问题、选用主张、证据、下一步 | 临时装配 |
| `Expression` | 受众、统领思想、结构、引用、不确定性、反馈 | 对外表达 |

对象不必一一对应文件。低价值捕捉可以是项目中的一行，高复用 Claim 才值得独立成页。

## 八、适用于本产品的学习笔记 SOP

1. 先写这次学习要回答的具体问题。
2. 不看资料，写出当前解释和最不确定的三处。
3. 阅读时只捕捉能支持、反驳或限定该问题的材料。
4. 关闭资料，再写一遍解释。
5. 对照原文逐项纠错，保留错误痕迹和变化原因。
6. 形成一个带来源、反证和边界的 Claim。
7. 只建立有明确理由的 `supports`、`contradicts`、`qualifies`、`depends-on` 或 `example-of` 关系。
8. 把 Claim 装配进当前内容或实验，而不是等待知识库“完成”。
9. 用真实问题、作品或延迟回忆检查是否能调用。
10. 反馈不支持时修改 Claim，不修改评价标准来保护旧结论。

## 九、主要反模式

- 把收藏、划线、重读和搜索笔记当成学会；
- 把“一卡一念”执行成没有上下文、证据和边界的碎片；
- 用标签数、双链数和图谱密度作为知识质量指标；
- 把金字塔的整齐误当成事实正确；
- 先生成解释，却不回查来源纠错；
- 对每份材料一次性做完整渐进式摘要；
- 把作者工作流和成功故事升级为认知科学规律；
- 把项目草稿、来源摘录、长期主张和发布稿混成同一种笔记。
