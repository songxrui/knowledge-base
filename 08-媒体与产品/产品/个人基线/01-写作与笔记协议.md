# 写作与笔记协议

这套协议吸收 Dan Koe 的问题驱动、短内容测试、长内容建构和项目产品化方法，但不复制他的绝对化口吻、身份攻击、宇宙化包装或个人创业经验的普适化表达。完整规则以 [[90-内部治理/02-内容与笔记规范]] 为准。

## 方法来源与取舍

- Dan Koe 方法依据：`03-资源/创作者素材/Dan-Koe/`、官网文章和本地两本书正文，身份为 `E2 author-method`。
- 永久笔记依据：Luhmann 档案与 Ahrens 的写作化解释。固定 ID、来源和关系优先于“一卡一念”的教条。
- 问题与表达依据：McKinsey 七步和 Minto 金字塔。事实、解释与下一步动作分开，但不把编辑器综合冒充官方笔记术。
- 来源与行动依据：CODE/PARA。它们负责流转和路由，不负责证明记忆或事实。
- 学习依据：提取、生成、自我解释和纠错。搜索笔记不算闭卷提取。

这里吸收的是方法，不继承作者的结论。每条产品知识仍需通过本产品的来源等级与升级门禁。

## 一、内容架构

长期产品按四层生长：

1. **世界观**：解释为什么旧理解不足，但不把隐喻包装成定律；
2. **方法论**：给出判断模型，写清适用与失效条件；
3. **项目**：让模型进入一次有限实验；
4. **产品**：把反复有效的模型、协议和案例组合成可交付系统。

工具、平台和具体软件属于可替换层。问题、判断模型和验证协议属于常青层。

## 二、单篇内容骨架

每篇只处理一次认知转变，并使用主张台账约束结论强度：

1. 一个具体问题；
2. 这个问题造成的可观察代价；
3. 现有解释为什么不够；
4. 一个有边界的新模型；
5. 一项可执行动作；
6. 保留、修改或放弃模型的证据。

没有真实经历时使用来源或公开事实，不补写故事。没有结果时写“准备验证”，不写“我发现它有效”。

短内容可以测试问题和表达，不能用互动表现证明观点正确。长内容负责完整论证、来源、反例和行动协议。

## 三、信息密度

密度不是塞进更多知识点。一个段落至少完成一项工作：

- 让问题更具体；
- 解释一个必要概念；
- 提供证据或反例；
- 改变下一步行动；
- 写清边界或不确定性。

删掉后不影响上述五项的段落，默认删除或移入来源笔记。

表达优先使用可观察语言：

- “提高执行力”改为“连续七天在约定时间开始十分钟”；
- “改善注意力”改为“记录中断次数与恢复所需时间”；
- “建立系统”改为“写出触发条件、默认动作、停止条件和复盘日期”。

具体不等于伪精确。数字没有记录或来源时，不使用数字制造可信度。

## 四、永久笔记格式

一张笔记只保留一个可独立调用的判断：

```markdown
# 判断名称

## 身份
- claim_id:
- status:

## 一句话
这个判断解决什么问题。

## 来源
- 路径或公开来源
- 证据等级：E1-E5

## 我的重述
不用原文句式，重新搭建推理。

## 与常识的冲突
常见理解是什么，为什么不足。

## 边界
在什么条件下不成立。

## 行动接口
明天能执行的一个动作。

## 验证信号
什么结果会保留、修改或推翻它。

## 闭卷检查
- 不看资料时我的解释：
- 对照来源后的错误与遗漏：

## 关系
- depends-on
- supports
- contrasts-with
- qualifies
- composes-with
```

## 五、发布门禁

- 每个第一人称事实能由本人确认；
- 每个精确数字有记录或来源；
- 外部作者观点没有伪装成个人原创；
- 模型与隐喻没有伪装成科学定律；
- 至少写出一个反例或失效条件；
- 核心判断有 `claim_id`，或明确标注为待登记假设；
- 文章只承诺材料能够支持的结果；
- 一篇文章不同时承担入门、进阶、销售和完整课程四种任务。
