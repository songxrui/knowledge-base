# 自动化优化与质量重构计划

## 目标

建立一套默认无人值守、本地运行、可审计、可回滚的维护系统，持续完成 `个人基线` 的盘点、整理、结构校验、来源核验、低风险修复、内容质量诊断、候选重构和验收报告。

这里的“无需人工干涉”不是让 AI 自由改写或替人决定，而是：

- 确定性检查和机械修复自动完成；
- 有证据约束的语义优化自动生成候选并自动复核；
- 无法证明安全的内容进入隔离区，不阻塞其他任务；
- 只有真实性、证据升级、高风险建议、删除、发布和商业决策需要人工确认；
- 没有确认时，系统保持原文和当前版本，不猜测、不补故事、不对外行动。

## 一、当前基线

当前产品已经具备：

- 用户层、研究层和治理层分离；
- `E1-E5` 证据身份与 35 条主张台账；
- Dan Koe 选题、写作、素材、产品化研究；
- Luhmann、Ahrens、McKinsey/Minto、Feynman、Forte 与学习科学研究；
- 五道门、状态向量、证据合同和七天运行协议；
- Wiki 链接、相对路径、表格、编码和脚手架扫描基线；
- `0.2.0-alpha` 版本事实与“真实运行为 0”的明确边界。

当前缺口不是继续增加理论，而是把已有规则变成稳定执行的本地维护流水线。

## 二、不可违反的系统边界

### 允许全自动执行

- 文件清单、哈希、字数、段落、链接和引用统计；
- Wiki 链接、本地路径、外部 URL 状态检查；
- Markdown 表格列数、空文件、BOM、尾随空格和编码检查；
- `claim_id` 格式、唯一性、引用存在性和孤儿主张检查；
- 证据等级、状态枚举、合同字段和版本字段一致性检查；
- 明确的旧路径替换、失效镜像替换和格式规范化；
- 自动索引、来源地图、导航和机器报告重建；
- 重复段落、过期副本、孤立文件和职责错放候选识别；
- 不改变语义的标题层级、列表、空行和表格修复；
- 对每次修改执行前后哈希、抽样差异和回归检查。

### 允许自动生成，但只能进入隔离区

- 论证缺口修复建议；
- 过强主张的降级版本；
- 重复内容的合并候选；
- 长文结构重排候选；
- 基于已有 `claim_id`、Evidence 和 Source 的内容装配稿；
- Dan Koe 风格框架的结构适配稿；
- 去 AI 味、降口号、补边界和增强可执行性的编辑候选；
- 旧稿到新 schema 的迁移候选；
- 来源不足、事实冲突和无法定位主张的阻断报告。

候选默认进入 `08-媒体与产品/产品/个人基线/00-缓冲区/自动化候选/`，不得直接覆盖正式正文。

### 必须人工确认

- 第一人称经历、身份、收入、成绩和个人事实；
- 用户案例、用户反馈和真实运行数据；
- 医疗、心理、法律、投资、营养和安全建议；
- 将 `E3/E4/E5` 升级为成熟产品知识；
- 删除非生成文件或不可恢复内容；
- 修改定价、承诺、退款、社群权益和产品定位；
- 发布、推送、发消息、创建外部任务或修改第三方资源；
- 无法由规则区分的互相冲突版本。

人工不响应时，系统必须选择“保留、隔离、报告”，不能选择“猜测、覆盖、发布”。

## 三、自治等级

| 等级 | 能力 | 写入范围 | 是否需要人工 |
|---|---|---|---|
| `L0 观察` | 全库盘点、质量诊断、生成报告 | 只写系统报告 | 否 |
| `L1 机械修复` | 格式、路径、枚举、索引、确定性链接修复 | 正式文件白名单 | 否 |
| `L2 受约束优化` | 基于来源和 schema 的局部语义修复 | 先写缓冲区，通过回归后可自动晋级低风险项 | 默认否，冲突时需要 |
| `L3 内容装配` | 从已核主张装配文章、协议和产品候选 | 只写缓冲区 | 发布前需要 |
| `L4 外部行动` | 发布、收费、通知、删除、外部资源变更 | 禁止自动执行 | 必须需要 |

首个稳定版本只实现 `L0-L2`。`L3` 在来源与质量门禁稳定后启用，`L4` 永久保持人工批准。

## 四、目标架构

```text
原始文件与来源
    ↓
资产清单与 SHA-256 基线
    ↓
结构/链接/编码/schema 扫描
    ↓
主张—来源—证据一致性审计
    ↓
内容质量与职责路由诊断
    ↓
风险分类：自动修复 / 隔离候选 / 人工阻断
    ↓
最小差异修改或候选生成
    ↓
链接、结构、信息密度、来源、版本回归
    ↓
差异报告、失败回滚、下一批任务队列
```

## 六、八个实施工作包

## WP0：锁定策略与基线

### 动作

1. 生成当前文件、大小、字符、段落、链接、引用和哈希清单。
2. 定义正式写入白名单、保护路径和冻结路径。
3. 把 `SOURCE_OF_TRUTH.md`、主张台账、合同 schema 和真实运行目录设为强保护对象。
4. 定义“生成文件”“正式正文”“原始来源”“运行事实”的不同处理规则。
5. 记录当前 Git 状态，不能把未跟踪文件误判为可删除临时文件。

### 验收

- 同一输入重复生成相同 manifest；
- 每个正式文件有唯一哈希和职责；
- `book-v7`、真实运行和原始来源不在自动语义写入范围；
- 所有后续脚本都必须先读取 policy 与 manifest。

## WP1：只读质量审计引擎

### 动作

1. 校验 Wiki 链接、相对路径和本地来源定位。
2. 校验外链状态，并区分成功、访问受限、环境超时和明确失效。
3. 校验 Markdown 表格、标题层级、代码围栏、BOM、空文件和尾随空格。
4. 校验 `claim_id` 唯一性、状态枚举、证据等级和使用位置。
5. 校验合同 schema 在接口表、运行模板、每日记录和复盘之间一致。
6. 扫描脚手架、占位符、伪评分、无来源精确数字和虚构案例信号。
7. 输出机器可读 JSON 与人类可读 Markdown 报告。

### 验收

- 对已知坏样本能稳定报错；
- 对当前已验证文件不产生误报性自动修改；
- 每条问题包含文件、行号、规则、严重度和建议动作；
- 网络不可达不能自动等同于死链。

## WP2：确定性安全修复器

### 动作

1. 只实现结果可确定、差异可验证的修复规则。
2. 每条规则提供 dry-run、目标文件数、预计差异和撤销信息。
3. 一次只处理一种规则，限制最大文件数和最大字符变化。
4. 修改后立即计算新哈希，并重跑相关检查。
5. 任一门禁失败，恢复本批次文件，不继续下一条规则。

首批可自动修复：

- 尾随空格和 BOM；
- 明确失效的旧路径；
- 唯一可确定的枚举漂移；
- Markdown 表格分隔列数；
- 自动索引与来源导航；
- 已验证的新 URL 替换失效镜像；
- schema 中缺失但可从唯一事实源恢复的字段。

### 验收

- dry-run 与实际差异一致；
- 修复后问题数下降，其他指标不退化；
- 不允许整段重写；
- 不触碰白名单外文件；
- 连续两次运行第二次产生零差异，即满足幂等性。

## WP3：主张与来源治理自动化

### 动作

1. 从产品正文提取 `claim_id` 引用并与台账双向核对。
2. 识别未登记主张、孤儿主张、无使用位置主张和重复主张。
3. 检查 `E1/E2` 是否有作者、标题、URL 或本地路径和定位。
4. 检查 `E3/E4/E5` 是否被误写成事实、承诺或普遍因果。
5. 检查作者方法、研究结果、历史描述和产品假设是否混级。
6. 对来源不足的句子生成“降强度、补来源、移入待核”三类候选。
7. 只有精确来源存在且身份不变时，允许自动补齐定位格式。

### 验收

- 所有正式产品主张都能回到台账或明确标记为待登记；
- `E1/E2` 精确定位覆盖率达到 100%；
- `E4/E5` 不进入产品效果承诺；
- 自动化不能提升证据等级；
- 来源冲突时保留双方并阻断晋级。

## WP4：笔记与信息对象重构

### 动作

1. 按 `Question / Source / Evidence / Claim / RetrievalAttempt / ProjectPacket` 识别信息对象。
2. 检查来源摘录、长期主张、项目装配和运行记录是否混放。
3. 为缺少固定 ID、来源、边界或行动接口的成熟笔记生成迁移候选。
4. 识别只做摘要、不含闭卷生成和纠错的学习笔记。
5. 识别孤立笔记、重复概念和无理由链接。
6. 自动建议 `supports / contradicts / qualifies / depends-on / example-of` 关系，但不自动写入无法由正文证明的关系。
7. 项目结束后只归档 ProjectPacket，不复制成第二套长期知识。

### 验收

- 正式信息对象类型可判定；
- Source、Evidence 和 Claim 不再互相冒充；
- 学习型笔记至少包含提取、对照和纠错接口；
- 自动迁移不减少来源、边界和上下文；
- 不以链接数量、卡片数量和图谱密度作为质量分数。

## WP5：内容质量提升引擎

### 六个检查维度

1. **真实性**：是否出现无来源事实、虚构经历、伪案例和过强因果。
2. **证据性**：核心判断是否有 claim、来源、反证和适用边界。
3. **结构性**：统领问题、核心判断、论据分组和行动是否一致。
4. **信息密度**：是否重复、空泛、堆概念或用口号替代材料。
5. **可执行性**：是否给出条件、动作、记录、停止和复盘接口。
6. **表达自然度**：是否模板句过多、身份攻击、伪洞察、机械排比和 AI 腔明显。

### 自动处理策略

- 事实错误风险：阻断，不自动润色掩盖；
- 来源缺失：生成待核清单，不补假引用；
- 论证过强：自动生成降强度候选；
- 重复段落：生成合并候选，并保留全部独有信息；
- 结构混乱：生成大纲映射，不直接搬段；
- AI 腔：做局部最小改写，禁止把具体内容改成安全空话；
- 缺行动接口：只能从现有协议和证据合同复用，不能发明通用建议；
- 第一人称材料缺失：改成客观说明或标记待作者确认，不能编故事。

### 验收

- 每次修复同时检查欠矫正和过矫正；
- 字数缩水不超过 10%，除非删除的是已证明重复内容；
- 书籍、作者、出处和有效来源数量不得减少；
- 具体案例、边界、反例和动作接口不得被空泛总结替代；
- 自动候选必须附修改理由、来源和回退方式。

## WP6：结构整理与重复治理

### 动作

1. 建立内容职责矩阵，识别错放文件和重复事实源。
2. 按标题、段落指纹、语义近似和引用重合识别重复内容。
3. 区分完全重复、旧版本、互补版本和冲突版本。
4. 完全重复只在哈希或规范化内容相同时自动处理。
5. 旧版本进入归档，当前版由 SOT 指定。
6. 互补版本生成合并候选，不自动删除原件。
7. 冲突版本进入 `source-blocked`，等待事实源裁决。
8. 自动重建 README、来源地图和必要索引。

### 验收

- 每个目录只有一个职责；
- 每类版本事实只有一个当前权威入口；
- 正式目录不出现 `_old`、`copy`、`最终版2` 等平行事实源；
- 无法证明重复的文件不删除；
- 移动后旧路径引用为 0，文件数和哈希有迁移清单。

## WP7：流水线、报告与持续运行

### 标准运行顺序

1. 环境自检；
2. 读取 policy；
3. 锁定 baseline manifest；
4. 运行只读审计；
5. 分类问题；
6. dry-run 安全修复；
7. 应用 `L1` 修复；
8. 生成 `L2/L3` 隔离候选；
9. 重跑所有相关门禁；
10. 抽样差异检查；
11. 生成批次报告；
12. 更新任务队列，不自动发布。

### 运行模式

- `audit`：只审计，不修改；
- `safe-fix`：只执行 `L1` 白名单修复；
- `candidate`：生成 `L2/L3` 候选；
- `full-local`：完成审计、安全修复、候选生成和终验；
- `verify`：不生成新内容，只检查当前状态。

### 验收

- 一条命令可完成 `full-local`；
- 默认模式为 `audit`，任何未知配置自动降级为只读；
- 同一无变化输入重复运行不产生新差异；
- 批次报告包含输入、修改、跳过、阻断、回滚和剩余风险；
- 失败不会留下半套 schema、半迁移路径或被覆盖原文；
- 本地自动运行不触发发布、通知和第三方写操作。

## 八、统一门禁

| 门禁 | 必须满足 | 失败动作 |
|---|---|---|
| `G0 环境` | PowerShell 7、正确仓库、工具可用 | 终止 |
| `G1 范围` | 目标文件在 allowlist，保护路径未触碰 | 终止 |
| `G2 基线` | manifest、哈希和指标已锁定 | 终止 |
| `G3 结构` | 链接、路径、表格、编码、schema 合法 | 回滚本批次 |
| `G4 证据` | claim、来源、身份和边界不退化 | 隔离或回滚 |
| `G5 内容` | 无造假、无空心化、无过强承诺 | 隔离或回滚 |
| `G6 差异` | 修改最小、数量受限、抽样符合预期 | 回滚本批次 |
| `G7 终验` | 全量检查通过，报告完整 | 不晋级、不更新版本 |

## 九、核心指标

### 系统可靠性

- 保护路径误写：`0`；
- 未授权删除：`0`；
- 半完成批次：`0`；
- 幂等性失败：`0`；
- 明确断裂的 Wiki/本地路径：`0`；
- claim ID 重复：`0`；
- 合同 schema 漂移：`0`。

### 信息质量

- 正式产品主张台账覆盖率：`100%`；
- `E1/E2` 精确定位覆盖率：`100%`；
- 无来源精确数字、伪案例和虚构第一人称：`0`；
- 有边界或反证的核心主张比例：`100%`；
- 自动修复后来源数、书名引用和有效定位不下降；
- 自动修复后字符数和段落数异常缩水立即阻断；
- 每篇正式内容只有一个主要读者任务和一个下一步。

### 自治效率

- `L0/L1` 日常批次目标人工介入次数：`0`；
- `L2` 候选因规则不清而升级人工的比例需持续下降；
- 所有人工阻断都必须有具体文件、行号、冲突和可选决定；
- 人工没有响应时不阻塞其他安全任务；
- 不用“自动修改文件数”衡量价值，以问题关闭率和无回归为准。

## 十、失败与回滚策略

### 自动回滚

- 文件哈希与预期不符；
- 实际修改文件超出 dry-run；
- 字符、段落、来源或链接异常下降；
- 出现新断链、重复 claim 或 schema 漂移；
- 修改触及保护路径；
- 修复后问题总数增加；
- 同一规则连续三轮仍无法清零。

### 自动隔离

- 来源冲突；
- 第一人称真实性未知；
- 需要提升证据等级；
- 可能改变产品承诺；
- 多个版本都有独有内容；
- 删除是否安全无法证明；
- 网络超时但不能确认链接失效。

### 禁止兜底

- 不得用整篇重写掩盖局部问题；
- 不得因无法验证就删除来源；
- 不得用 AI 常识补缺失事实；
- 不得为了指标删除具体内容；
- 不得把报告中的“建议”直接当成“已完成”；
- 不得因 Git 未跟踪就判断文件无价值。

## 十二、最终完成定义

只有同时满足以下条件，目标才算完成：

1. 计划中的脚本、规则、schema、测试和报告目录真实存在；
2. 当前 24 个产品 Markdown 与 4 个 Dan Koe 信源 Markdown 全部进入 manifest；
3. `audit`、`safe-fix`、`candidate`、`full-local`、`verify` 五种模式可运行；
4. 所有确定性检查有通过样本和失败样本；
5. 当前产品全量运行后，结构、来源、claim、合同和质量门禁通过；
6. `L1` 修复连续两次运行满足幂等性；
7. `L2/L3` 候选只进入缓冲区，不污染正式事实源；
8. 保护路径、真实运行、冻结书稿和原始来源未被越权修改；
9. 没有虚构用户案例、第一人称经历、结果或证据；
10. 外部发布、删除、定价和证据升级仍保留人工批准；
11. 一次完整本地维护批次可以在无人干预下完成，并留下可审计报告；
12. `SOURCE_OF_TRUTH.md` 只在全部验收后更新自动化状态和版本。
