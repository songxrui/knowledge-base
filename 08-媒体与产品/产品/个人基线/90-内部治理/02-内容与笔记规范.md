# 内容与笔记规范

这是一份内部治理文件。用户运行产品不需要阅读它。

## 一、方法分工

| 任务 | 使用方法 | 不使用它证明什么 |
|---|---|---|
| 文件路由 | PARA | 不证明内容重要或已经学会 |
| 输入到表达 | CODE | 不证明主张正确 |
| 长期主张与连接 | Luhmann/Ahrens | 不以链接密度衡量质量 |
| 问题拆解 | McKinsey 七步 | 不冒充统一“麦肯锡笔记术” |
| 结论表达 | Minto 金字塔 | 不以结构整齐代替证据 |
| 理解检查 | 提取、生成、自我解释 | 不跳过回查和纠错 |
| 传播结构 | Dan Koe/APAG/BPAS | 不继承过度承诺和身份攻击 |

## 二、信息对象

### `Question`

- 要支持什么决策或交付；
- 范围与不处理项；
- 完成标准；
- 当前领先假设；
- 什么证据会推翻它。

### `Source`

- 作者、标题、日期；
- URL 或本地路径；
- 标题、页码、段落或行号；
- 来源类型与证据等级；
- 是否读过原文。

### `Evidence`

- 支持或反驳哪个 `claim_id`；
- 方法、样本或材料类型；
- 观察到什么；
- 不能推出什么；
- 核验日期。

### `Claim`

```markdown
# 一句话判断

- claim_id:
- status: research-supported | author-method | historical-description | product-hypothesis | blocked
- source:
- locator:

## 我的推理
不用原文句式，写清证据怎样支持该判断。

## 反证与边界
什么情况不成立，当前还有什么竞争解释。

## 行动接口
这个判断会改变哪个具体选择。

## 关系
- supports:
- contradicts:
- qualifies:
- depends-on:
- example-of:
```

### `RetrievalAttempt`

- 问题；
- 不看资料的回答；
- 置信度；
- 对照来源后的错误和遗漏；
- 修正后的回答；
- 下次检查日期或真实使用情境。

### `ProjectPacket`

临时装配当前交付所需的 Question、Claim、Evidence、反例和下一步。项目结束后归档，不复制成长期知识。

## 三、研究 SOP

1. 先写问题，不先建空目录。
2. 闭卷写当前解释，暴露最不确定处。
3. 先检索本库原始来源，再做库外检索。
4. 捕捉来源指针、关键事实和限制，不复制全文。
5. 关闭资料重新解释。
6. 回到来源逐项纠错。
7. 形成一个 Claim，并登记到 [[01-主张与来源台账]]。
8. 只建立有理由的关系。
9. 立即装配进当前文章、协议或决策。
10. 根据使用、反例或延迟回忆更新状态。

## 四、选题门禁

一个选题进入草稿前必须回答：

- 它来自哪一个真实问题、运行记录或读者反馈？
- 统领问题是什么？
- 当前最强的一句话判断是什么？
- 哪个 `claim_id` 支持它？
- 有什么反例或边界？
- 这篇主任务是增长、真实性还是权威性？
- 读者看完只需要做哪一个下一步？

任何一项答不出，选题退回素材层，不让 AI 补齐故事或证据。

## 五、长文结构

### 证据优先版 APAG

1. **Attention**：用真实问题或观察开场，不用无来源数字和虚假危机。
2. **Perspective**：写清常见解释及其遗漏，不把持不同意见者塑造成敌人。
3. **Advantage**：先给有边界的新判断，再给来源、反证和适用条件。
4. **Grounded action**：给最小行动、记录字段、停止条件和复盘日期。

这里把 Gamify 改写为 Grounded action，是本产品的编辑适配，不声称 Dan Koe 原框架如此命名。

### 金字塔检查

- 第一屏能否读到核心判断；
- 每个一级标题是否支持核心判断；
- 同组论据是否同类；
- 论据顺序是否为时间、因果、结构或优先级之一；
- 每条关键事实是否有来源；
- 结论强度是否超过证据。

## 六、短内容结构

- **问题 + 改判**：一个常见解释，指出遗漏，再给新判断。
- **错误 + 边界**：指出常见错误，并说明它在什么条件下其实成立。
- **观察 + 动作**：一条真实观察和一个可记录动作。
- **证据 + 含义**：研究发现、限制和它对日常选择的具体影响。

短内容不得把“传播表现好”写成“观点被证明”。

## 七、表达纪律

- 没有真实经历，不写第一人称故事；
- 没有用户结果，不写成功案例；
- 没有来源，不写精确数字；
- 作者观点写“作者主张”，不写成研究事实；
- 隐喻必须标记为隐喻，不能冒充机制；
- 不使用 NPC、觉醒、降维打击等身份优越叙事；
- 不使用“所有人、唯一、必然、彻底”等词，除非材料真的覆盖；
- 允许写“不知道”“待核”和“当前证据不足”。

## 八、发布门禁

- 核心判断有 `claim_id`；
- 第一人称事实由本人确认；
- 外部材料有作者、标题和定位；
- 至少有一个边界、反例或竞争解释；
- 行动建议包含适用条件和停止条件；
- 医疗、心理、投资和收入主张已排除或单独验真；
- 文章只承担一个主要受众任务；
- CTA 不承诺材料无法支持的结果；
- 发布后登记理解、传播、使用、反例和购买信号，不能只看播放量。
